# R6 — 승인된 범위 (2026-09-02)

이 문서는 제품 오너가 2026-09-02에 R6 착수를 승인하며 보낸 지시문 원문을 그대로 보존한 것이다. 새 세션은 이 문서를 R6의 유일한 확정 스펙으로 삼는다 — 요약하거나 재해석하지 말고 아래 내용을 그대로 따른다. 진행 중 발견되는 세부 구현 판단은 개발자 재량이지만, 정책/UX가 달라지는 지점은 문서 하단 "중단 조건"을 따른다.

## 선행 조건 (완료됨, 재작업 금지)

- **R4(수업권·결제 원장)·R5(과목 수강·선생님 배정) 둘 다 완료 확정.** 2026-09-02 제품 오너가 실제 Vercel Preview에서 직접 UAT를 수행해 확인 완료(보호자 구매→관리자 확인→과목 활성화→선생님 배정→변경→역할별 화면까지 전체 흐름). **같은 범위를 다시 테스트하거나 수정하지 않는다.**
- UAT 중 발견되어 이미 수정·커밋된 것: 관리자 Google 로그인/재설정 링크/Stripe 성공 리다이렉트의 origin 버그(`039068b`/`a0645ce`/`97b04f2`), 결제 웹훅 재전달 이슈(Preview 전용 Deployment Protection + URL 변경 때문 — Production 구조 문제 아님), 관리자 "구매 상세 조회" 500 에러(`7992fb3`), 선생님 변경 화면에 적용일 입력란 누락(`7992fb3`).
- **Production Stripe 웹훅 엔드포인트는 아직 등록되어 있지 않다.** 지금 등록하지 않는다 — "법인 설립·Stripe Live 계정 활성화 후 오픈 전 필수 작업"으로 체크리스트에 남겨둔다(아래 `docs/CURRENT.md`에도 기록).

## 사용자 지시문 원문 (그대로)

> R4·R5 통합 UAT는 사용자가 실제로 확인했고 큰 문제 없이 마무리됐습니다. 두 단계는 완료 상태로 확정하고, 같은 범위를 다시 테스트하거나 수정하지 마세요.
> Preview에서 발생했던 지연은 임시 URL 변경과 Deployment Protection 때문이며 Production 구조의 blocker가 아닙니다. 다만 Production Stripe 웹훅 엔드포인트 등록은 아직 안 되어 있으므로, 지금 등록하지 말고 "법인 설립·Stripe Live 계정 활성화 후 오픈 전 필수 작업"으로 체크리스트에 명시해 주세요.
> 이제 마스터 로드맵과 확정 정책에 따라 R6 전체를 한 번에 진행해 주세요.
>
> R6 필수 범위:
>
> 1. 정규수업 예약
>
> - 선생님의 반복 가능 시간, 날짜별 예외, 수업 전후 버퍼 관리
> - 120분 수업, 15분 버퍼
> - 예약 가능 범위: 최소 24시간 이후부터 최대 8주
> - 사용자·가족·선생님 시간대와 DST 정확히 반영
> - Google FreeBusy와 내부 DB 잠금을 함께 사용해 중복예약 차단
> - 보호자·학생 예약 화면과 선생님·관리자 일정 관리 화면
> - 주 1회 반복예약은 최대 8회까지 만들되 각 회차를 독립 예약·수업·수업권 hold로 관리
>
> 2. 수업권 연동
>
> - 예약 확정 시 회차별 수업권 1개 hold
> - 정상 완료 시 consume
> - 24시간 이전 취소는 release
> - 24시간 미만 학생 취소 및 확정된 노쇼는 consume
> - 선생님·회사 취소는 release하고 선생님 지급 없음
> - 선생님·회사 취소 시 기존 만료일까지 30일 미만이면 취소일 기준 최소 30일을 확보하도록 연장
> - 모든 변경은 기존 immutable entitlement ledger 원칙을 유지하고 중복 차감·이중 복구가 없어야 함
>
> 3. Google Calendar·Meet
>
> - 확정된 각 수업에 Calendar 이벤트와 고유 Meet 링크 생성
> - Supabase를 원본으로 유지하고 Google 일정은 실행용 사본으로 취급
> - Google 생성 실패 시 DB·수업권 hold가 어중간하게 남지 않도록 보상·재시도·대사 경로 마련
> - 취소·재예약·선생님 변경 시 기존 이벤트와 새 상태가 정확히 동기화
> - Meet 출결 데이터의 제공 범위, 권한, 지연시간을 실제 공식 API 기준으로 확인
> - Google Meet 출결과 ALTON 화면 접속·수업 페이지 열람 기록은 별도 데이터로 구분
>
> 4. 취소·재예약·지각·노쇼
>
> - 취소 후 기존 예약을 임의로 덮어쓰지 말고 취소 이력을 보존한 채 새 예약 생성
> - 선생님 취소 후 사용자가 직접 새 시간을 예약
> - 학생 지각은 예정 종료시간을 연장하지 않고 수업권 정상 소비
> - 선생님이 10분 이상 늦으면 당사자 합의와 다음 일정 충돌이 없는 경우에만 당일 연장하고, 그렇지 않으면 보강시간을 별도로 기록
> - 학생 노쇼는 수업 시작 15분 후 선생님 신고와 관리자 또는 시스템 확인을 거쳐 확정
>
> 5. AI 회의록·Smart Notes
>
> - 필수 개인정보 동의와 분리된 기존 선택 동의 구조 재사용
> - 보호자가 AI 회의록을 거부하거나 철회한 회차에는 Smart Notes를 사용하지 않음
> - 허용된 회차만 Smart Notes 사용
> - 녹화·오디오 저장은 기본 비활성화하고 별도 녹화 기능을 만들지 않음
> - 녹화 비활성 상태에서 스크린샷 등 예상하지 않은 미디어 산출물이 생성되지 않는지 확인
> - 회의록 결과, Meet 이벤트 및 내부 session을 안정적으로 연결하고 누락·지연·중복을 대사할 수 있게 구성
> - 공식 API에서 자동 활성화나 결과 수집이 지원되지 않는 기능은 가능한 것처럼 구현하지 말고, 지원 범위와 운영상 수동 절차를 분리해 기록
>
> 6. 알림 및 운영
>
> - 24시간 전·2시간 전 알림을 위한 outbox·스케줄 구조
> - 실제 이메일이나 메시지는 발송하지 말고 발송 대기 상태까지만 검증
> - 관리자에게 예약·Calendar·Meet·수업권·출결·AI 회의록 불일치를 확인하고 재처리할 수 있는 최소 운영 화면 제공
>
> 구조 전환 시 `sessions_v3`를 현행 `sessions`로, 기존 `sessions`를 `legacy_sessions`로 전환하고 관련 코드와 관리자 액션도 같은 단계에서 함께 전환하세요. 기존 데이터는 테스트 데이터이지만, 삭제보다 전환·보존을 우선하고 롤백 가능한 체크포인트를 남기세요. Calendly와 Zoom 제거는 새 예약→Meet→출결→수업권 처리 흐름의 E2E 통과 후에만 진행하세요.
>
> R8의 Drive 권한 자동화와 R9의 커리큘럼 인수인계는 이번에 구현하지 말고 필요한 인터페이스·재처리 상태만 유지하세요. Production 배포, Production 데이터 변경, 실제 사용자 알림, 유료 라이선스 구매, 실제 고객 일정 생성은 금지합니다.
>
> 이번 메시지로 다음 범위를 한 번에 승인합니다.
>
> - 필요한 조사와 코드 구현
> - additive migration 및 로컬·원격 dev DB 반영
> - 테스트 계정만을 사용한 Preview 배포
> - 승인된 ALTON 테스트 계정 범위에서 Calendar·Meet 샌드박스성 검증과 생성 자산 정리
> - 유닛·통합·역할별 권한·동시성·전체 E2E 테스트
> - CURRENT·로드맵·R6 실행 로그 갱신과 커밋
>
> 기존 `WORKSPACE_PROVISIONING_ALLOW_REAL_CALLS`와 `WORKSPACE_PREFLIGHT_ALLOW_REAL_READS`는 계속 `false`로 유지하세요. R6 외부 호출이 필요하면 R6 전용 최소권한·기본 false 게이트를 분리하고 테스트할 때만 일시적으로 사용한 뒤 반드시 복원하세요.
>
> 중간 선택지는 묻지 말고 기술적 세부사항과 비파괴적 버그 수정은 자체 판단으로 연속 진행하세요. 다음 경우에만 즉시 멈추고 한 번에 보고하세요.
>
> - 확정 정책 또는 사용자 경험을 바꿔야 하는 경우
> - Google 유료 라이선스·관리자 승인·새 외부 자격증명이 필요한 경우
> - Production이나 실제 사용자 데이터에 접근해야 하는 경우
> - 파괴적 마이그레이션 또는 복구 불가능한 외부 변경이 필요한 경우
> - 공식 API 제약으로 필수 인수 기준을 달성할 수 없는 경우
>
> 사람이 직접 Google 승인이나 화면 확인을 해야 한다면 개발을 먼저 끝낸 뒤 필요한 작업을 마지막에 한 번의 UAT 절차로 묶어 요청하세요. 최종 보고는 `완료 / 검증 / 미완료 / 결정 필요 / 외부 변경 및 플래그 복원` 다섯 항목으로 한 번만 제출해 주세요.
