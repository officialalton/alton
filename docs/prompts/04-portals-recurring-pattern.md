# 프롬프트 04 — 나머지 포털들 (반복 패턴)

Phase 2~5(학생/학부모/선생님/관리자 포털)는 전부 같은 패턴으로 진행한다. 세션뷰가 이미 서 있다는 전제 하에, 이 화면들은 상대적으로 표준적인 CRUD라 리스크가 낮다.

## 기본 프롬프트 템플릿

```
docs/spec/mockups/[해당 목업 파일].html에서 [화면/기능 이름] 부분을 분석해줘 (관련 view, 데이터 구조, 함수 전부).

이걸 우리 앱의 [경로]에 만들어줘. 목업의 화면 구성과 인터랙션을 그대로 재현하되:
1. 실제 Supabase 쿼리로 데이터를 가져오도록 만들어줘 (mock 데이터 쓰지 말고)
2. 목업에서 alton_material_viewer_prototype.html로 연결되던 링크는, 실제로는 우리가 이미 만든 세션뷰 라우트(/session/[id] 같은 형태)로 연결해줘 — "레이어 분리" 원칙 기억해: 세션 진입 링크와 순수 교재 라이브러리 링크는 다른 라우트다.
3. 역할별 권한을 실제 로그인 세션 기준으로 체크해줘

작업 후 관련 테스트 작성하고 통과 확인해줘.
```

## 052 (교재 편집기 WYSIWYG) 관련 별도 질문

목업은 `contenteditable` + `document.execCommand`로 만들었는데, execCommand는 deprecated API다. 실제 프로덕션에서는 더 나은 선택지를 물어보는 게 좋다:

```
목업의 교재 편집기는 contenteditable + document.execCommand로 WYSIWYG를 구현했어 (굵게/기울임/정렬/색상/제목/표/강조박스). 실제 프로덕션 코드에서는 execCommand가 deprecated라 계속 쓰기엔 리스크가 있다고 들었어. Tiptap이나 Lexical 같은 리치텍스트 에디터 라이브러리로 교체하는 게 나을지, 아니면 계속 execCommand로 가도 되는지 트레이드오프를 알려주고 추천해줘.
```
