# 프롬프트 03 — 수업 세션뷰 (가장 중요한 화면, Phase 1)

> **문서 상태: 실행 금지·초기 구축 이력.** 기존 세션뷰의 구현 경위를 확인할 때만 참고한다. 신규 작업은 v3 도메인·권한과 `../2026-08-29-master-roadmap-v3.md`의 R7~R9를 따른다.

세션뷰는 스코프가 크기 때문에 한 번에 다 시키지 말고, tickets.md의 010~017을 순서대로 나눠서 진행한다. 아래는 첫 번째(010-session-shell) 프롬프트 예시이고, 나머지는 같은 패턴으로 "이번엔 어떤 탭을 만들지"만 바꿔서 반복하면 된다.

## 프롬프트 예시 (010-session-shell)

```
docs/spec/mockups/alton_material_viewer_prototype.html 파일을 열어서 전체 구조를 분석해줘. 이 파일이 우리가 만들 "수업 세션뷰"의 완성된 스펙이야.

이번 세션에서는 셸(shell)만 만들 거야 — 탭 내용물은 다음에 만들 거고, 이번엔:

1. 상단바: 뒤로가기, 세션 제목/과목/학생/회차 표시
2. 세션 상태바: 상태(prep/live/completed)에 따라 다른 내용 — 목업의 renderSessionStatusBar() 로직 그대로
3. 좌우 역할 분기: 학생으로 로그인했는지 선생님으로 로그인했는지에 따라 편집 권한이 달라지는 구조를 미리 잡아줘 (목업의 MODE 변수 역할을 실제 로그인 세션에서 가져오는 걸로 대체)
4. 네비게이션: 교재/과제/문제생성(선생님만)/문제기록/단어장/연습장 탭 — 탭 전환만 되게 하고 내용은 "준비 중" 플레이스홀더로 둬
5. "레이어 분리" 원칙 지켜줘: 이 화면은 항상 session_id를 URL 파라미터(또는 라우트 세그먼트)로 받아서 진입해야 해. 세션 없이 교재만 보는 화면(교재 라이브러리)은 이거랑 별개의 라우트로 나중에 만들 거야 — 지금은 세션뷰만 만들어.

Vitest로 상태바가 prep/live/completed에 따라 올바른 내용을 렌더링하는지 테스트도 같이 작성해줘.
```

## 이후 탭 프롬프트 패턴 (011~017 반복 사용)

```
docs/spec/mockups/alton_material_viewer_prototype.html에서 [탭 이름] 탭 부분을 분석해줘 (nav-[탭id], view-[탭id] 관련 JS 함수 전부).

이 로직을 그대로 우리 세션뷰의 [탭 이름] 탭으로 옮겨줘. 목업의 인터랙션(예: 클릭 시 동작, 조건부 렌더링)을 빠짐없이 재현해줘. 데이터는 아직 실제 API가 없으니 Supabase 쿼리 자리에 TODO 주석을 남기고 목업과 동일한 mock 데이터로 우선 동작하게 만들어줘.

작업 후 관련 테스트 작성하고 통과 확인해줘.
```

이 패턴으로 011(교재), 012(캔버스), 013(단어장), 014(과제), 015(문제생성), 016(연습장), 017(문제기록) 순서로 반복.

## 특별히 신경써야 할 티켓

**012-session-canvas (캔버스 필기)**: 목업은 순수 Canvas 2D API를 썼다. React에서 이걸 그대로 옮길지, react-konva 같은 라이브러리를 쓸지는 Claude Code에게 먼저 트레이드오프를 물어보고 결정하는 게 좋다 — 이 부분만 별도로 질문:

```
캔버스 필기 기능을 React로 옮기려고 해. 목업은 순수 Canvas 2D API로 만들었어. 우리 상황(스크롤 콘텐츠 위에 오버레이되는 단일 캔버스, 펜/색상/지우기)에서 순수 Canvas API를 그대로 쓰는 게 나은지, react-konva 같은 라이브러리를 쓰는 게 나은지 장단점을 알려줘. 나중에 실시간 협업(여러 명이 동시에 그리기)까지 갈 걸 감안해서 추천해줘.
```

**015-session-aigen (문제 생성)**: 이 단계에서는 아직 실제 AI 호출 없이 mock으로 만들고, Phase 6(060-ai-integration)에서 실제 Claude API로 교체한다. 미리 이렇게 명시해줘:

```
문제 생성 플로우는 이번엔 AI 호출 부분을 mock(목업과 동일하게 setTimeout + 더미 데이터)으로 만들어줘. 실제 Claude API 연동은 나중 티켓에서 할 거야. 대신 UI 흐름(생성→편집가능한 초안→재생성→과제로 확정)은 목업과 완전히 동일하게 만들어줘.
```
