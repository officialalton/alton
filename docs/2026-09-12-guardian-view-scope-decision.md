# 보호자 열람 범위 확정 (2026-09-12)

제품 오너 지시로 이 날 두 번 바뀌었다. **최종은 아래 §2다.** §1은 왜 코드에
그 흔적이 남아 있는지 설명하기 위해 남긴다.

## 1. 폐기 — "보호자는 요약만" (같은 날 오전)

보호자 열람 범위를 회차 목표·일정·진도·숙제·교사가 쓴 수업 요약으로 한정하고,
필기 원본·교재 본문·문제·풀이판을 전부 제외했다.
마이그레이션 `20261299000000`이 이 정책을 구현했다. **철회됐다.**

## 2. 확정 — 연결된 자녀의 학생 화면을 읽기 전용으로

마이그레이션 `20261300000000`이 정본이다.

### 볼 수 있다
교재, 문제, 교사 공용 필기, 학생 문제 풀이, 교사 피드백, 복습 기록.

### 볼 수 없다
**학생 개인 교재 메모** — 학생 본인만 본다. 이 한 가지는 두 정책 모두에서 같다.

### 할 수 없다
답안 제출, 필기 작성·수정·삭제, 수업 시작, 준비 구성 변경.

### 범위
연결된 자녀의 데이터만. 자녀가 여럿이어도 서로 섞이지 않는다.

## 3. 어떻게 강제하는가

화면에서 버튼을 숨기는 것에 의존하지 않는다.

| 층 | 수단 |
| --- | --- |
| 조회 | `session_annotation_events` 범위별 SELECT 정책, `canvas_annotations`, `session_problem_work`, `session_content_manifest` 정책이 `is_session_guardian_v3()`로 판단한다. 연결이 없으면 빈 결과다. |
| 쓰기 | 범위별 INSERT 정책에서 보호자를 전부 제외한다. 수정·삭제는 append-only 트리거가 모두에게 막는다. |
| 실시간 | 공용 필기 브로드캐스트는 RLS가 적용되지 않으므로, 보호자 화면은 읽기 전용 뷰어로 렌더링되어 송신 경로 자체를 갖지 않는다. 개인 필기는 애초에 채널을 열지 않는다. |
| 정답·해설 | 자녀에게 열리는 시점과 동일하게 계산한다 — 자녀가 제출하기 전에는 보호자에게도 내려가지 않는다(payload에 실리지 않는다). |

## 4. 이번 변경에서 함께 막은 구멍

`teacher_shared` 범위의 INSERT 조건이 `is_session_related_v3()`였는데, 이 판정에는
보호자가 포함된다. 즉 **보호자가 공용 필기를 쓸 수 있었다.** 읽기 권한을 넓히는
이번 변경에서 반드시 함께 닫아야 했던 부분이라 같은 마이그레이션에서 처리했다.

## 5. 유지되는 것

학부모 포털의 기존 요약 화면(`app/parent`)은 그대로다. 세션뷰와 독립적으로
동작하므로 이번 변경의 영향을 받지 않는다.
