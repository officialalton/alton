# 기획자 전달용 현황 정리 (2026-09-07, 갱신)

브랜치: `preview/m4-integration-verification` (Production 미배포, main 미병합)

이 라운드는 상담/복수자녀 온보딩 기능 구현 이후, 제품 오너가 실제 Preview
배포본을 직접 써보며 발견한 버그·UX 이슈를 즉시 재현·수정하는 방식으로
계속 진행됐다. 아래는 그 전체를 마무리 시점에서 정리한 것이다.

## 1. 완료 — 인수 기준 중 끝난 항목

**비운영 데이터 정리**
- non-prod DB에서 UAT 테스트 계정 비식별화(로그인 차단), 보존 대상 2계정(`official@`, `teacher1@`)은 무결성 확인 완료.

**복수 자녀 온보딩 (핵심 기능)**
- 관리자가 온보딩 안내 발송 시 학생 1~N명을 한 번에 입력, 가족당 링크 1개 발송.
- 보호자 확인 시 학생별 Auth 계정 자동 생성, 학생별 칸반 카드 자동 생성(단일 칸반 유지, 별도 보드 없음).
- 학생별 초대 상태·계정생성 상태 완전 분리 저장(형제자매 간 결과 덮어쓰기 없음).
- 부분 실패 격리 + 학생별 독립 재시도, 동시성 중복 방지.
- **온보딩 링크 "전체 취소" 액션 신설** + **재발급 시 취소된 학생을 영구
  제외하던 버그 수정**(이미 계정 생성된 학생만 제외, 취소된 학생도 값을
  고쳐 다시 포함 가능).
- 실사용 중 발견된 버그(좀비 auth identity로 재발급 영구 실패, guardianEmail 공백 미제거, React 예외 마스킹으로 실제 원인 안 보임 등) 다수 근본 수정.

**체험 생략 → 바로 정규 등록 플로우**
- 상담 결과 "정규 진행 권장" 선택 시 체험을 건너뛰고 계약 draft 자동 생성,
  학생 계정 생성 폼까지 이어지는 흐름 완결.

**지인/추천 — 상담 없이 바로 계정 생성**
- 상담 칸반과 무관한 별도 관리자 화면(`DirectAccountCreationForm`) 신설.
- 잘못된 이메일로 발송한 뒤 재발송할 방법이 없던 문제 해결: 링크 재발급(오타
  수정) + 학생 개별 취소 + 링크 전체 취소.
- 발송 내역을 조회할 화면 자체가 없던 설계 공백 해결(`DirectAccountLinksList`).

**상담 캘린더 UI**
- 랜딩 페이지 상담 신청의 시간 드롭다운을 월간 캘린더+시간버튼 공용 컴포넌트로 교체.
- 관리자 "공용 상담일정 등록" 캘린더를 축소하고, 선생님 가용시간과 동일하게
  반복요일 중 특정 날짜·특정 시간대만 부분 휴무 지정 가능하도록 개선.
- 사용하지 않는 과거(레거시) 디버그 UI를 삭제 대신 `<details>`로 접어 정리.

**상담 동의 확인 메일 — 자동발송으로 정책 전환**
- 처음엔 관리자가 카드에서 누르는 수동 재발송 버튼으로 구현했으나, 제품
  오너 지시로 **상담이 최초로 확정될 때 Calendar 초대와 별개 채널로 무조건
  발송**하도록 정정(Calendar 안의 기존 링크는 그대로 유지). 관리자 조작
  없이 항상 나간다.

**보호자 포털**
- "자녀 추가 상담" 셀프서비스 신청 화면 신설(랜딩과 동일 캘린더 컴포넌트 재사용).
- 정규 진행 희망 배너 조건 수정(리뷰 확정 무관, 홈/수강과목 탭 기준 통일).
- 상담 중도 종료된 자녀는 탭에서 자동 숨김(정규 전환된 자녀는 항상 노출).
- 레거시 "학부모 초대"(구 수업권 시스템 잔재) 제거, 지인 추천 기능만 유지.
- 중복 "수업권" 탭 이름 충돌 해결(레거시 `students.credit_balance` 탭 vs
  신규 entitlement 탭이 같은 이름이라 구매 완료해도 "0장"으로 보였던 문제).

**R11(문의·면담) 실구현**
- household 메신저(문의) + 면담 일정 요청 + 면담 전용 가용시간(상담과 완전 분리) + 관리자 "문의·면담 운영" 화면.

**학생/선생님 포털 정리**
- 선생님·학생 양쪽에서 배정된 상대가 서로 안 보이던 실제 RLS/조회 버그 수정.
- 수업 종료 처리 시 React 예외 마스킹 버그 수정, "수업 시작" 시 Google Meet 자동 입장 추가.
- 선생님이 수업 종료 처리하면 학생 쪽도 즉시 "지난 수업"으로 동기화(기존엔 시간 경과만 봐서 불일치 발생).
- 선생님/학생 탭 구조 정리(중복 탭 통합: 수업/수업일정, 학생/배정, 레슨/예약).
- 선생님 가용시간에 월간 캘린더 뷰 + 부분 휴무 지정 기능 추가.

**성능 개선 1라운드**
- 학생/보호자/선생님 포털 홈 페이지의 순차 DB 쿼리(워터폴)를 `Promise.all` 병렬화, 반복문 내 N+1 패턴 제거. 쿼리 로직 자체는 불변, 순서만 변경.

**정규 계약 발송**
- 발송 실패 시 관리자에게 피드백이 안 가던 버그 수정.
- 승인자 직함 기본값을 "CEO, Do Kyung Kim"으로 통일.
- 보호자의 "정규 진행 희망" 확인 시 계약이 자동 발송되도록 정책 전환 완료
  (더 이상 관리자가 별도로 "발송" 버튼을 눌러야 하지 않음).
- 관리자가 사용자 프로필(이름/이메일 등)을 수기로 수정할 수 있는 기능 추가
  (수정 이력 감사 컬럼 포함).

## 3. 다음 업무 계획 — UAT 기준선 고정 후 단계별 진행

### 3-0. UAT 기준선 고정 (다음 개발 착수 전 마감 라운드)

이번 UAT에서 여러 흐름이 빠르게 확장됐으므로, R8/R10을 시작하기 전에 현재
Preview의 동작을 하나의 기준선으로 고정한다. 이 단계에서는 새 기능·새 정책·새
외부 호출을 추가하지 않는다.

- 복수 자녀 온보딩, 상담 캘린더/보호자 셀프서비스, 직접 계정 생성, 체험 생략
  정규 등록, 자동 계약 발송, 상담 동의 메일, R11 문의·면담, 포털/RLS 수정,
  성능 1차 개선을 각각 사용자 흐름·상태 원본·권한/외부 호출 경계·회귀 테스트
  위치로 정리한다.
- 같은 업무를 수행하는 화면·서버 액션·DB 함수가 남아 있는지 확인하고, 실제
  사용 경로를 하나의 원본으로 고정한다. 안전하게 삭제할 수 없는 이전 경로는
  숨은 대체 경로가 되지 않도록 차단하거나 후속 정리 대상으로 기록한다.
- 자동 계약 발송과 상담 동의 메일은 발송 조건, 재시도/중복 클릭/웹훅 중복에
  대한 멱등성, 실패 시 관리자 표시, Preview와 Production의 외부 발송 차단
  조건을 테스트와 문서로 고정한다.
- 성능 1차 개선은 포털 홈과 상담 슬롯 화면의 쿼리 수, 순차 대기 구간, 서버
  응답 시간, 클라이언트 추가 요청을 같은 조건에서 전후 비교해 기록한다.
- 정확한 전체 테스트 결과와 간헐 실패의 재현 조건·단독 실행 결과, non-prod
  migration 일치, Preview alias 상태를 문서에 남긴다.

### 3-1. R8와 R10 병렬 진행

기준선이 고정된 뒤 R8과 R10을 병렬 진행한다. R8은 Smart Notes 원본의 회사
Shared Drive 이동·권한·보존·삭제, 이벤트 유실/재처리, Drive 실패 큐와 선생님
정지 전 운영 게이트를 마감한다. R10은 환불·분쟁·정산·재처리·감사 이력을
마감하며, 법률 검토가 필요한 환불 산식과 전자승인은 정식 오픈 blocker로
분리해 유지한다. 법인 설립 전에는 수업별 정산 원장, payout batch, 명세, 이의,
검토·승인과 역분개까지만 구현하고 실제 송금·`paid` 전이·지급 API는
fail-closed로 막는다. 법인명/EIN, 사업 계좌, 계약 주체, 선생님 분류와 세금서류,
지급수단·통화/수수료 정책, 법률·회계 승인이 확정된 뒤 별도 승인으로 지급을
활성화한다.

### 3-1a. R10 지급 인프라 확정 정책

- 고객 수납은 Stripe, 회사 운영·정산 예비금·미국 강사 USD 지급은 Mercury, 한국
  강사 KRW 지급은 `Mercury Teacher Payout Reserve → Wise Business → 강사 계좌`를
  사용한다. 추가 전통 은행 계좌는 법인 설립 후 별도 검토한다.
- ALTON은 정산 근거·승인·명세·감사 상태의 원본이다. 관리자의 승인 후 자동 지급이
  켜진 경우에만 서버가 국가별 제공자에 지급 요청을 만들며, 제공자 최종 성공 전에는
  `paid`로 전이하지 않는다.
- R10은 지급 요청 멱등성, 제공자 거래 ID, 웹훅/재조회 대사, 강사별 부분 실패 재시도,
  운영비·정산 예비금 분리를 인수 기준으로 둔다.
- 고객의 청구지 주와 실시간 수업·디지털 콘텐츠·실물 교재·구독의 상품 유형을 결제
  원장에 보존한다. 주별 매출이 sales-tax economic nexus 기준에 접근할 때 세무 검토와
  징수 등록을 시작한다.

### 3-2. R9 — 신규 운영 흐름과 실제 수업 경험 연결

R9는 단순한 마일스톤 보드 작업이 아니라, 새 상담·온보딩·배정·예약 흐름과
기존 커리큘럼·교재·수업 세션뷰를 연결하는 통합 마일스톤으로 진행한다.

1. **수업 시작 → 세션뷰**: 학생·선생님·관리자가 자신의 예약에서 동일한
   학생·과목·회차 세션뷰로 들어간다. 체험/정규를 모두 지원하고, 취소·노쇼·종료
   수업은 역할과 상태에 맞는 읽기 전용 이력으로 연결한다.
2. **커리큘럼·교재 배정**: 과목 수강·선생님 배정 시 적용 커리큘럼과 교재
   버전을 회차에 스냅샷으로 고정한다. 이후 템플릿 변경이 진행 중 수업을
   바꾸지 않게 하며, 선생님은 수업 준비에 필요한 자료·진도·과제를 확인한다.
3. **회차 운영**: 수업 준비 → 세션뷰 → 종료 → 리뷰/과제/진도/다음 회차 준비가
   하나의 회차 기록으로 이어지게 한다.
4. **레거시 연결 정리**: `legacy_sessions` 기반 화면과 신규 예약 기반 `sessions`
   의 연결 지점을 전수 대조한다. 신규 예약이 옛 화면으로 잘못 연결되거나 다른
   학생 자료에 접근하는 경로가 없음을 역할별 E2E로 검증한 뒤에만 이관한다.

### 3-3. R11 잔여 운영 도구 마감

이번 UAT에서 구현한 household 문의·면담 요청·면담 운영 화면을 다시 만들지
않는다. 남은 알림 템플릿/전달 상태/재시도/중복 방지, 수업권 알림, 대화 감사와
보관, QC 큐, 운영 대시보드 및 R9 요청 버튼 연결을 보완한다. 상담과 면담의
데이터·상태·운영 화면 분리는 유지한다.

### 3-4. R12, 성능 2차, R13 오픈 준비

- R12에서 권한·감사·복구·보존·테스트 데이터 격리와 계정 운영 절차를 마감한다.
- 성능 2차에서는 데이터 신선도별 캐싱과 무효화를 적용한다. 예약 가능 시간,
  수업권, 진행 상태는 사용자·자녀·권한·시간대별 분리와 예약 직전 DB 제약을
  전제로 한다.
- R13에서 전체 역할별 E2E, Preview UAT, Production 전환 체크리스트, 법률
  blocker, 외부 발송/결제/계약/Workspace 호출의 승인 단위를 마감한다.

### 별도 승인 범위

실제 고객 이메일·DocuSign·Google·Stripe 호출, Production 배포와 main 병합,
운영 데이터의 복구 불가능한 변경, 계약·법률 정책의 실질 변경은 위 개발
마일스톤과 별도로 승인받는다.

## 5. 참고 — UAT 진행상 알게 된 운영 메모(개발 불필요 판단)

제품 오너가 반복 UAT 중 같은 이메일로 테스트 계정을 여러 번 만들고 지우는
과정에서 "계정이 겹쳐서 재사용이 번거롭다"는 마찰을 겪음. 원인은 계정
병합/삭제 후 Auth 쪽에 좀비 데이터가 남는 케이스(이번 라운드에서 실제
발견·수정한 `cleanup_orphaned_auth_identities()`류)와, 관리자가 테스트
계정을 완전히 지우고 이메일을 바로 재사용할 수 있는 전용 UI가 아직 없다는
점. **제품 오너 판단으로 이번 라운드에서 별도 개발은 하지 않음** — 오픈
전 운영 편의성 라운드에서 필요하면 재검토.
