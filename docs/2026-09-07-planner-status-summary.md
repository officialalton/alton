# 기획자 전달용 현황 정리 (2026-09-07)

브랜치: `preview/m4-integration-verification` (Production 미배포, main 미병합)

## 1. 완료 — 인수 기준 중 끝난 항목

**비운영 데이터 정리**
- non-prod DB에서 UAT 테스트 계정 비식별화(로그인 차단), 보존 대상 2계정(`official@`, `teacher1@`)은 무결성 확인 완료.

**복수 자녀 온보딩 (핵심 기능)**
- 관리자가 온보딩 안내 발송 시 학생 1~N명을 한 번에 입력, 가족당 링크 1개 발송.
- 보호자 확인 시 학생별 Auth 계정 자동 생성, 학생별 칸반 카드 자동 생성(단일 칸반 유지, 별도 보드 없음).
- 학생별 초대 상태·계정생성 상태 완전 분리 저장(형제자매 간 결과 덮어쓰기 없음).
- 부분 실패 격리 + 학생별 독립 재시도, 동시성 중복 방지.
- 실사용 중 발견된 버그(좀비 auth identity로 재발급 영구 실패, guardianEmail 공백 미제거, React 예외 마스킹으로 실제 원인 안 보임 등) 다수 근본 수정.

**상담 캘린더 UI**
- 랜딩 페이지 상담 신청의 시간 드롭다운을 월간 캘린더+시간버튼 공용 컴포넌트로 교체.

**보호자 포털**
- "자녀 추가 상담" 셀프서비스 신청 화면 신설(랜딩과 동일 캘린더 컴포넌트 재사용).
- 정규 진행 희망 배너 조건 수정(리뷰 확정 무관, 홈/수강과목 탭 기준 통일).
- 상담 중도 종료된 자녀는 탭에서 자동 숨김(정규 전환된 자녀는 항상 노출).

**R11(문의·면담) 실구현**
- household 메신저(문의) + 면담 일정 요청 + 면담 전용 가용시간(상담과 완전 분리) + 관리자 "문의·면담 운영" 화면.

**학생/선생님 포털 정리**
- 선생님·학생 양쪽에서 배정된 상대가 서로 안 보이던 실제 RLS/조회 버그 수정(legacy 스키마만 보던 조회 로직을 v3 스키마 인식하도록 수정).
- 수업 종료 처리 시 React 예외 마스킹 버그 수정, "수업 시작" 시 Google Meet 자동 입장 추가.
- 선생님/학생 탭 구조 정리(중복 탭 통합: 수업/수업일정, 학생/배정, 레슨/예약).
- 선생님 가용시간에 월간 캘린더 뷰 + 반복요일 중 특정 날짜·특정 시간대만 부분 휴무 지정 기능 추가.
- 선생님이 수업 종료 처리하면 학생 쪽도 즉시 "지난 수업"으로 동기화(기존엔 시간 경과만 봐서 불일치 발생).

**성능 개선 1라운드**
- 학생/보호자/선생님 포털 홈 페이지의 순차 DB 쿼리(워터폴)를 `Promise.all` 병렬화, 반복문 내 N+1 패턴 제거. 쿼리 로직 자체는 불변, 순서만 변경.

**정규 계약 발송**
- 발송 실패 시 관리자에게 피드백이 안 가던 버그 수정(Preview 환경 DocuSign 게이트를 실제 버그와 구분해 안내).
- 승인자 직함 기본값을 "CEO, Do Kyung Kim"으로 통일.
- (진행 중) 보호자의 "정규 진행 희망" 확인 시 계약을 자동 발송하도록 정책 전환 — 완료되는 대로 별도 보고.

## 2. 검증

- 매 라운드마다 `supabase db reset --local`, `tsc --noEmit`, 전체 Vitest, `next build` 통과 확인 후에만 커밋.
- 현재 전체 Vitest 190개 파일·1270건대 통과 유지 중(오늘 날짜 기준 시드 데이터가 미래 날짜를 못 커버하는 기존 이슈 5건은 변경 전 커밋에서도 동일 재현 확인, 무관 처리).
- 실제 non-prod DB에 대해 psql 직접 조회로 여러 버그를 실측 재현 후 수정 확인(추측 기반 수정 금지 원칙 유지).
- 매 라운드 종료 시 non-prod migration 반영 + Preview 재배포 + alias 재연결까지 확인.

## 3. 미완료 — 남은 항목과 다음 순서

1. **체험 생략 → 바로 정규 등록 플로우 완성** (착수 전): 관리자가 상담 결과로 "정규 진행 권장"을 선택해도 이후 학생 계정 생성·계약 생성·발송이 전부 막다른 상태임을 확인함. 계약 draft 자동 생성 + 정규 진행 희망 게이트 우회 + 학생 계정 생성 폼 노출 조건 확장 필요.
2. **지인/추천 — 상담 없이 바로 계정 생성** (착수 전): 상담 칸반과 무관한 별도 관리자 화면 신설 필요. 상담 레코드 없이 보호자+학생 계정 생성.
3. R9(과목 마일스톤 보드, 학생 전용 프로필 페이지, 세션뷰-커리큘럼 연동)는 이번 라운드 범위 밖으로 명시적으로 보류 — 별도 승인 필요.
4. 캐싱 도입(성능 개선 2단계)은 오픈 전 별도 라운드로 이관 확정.
