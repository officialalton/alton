# 2026-09-14 — 과제 v3 한 갈래 통일 (1장)

제품 오너 결정(2026-09-14): 과제는 v3 한 갈래. 교사가 수업 준비의 키워드·문제 풀에서 **직접 골라** 발급 →
학생은 수업 화면과 **같은 유형별 풀이 흐름**(객관식 클릭 / 서술형 연습장 / 풀이형 풀이판·제출) → 교사가
**같은 채점 UI**로 채점 → 채점 뒤 정답·해설 공개. 레거시 `homework_items` 는 조회만. 기한·알림·AI 생성은 후속.

## 1. 사용자 흐름
- 교사: 수업 화면 `과제` 탭 → 이 회차 키워드 풀의 문제 목록(수업에서 다룬 문제는 표시·기본 제외) → 체크 → `과제로 발급`.
  발급 항목은 학생이 시작하기 전까지 `회수` 가능. 같은 탭 아래에서 학생 답을 보고 채점(수업 문제와 동일한 패널).
- 학생: 포털 `과제` 탭에 **회차별 과제 묶음**(과목·수업일·N문제·푼 수·채점 수) → 열면 그 수업 화면의 `과제` 탭.
  풀이는 수업 문제와 완전히 같다. 정답·해설은 교사 채점 뒤.
- 보호자: 읽기 전용(수업 화면 규칙 그대로).
- 실패: 풀 밖 문제·미확정 문제는 서버가 발급 거절(사유). 학생이 이미 시작한 항목은 회수 거절.

## 2. 데이터와 권한
- 발급 원본: `session_homework_items`(session, problem, student, position) + **`problem_version_id`(발급 시 공개 버전 고정)** 신설.
- 답·채점 원본: **`session_problem_work`** — 수업 문제와 같은 행(수업·학생·문제). 자동 채점·`grade`·정답 공개 규칙 재사용.
  `session_homework_attempts` 는 더 쓰지 않는다(빈 표, 삭제하지 않음).
- RPC(정의자): `issue_homework_items(session, problem_ids[])` — 담당 교사·관리자, 확정 문제, 이 회차 키워드 범위 안, 이미 발급은 건너뜀.
  `withdraw_homework_item(item)` — 학생 풀이판이 없을 때만. `session_problem_formats` 가 과제 문제도 준다. `start_problem_work` 가
  과제 항목의 버전을 우선 쓴다.
- 레거시 `homework_items`: 화면에서 추가·답안 입력 UI 제거, 목록만.

## 3. UAT 데이터: Preview 제품 오너 교사·학생 계정. 자동 테스트는 로컬 DB.

## 4. UI 기준
- 수업 화면 `과제` 탭 = [교사: 발급 구역] + 과제 문제 패널(`ProblemsPanel source="homework"`: '과제 N', 목차 '과제 목차').
- 학생 포털 `과제` 탭 = 회차별 묶음 카드 → 링크. 빈 상태: "아직 발급된 과제가 없습니다."

## 5. 검증
- 통합: 발급(범위·확정·중복·버전 고정), 회수(시작 전만), 학생 유형 조회 union, 학생이 과제 문제 풀이판을 열고 답하면 수업 문제와 같은 채점 흐름.
- 컴포넌트: 발급 구역 체크·발급·회수, 과제 패널 문구, 학생 묶음 카드.
