# P4-2 착수 1장 정리 — 교사 정산 흐름 (2026-09-12)

근거: `docs/2026-09-10-p-execution-roadmap.md` P4-2 절, R10 구현
(`20260830070000_r1_payout.sql`, `20261218000000_r10_payout_batch_lifecycle.sql`,
`20261222000000_r10_settlement_pipeline_schema.sql`, `app/admin/payout-batches-*`).
**범위 밖(고정)**: 실제 송금, `paid` 전이, Mercury/Wise·Stripe Live, Drive 권한·
환경변수 변경. P4-3 관리자 문서 탭 구현도 이번 범위 밖(연계 지점만 만든다).

## 사전 조사 결론 (재사용 대상)

- **정산 원장은 이미 있다**: 세션 최종 판정이 `upsert_session_payout_item()`
  (`20261030000000_m5a_...sql:50`)으로 `payout_items` 1행을 만들고 갱신한다
  (`amount_minor = 시급 스냅샷 × payable_minutes / 60`). 배치는
  `generate_payout_batches(period_start, period_end)`가 **세션 예약일
  (`reservations.starts_at::date`) 기준 월**로 묶는다.
- **교사 읽기 권한도 이미 있다**: `payout_items`/`payout_batches`/
  `payout_batch_audit_log` RLS 조회 정책이 `teacher_id = auth.uid()`를 이미
  허용한다 — **교사 정산 화면에 새 RLS·새 RPC가 필요 없다.**
- **없는 것**: 교사 수취 계좌 테이블, 교사 제출 서류 테이블, Storage 버킷
  (현재 레포에 `storage.buckets` 0개, `storage.from(` 사용처 0곳), 교사 포털
  정산 진입점.
- `payouts-data.ts`(레거시 `payouts` 테이블)는 쓰지 않는다 — v3
  `payout_batches`/`payout_items`만 원본으로 쓴다.

## 1. 사용자 흐름

- **교사(정상)**: 교사 포털 `정산` 탭 → ① 다음 지급 예정액(통화별) ② 월별 정산
  내역(수업 월 · 지급 예정 월 · 상태 · 금액) ③ 월 펼치면 수업별 산출 근거
  (날짜·학생·과목·지급 대상 분·시급 스냅샷·금액) ④ 수취 계좌 등록·수정
  ⑤ 제출 서류 업로드·목록.
- **계좌(실패/재시도)**: 필수값 누락·형식 오류는 인라인 오류로 막고 저장하지
  않는다. 저장 성공 시 마스킹된 값으로 다시 표시한다. 재입력하면 덮어쓰고
  변경 이력이 1행 쌓인다.
- **서류(실패/취소)**: 허용 확장자·크기를 넘으면 업로드 전에 막는다. 업로드
  실패는 메타 행을 남기지 않는다(파일·메타 모두 없음). 취소는 무변경.
  **미제출·검토 상태는 어떤 업무도 차단하지 않는다** — 정산·매칭·수업 어느
  경로에서도 서류 상태를 읽지 않는다.
- **관리자**: `정산` 탭에 `수취 계좌` 서브탭 → 교사별 계좌 목록(마스킹) +
  변경 이력. 값 수정은 교사 본인만 한다(관리자는 조회 전용).

## 2. 데이터와 권한

- **신규(additive migration 1건)**
  - `teacher_payout_accounts` — 교사당 1행(`unique(teacher_id)`):
    예금주, 은행명, 계좌번호, 통화, 국가, (선택) SWIFT/라우팅, 갱신 시각·갱신자.
  - `teacher_payout_account_events` — INSERT-only 변경 이력:
    `action(created|updated)`, 바뀐 필드 이름 목록, 계좌번호 끝 4자리 전/후.
    **이력에는 전체 계좌번호를 복제하지 않는다.**
  - `teacher_documents` — 제출 서류 메타(교사, 종류, 파일명, storage 경로,
    크기, MIME, 업로드 시각). 파일 본문은 비공개 Storage 버킷
    `teacher-documents`에 `<teacher_id>/<uuid>-<파일명>`으로 둔다.
- **권한**: 세 대상 모두 RLS — 교사는 **본인 행만** 읽기·쓰기,
  관리자/`정산권한`은 읽기. Storage 버킷도 같은 규칙(경로 첫 세그먼트가
  본인 `teacher_id`일 때만). 관리자 계약·동의서 권한은 확대하지 않는다.
- **마스킹**: 서버가 계좌번호 전체를 클라이언트로 절대 내려보내지 않는다 —
  교사 본인 화면에도 `****1234` 형태만 내려가고, 수정은 전체 재입력이다.
  관리자 목록도 동일 원본·동일 마스킹을 쓴다.
- **정산 수치 원본 경로 하나**: `payout_items`(+ `payout_batches`)만 읽는다.
  교사 화면은 사용자 스코프 클라이언트로 자기 행만 읽고(기존 RLS),
  금액을 앱에서 다시 계산하지 않는다 — `amount_minor`를 그대로 쓴다.
- **지급 상태 구분**:
  `예정`(= `payout_items.status='pending'`, 아직 배치 없음 — 판정·조정에 따라 변동)
  / `확정`(배치에 담겼고 배치가 `paid`/`failed`가 아님)
  / `지급 완료`(배치 `paid`). `paid` 전이는 이번 범위 밖이며 화면은 읽기만 한다.

## 4. UI 기준

- **교사 `정산` 탭**(홈/담당 학생/수업/가능시간/커리큘럼/교재 다음, 아이콘 💸)
  - 상단 요약 카드: `다음 지급 예정액`(통화별 합계), 지급 예정 월, **마지막
    갱신 시각**, "수업 판정·조정에 따라 변동될 수 있습니다" 문구. 확정·지급
    완료 금액은 별도 칸으로 분리 표시.
  - 월별 표: 수업 월 / 지급 예정 월 / 통화 / 금액 / 상태(예정·확정·지급 완료) /
    수업 수. 행을 펼치면 수업별 산출 근거.
  - 수취 계좌 카드: 미등록이면 "등록되지 않았습니다" + `등록`, 등록 후에는
    마스킹 값 + `수정`. 저장 중 비활성, 실패 시 인라인 오류.
  - 제출 서류 카드: 목록(파일명·종류·업로드 시각·다운로드) + 업로드.
    **"필수/미제출" 경고 배지를 쓰지 않는다** — 게이트로 오해될 표현 금지.
  - 빈 상태: "아직 정산 내역이 없습니다. 수업이 완료되면 이곳에 표시됩니다."
- **관리자 `정산` > `수취 계좌`**: 교사명 / 예금주 / 은행 / 마스킹 계좌번호 /
  통화 / 최종 수정 시각 / 변경 이력 펼치기. 빈 상태 문구 제공.
- 정보 밀도·문구 정리는 마일스톤 종료 폴리싱 라운드에서 처리한다.

## 5. 검증과 성능

- **통합/유닛**: (a) 교사는 본인 payout 행만 읽고 타 교사 행은 RLS로 막힌다,
  (b) 예정/확정/지급 완료 3분류가 배치 상태에 따라 정확히 갈린다,
  (c) 계좌 저장이 변경 이력 1행을 남기고 전체 계좌번호를 응답에 넣지 않는다,
  (d) 교사는 타 교사 계좌·서류를 읽지 못한다(RLS), (e) 서류 상태가 정산 수치
  계산에 전혀 관여하지 않는다(게이트 아님), (f) 관리자 목록이 교사와 같은
  원본을 읽고 동일하게 마스킹한다.
- **Preview UAT**: 위 흐름 1회.
- **성능**: 교사 정산 탭은 왕복 4회 고정(payout_items+batches 조인 1, 세션 근거 1,
  계좌 1, 서류 1) — 수업 수에 비례한 N+1을 만들지 않는다.

## 미확정 — 제품 오너 확인 필요(이번 구현은 아래 가정으로 진행)

1. **예정액 산정 대상**: 최종 판정이 끝나 `payout_items`가 생긴 수업만 포함한다
   (예약만 되고 아직 진행되지 않은 수업은 제외). 로드맵이 미정으로 남긴 항목이다.
2. **지급 주기·마감일·지급일**: "수업 월 기준 익월 지급"만 표시하고 구체
   마감일·지급일은 표시하지 않는다(확정된 값이 없어 임의 날짜를 만들지 않음).
3. **공제·보류**: 세금·수수료·보류 공제를 반영하지 않은 **총액**을 보여준다.
   화면에 그렇게 명시한다.
4. **제출 서류 종류 목록**: 확정된 목록이 없어 자유 입력(종류 선택 없이 파일명
   기준)으로 두고, 확정되면 종류 enum을 추가한다.
