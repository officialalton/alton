# 수업용 PDF·영상 자료 규격 (v1, 2026-09-14)

Drive 기반 파일 자료(`curriculum_docs.kind = pdf | video`)를 만들 때의 기준. 뷰어·페이지 필기 구현이
전제하는 것과 운영에서 정한 것을 나눈다. 제품 오너 확정(2026-09-14, "그래 그러자").

## 1. 구현이 전제하는 것 (지키지 않으면 화면이 어긋난다)

- **한 PDF 안에서 페이지 크기·방향이 일정**해야 한다. 필기는 그릴 때의 캔버스 너비 대비 비율로 저장돼
  화면 크기가 달라도 자리를 지키지만, 페이지마다 크기가 다르면 확대 비율이 페이지마다 튄다.
- 뷰어는 **가로 맞춤(fit-width)** 이 기본이다. 가로형이면 한 페이지가 화면에 들어오고, 세로형은 스크롤이 생긴다.
- **글꼴은 PDF 에 임베드**돼야 한다. 없는 글꼴은 pdf.js 가 대체해 한글이 깨질 수 있다.
- 폼 필드·링크·PDF 주석·JavaScript·암호화는 표시하지 않는다/지원하지 않는다. 정적 페이지만.
- PDF 안 텍스트는 단어장 클릭·문제 생성 같은 HTML 교재 기능과 **연결되지 않는다**.
- 공개하면 그 시점 파일이 고정 사본으로 보존된다. 원본을 고쳐도 기존 공개 버전·과거 수업은 그대로고,
  고친 파일은 **재공개 = 새 버전**이다.

## 2. 정한 규격

| 항목 | 기준 | 이유 |
| --- | --- | --- |
| 페이지 비율 | **16:9 가로** (Google Slides 기본 25.4 × 14.29 cm) | 노트북·아이패드 가로에서 한 장 = 한 페이지, 필기 중 스크롤 없음 |
| 자료 단위·길이 | 자료 1건 = 개념 하나. **페이지 수 제한 없음**(2026-09-14 확정 — 운영해 보고 정한다) | 회차 구성에서 순서·제외 단위가 자료이므로 짧게 나누면 재사용이 쉽다는 것은 권장일 뿐, 제한하지 않는다 |
| 필기 여백 | 우측 또는 하단 **20~25 %** 비움 | 교사·학생 필기 공간, 본문 위 덧쓰기 최소화 |
| 글자 크기 | 슬라이드 기준 본문 **18 pt 이상** | 아이패드 세로에서 축소돼도 읽힌다 |
| 글꼴 | 임베드, 한글 1종 · 영문 1종 고정 | 렌더 일관성 |
| 색 | 흰 배경, 본문색은 필기 색(검정·빨강·파랑)과 겹치지 않게 | 필기 가독성 |
| 파일명 | `과목_키워드_제목_v1.pdf` | Drive 에서 찾기 쉽고, ALTON 제목 기본값이 확장자 뗀 파일명 |
| 용량 | **20 MB 이하**, 이미지 150 dpi | 모바일 로딩 (검증용 로컬 표본 경로는 100 MB 상한) |
| 영상 | **mp4 (H.264 / AAC), 1080p 이하**, 한 자료 = 한 영상 | 브라우저 재생 호환. 영상 위 필기·동시 재생 제어는 v1 제외 |
| 정답·해설 | **학생용 PDF 파일 안에 정답지를 넣지 않는다** | PDF 는 파일 그대로 보이고 앱이 내용을 가릴 수 없다. 문제·정답·해설은 기존대로 **문제은행**에 두며, 학생·보호자에게는 서버가 정답·해설을 빼고 내려준다(기존 기능 유지) |

## 3. 등록 시 점검 (후속 — 아직 구현 안 함)

공개 단계에서 다음을 **경고**로 보여준다(막지 않음, 관리자가 판단): 페이지 크기 불일치 · 20 MB 초과 · 세로형.
페이지 수는 제한하지 않고 지금처럼 공개 알림에 표시만 한다.
