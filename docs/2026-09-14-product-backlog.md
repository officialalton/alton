# 제품 백로그 — 2026-09-14

제품 오너 요청을 기획 세션에서 기록했다. 아래는 개발 요구이며 구현·배포 완료 보고가 아니다.

## 1. 과목별 전체 교재 보기 — 현재 P2/P3 작업과 연계 우선

**우선순위:** 현재 교재 라이브러리·수업 준비 공통 뷰어 작업과 함께 반영을 우선 검토한다. 독립적인 대규모 재설계로 확대하지 않는다. 기존 조회·뷰어를 재사용하되 난이도는 구현 경로 확인 후 판단한다.

### 사용자 흐름

- 기존 교재 탭에서 과목 선택 → 단원별 전체 목차 → 교재 읽기.
- 과목 안의 교재를 정해진 순서로 처음부터 끝까지 읽고 이전/다음 교재로 이동한다.
- 교재 내부 섹션으로 바로 이동하고 마지막 읽던 위치를 이어볼 수 있게 한다. 읽던 위치는 사용자별로 관리하고 학습 완료나 수업 진도 처리와 혼동하지 않는다.
- 회차 연결·예약·수업 시작 없이 이용한다. 열람을 위해 가짜 수업이나 예약을 만들지 않는다.

### 대상과 콘텐츠 기준

- 학생 포털에도 반드시 제공: 본인 수강 과목의 공개된 과목 공통 교재.
- 교사는 담당 과목, 보호자는 연결된 자녀의 같은 범위를 읽기 전용으로 열람한다. 관리자는 관리 대상 과목을 확인한다.
- 초안·보관 교재, 다른 학생의 전용 자료, 교사의 비공개 준비 메모는 전체 목록에서 제외한다. 서버 조회와 직접 접근에도 같은 권한 기준을 적용한다.
- 과목 전체 읽기는 현재 공개 버전, 지난 수업 복습은 당시 고정 버전을 읽는다. 편집 중인 살아 있는 본문으로 공개본을 대체하지 않는다.
- 특정 수업의 필기를 과목 전체 읽기에 자동으로 섞지 않는다. 해당 수업에 진입하면 그 수업의 필기를 확인한다. 이번 범위에서 별도 개인 필기 체계를 신설하지 않는다.

### 편집 권한 — 관리자만 (2026-09-14 확정)

- 과목별 전체 보기의 공통 교재 내용·포함 구성·단원 배치·정렬·공개/보관 상태는 관리자만 변경한다. 기존 관리자 교재 관리 경로를 재사용할 수 있다.
- 교사·학생·보호자는 각자 허용된 과목을 열람만 한다. 편집 도구를 숨기는 것뿐 아니라 서버 변경 요청에서도 비관리자 쓰기를 거부한다.
- 교사가 자신의 기본 구성이나 학생별 수업 준비에서 교재를 선택·제외·정렬하는 기존 권한은 유지한다. 그 변경이 과목 전체 보기의 공통 원본이나 순서에 반영되면 안 된다.
- 사용자별 읽던 위치 저장은 공통 교재 편집과 구분한다.

### 기존 키워드 연결 재사용 기준

- 제품 오너 제안: 과목의 키워드와 교재 연결을 활용해 전체 공개 교재를 모으는 단순한 조회·노출 방식부터 검토한다. 회차마다 교재 연결을 새로 만들 필요는 없다.
- 키워드는 자료를 찾는 연결 기준이고 단원은 목차의 묶음이다. 기존 단원 개념은 유지한다.
- 같은 교재는 한 번만 노출한다. 키워드 미지정 공개 교재도 과목 전체 보기에서 누락시키지 않는다.
- 단원 미지정 교재는 별도 묶음으로 표시한다. 키워드 안 순서만으로 전체 순서가 모호하면 기존 단원·교재 정렬 기준을 우선 재사용하고 안정적인 전체 순서를 정한다.

### 인수 기준

- 학생이 예약 없이 수강 과목의 전체 공개 공통 교재를 목차와 이전/다음 이동으로 읽는다.
- 키워드 미지정·단원 미지정·중복 연결에서도 누락·중복이 없다.
- 교재 재공개 후 전체 읽기는 새 공개본을, 과거 수업은 기존 고정본을 표시한다.
- 다른 과목·학생 전용 자료·비공개 자료 접근은 차단된다.
- 관리자만 공통 구성·내용·순서를 변경할 수 있고, 교사·학생·보호자의 직접 변경 요청은 거부된다. 교사 수업 준비 조정 후에도 과목 전체 보기의 공통 구성은 유지된다.

## 2. 마스터 / 중간 관리자 계정과 권한 배분 — 낮은 우선순위

**상태:** 후속 백로그. 현재 P2/P3·UAT 완료를 막지 않으며 이번에 역할 체계를 구현하지 않는다.

- 현재 관리자를 향후 마스터 관리자로 두고 중간 관리자 계정에 업무별 권한을 부여·회수하는 구조를 설계한다. 계정 ID를 코드에 고정하지 않는다.
- 업무 범위: 사용자·매칭·예약·콘텐츠 운영·회사 문서·계약·교사 제출 서류·정산. 조회와 변경·발송·실행 권한을 구분한다.
- 초대·비활성화·권한 변경 기록, 본인 권한 상승 차단, 마스터 관리 권한 보호를 포함한다.
- 화면 숨김만으로 제한하지 않고 서버·DB·파일 접근까지 같은 권한 기준을 적용한다. 기존 contracts 조회 정책의 비대칭도 이때 함께 정리한다.
- 지금은 별도 정산 관리자 역할이 없고 기존 관리자 접근과 교사 본인 서류 경로를 유지한다. 세부 역할 이름과 capability 매핑은 후속 설계에서 확정한다.
- 기존 기록: [P4-3 Drive 준비 문서 §7](2026-09-12-p4-3-drive-provisioning-request.md#7-후속-계획--마스터-관리자--중간-관리자-권한-배분). 해당 절의 권한 매핑은 설계 후보이며 최종 결정으로 간주하지 않는다.

## 3. 파일럿 직전 UI·경로·성능 폴리싱

**우선순위:** 파일럿 직전의 마지막 마감 단계. 문제은행·교재·수업·과제 기능을 진행 중인 현재 작업은 중단하지 않는다. 신규 기능 범위를 넓히는 작업이 아니라, 완료된 주요 흐름을 실제 운영 가능한 수준으로 다듬는 라운드다.

### UI와 피드백

- 이모지 기반 아이콘·표현을 제품 UI에서 걷고, 공통 아이콘과 문구 체계로 통일한다.
- 클릭 가능한 요소의 hover/focus/disabled 상태를 분명히 하고, 저장·공개·발급·연결·수업 시작처럼 시간이 걸리는 행동은 진행 중 상태와 중복 클릭 방지를 제공한다.
- 성공·실패·재시도 가능 여부를 사용자 언어로 표시하고, 내부 오류 코드·기술 메시지는 노출하지 않는다.
- 로딩 중, 빈 목록, 권한 없음, 조회 실패를 각각 다른 상태로 보여 준다.

### 학생·보호자 포털 영어화

- 학생·보호자에게 노출되는 화면의 고정 UI 문구를 영어로 통일한다. 버튼, 오류, 빈 상태, 날짜·시간, 커리큘럼·수업·과제·문제·자료 화면을 포함한다.
- 관리자·교사 운영 화면의 언어 변경과, 과목명·교재명·문제 본문 등 운영 콘텐츠의 일괄 번역은 이번 범위에 포함하지 않는다.

### 경로와 뒤로가기

- 브라우저와 화면 내부의 뒤로가기는 현재 역할·과목·학생·회차 문맥을 유지한다.
- 수업 준비, 예약 수업, 학생별 커리큘럼, 문제 풀이, 과제, 자료 미리보기에서 빈 화면·상위 화면·다른 맥락으로 튀는 경로를 전수 점검한다.
- 직접 URL 진입, 새로고침, 탭 전환과 뒤로가기 뒤에도 동일한 권한·문맥으로 복원된다.

### 성능

- 측정으로 느린 화면과 원인을 먼저 특정한다. 최소 대상은 커리큘럼, 수업 준비, 문제은행, 학생 문제 기록, 과제, 자료 미리보기, 회사 문서 목록이다.
- 불필요한 전체 재조회·순차 요청·큰 데이터 선로딩·탭 전환 시 화면 초기화를 줄인다. 이미 볼 수 있는 내용은 먼저 표시한다.
- 주요 화면의 개선 전후 초기 표시와 탭 전환 시간을 기록하고, 남은 병목은 파일럿 리스크로 명시한다.

### 완료 기준

- 교사·학생·보호자·관리자별 대표 흐름을 Preview에서 확인하고, 클릭 피드백·저장 결과·새로고침·뒤로가기·오류·빈 상태를 포함한다.
- 파일럿 전 결과를 별도 체크리스트로 보고한다.
