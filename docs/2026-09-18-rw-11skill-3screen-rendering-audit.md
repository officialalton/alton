## 발견한 버그와 수정

**버그**: `app/admin/ProblemDraftEditor.tsx`의 `PublishedContentView`(공개본 및
"자동생성 초안 읽기전용" 미리보기에 공용으로 쓰임)가 근거 모델 4필드
(`evidenceTarget`/`evidenceSpan`/`answerRationale`/`distractorErrorTypes`)를 전혀
렌더링하지 않았다. 반면 수동 편집용 `ProblemDraftEditor` 본문에는 "내부 검토용 —
학생 비공개" 라벨로 이미 존재했다. AI 자동생성 문항(현재 검수 탭 55개 전부)은
`ProblemBankTab.tsx`의 `autoGenerated` 분기에서 편집 UI 대신 `PublishedContentView`
읽기전용 뷰만 보여주므로, **근거 모델 5개 세부 기술(words_in_context,
central_ideas_details, inferences, command_of_evidence_text,
cross_text_connections)의 자동생성 초안은 관리자가 검수 목록에서 근거 인용·근거→정답
논리·오답 유형을 볼 방법이 없었다.**

**수정**: `PublishedContentView`에 동일한 "내부 검토용 — 학생 비공개" 블록을
추가(`isEvidenceModelSkill` 가드, 값이 있을 때만 렌더). 학생·교사 화면 코드에는
해당 필드에 대한 쿼리 자체가 없으므로 이 수정으로 학생 비공개 원칙이 깨지지 않는다.

- 커밋: `dce6433` — `fix(problem-bank): 검수 목록의 자동생성 초안·공개본 읽기전용 뷰에도 근거 모델(내부 검토용) 노출`
- **주의**: 현재 검수 탭의 기존 55개 초안은 모두 2026-09-17 근거 모델 기능 이전(혹은
  해당 필드가 비어 있는 상태로) 생성되어 `evidenceSpan` 등이 비어 있다 — 수정된 블록이
  실제 데이터로 화면에 뜨는 것을 라이브로 볼 수 없었다. 코드는 기존
  `ProblemDraftEditor` 블록과 완전히 동일한 JSX(같은 필드명·같은 가드 조건)를
  그대로 복제했으므로 로직 정확성은 코드 대조로 확인했다.

## (c) 화면별 검증 방식 — 실측 vs 코드 검증(proxy)

- **관리자 검수 화면**: 11개 스킬 전부 실측(Preview에 로그인해 실제 카드를 열어
  `read_page`/`get_page_text`로 확인).
- **학생·교사 화면**: 실제 로그인 세션으로 배정된 수업 회차에 들어가 화면을 띄우는
  것은 이번 라운드에서 하지 않았다(전용 UAT 학생·교사·회차 세팅이 필요해 범위를
  초과) — 대신 `app/session/[id]/ProblemsPanel.tsx`(학생·교사·관리자가 공유하는
  단일 세션뷰 컴포넌트)와 `app/student/ProblemHistoryTab.tsx`(과제/이력) 소스를
  읽어 역할별 분기(`viewerRole`, `isTeacherLike`, `answerShown`, `graded`)와
  지문·표 렌더 컴포넌트(`RwStimulusView`, `ProblemFigure`)가 관리자 미리보기와
  **완전히 동일한 컴포넌트**임을 코드로 확인했다. 근거 모델 필드에 대한 쿼리가
  session/student 코드 어디에도 없음을 grep으로 확인해 노출 가능성 자체를 배제했다.
  11개 스킬 전부 이 방식(코드 검증)으로 커버했다 — 화면별로 다른 결과가 나올 스킬별
  분기 로직이 없으므로 스킬 단위가 아니라 화면(공유 컴포넌트) 단위 검증이다.
