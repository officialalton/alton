# 기존 원격 문항 정답 위치 편향 교정 — 계획과 진행 (2026-10-01 갱신)

원격 접근·반영 없음. 원문은 로컬 passed.json(모의고사용 959 + 일반용 full 908 + stage1 39 = 1906건). 마이그레이션은 총괄이 직접 작성한다(이 문서에 SQL 없음).

## 1. 문제
정답 위치가 치우쳐 있다(기존 분포 RW A 53/B 31/C 12/D 4%, Math 40/34/22/4%). 풀 분포가 곧 조립 세트·학생 시험의 분포다.

## 2. 방식
섞기 대상 선별 → 목표 위치 배정(섹션·source 별 최소 위치 우선, 결정론) → 정답만 목표로 옮기고 나머지 상대 순서 유지 → 해설(한·영)의 선택지 참조를 새 순서로 치환 → 정적 감사 → (유료) 독립 모델 검증.
생략: 숫자 선택지 Math(오름차순 관례), mc 아님, 선택지 안 글자, 순서 의존 선택지, 본문·도형에 A~D 토큰(점·변수), 정적 감사 실패, 이미 목표 위치.
산출물: `data/mock-exam-generation/position-fix/` — plan.json(전후·순열·재작성 방식), summary.json, plan.v1.json(1차 규칙 계획, 보존), verify-results.json(보강 전 규칙의 표본 검증), verify-results.strict-v1.json(너무 엄격했던 첫 판정, 보존), apply-candidates.json(검증 통과 223건), apply-candidates.static-only.json(정적 감사만 통과 891건, 반영 금지), ledger.json.

## 3. 표본 검증 결과(보강 전 규칙, 비용 $25.01 — 상한 도달)
- 판정 기준을 '글자 참조 정합'으로 좁히고, 실패하면 원래 순서에도 같은 감사를 돌려 기존 결함과 섞기로 새로 생긴 오류를 구분했다(첫 판정은 원 문항 결함까지 잡아 오탐 65%).
- 섞기로 새로 생긴 오류 13건. 층별: math 글자참조 3/63, rw 글자없음 2/20, rw 글자참조 2/40, rw AI재작성 3/87, math 글자없음 3/20, math AI재작성 0/6. 임계(1%) 초과라 전수 확대가 필요했으나 예산이 소진돼 중단. 검증 통과 223건만 적용 후보로 유지.
- 기존 결함(섞기와 무관, 한·영 해설 불일치 등) 28건은 별도 표시.

## 4. 오류 원인과 보강 규칙
13건의 원인은 두 가지였다.
1. **서수 참조 미치환**: "첫/두/세/네 번째 선택지", "first/second/third/fourth option·choice"(7건 안팎).
2. **관사 오인**: 영어 해설의 "making A correct", 문장 첫머리 "A misrepresents …", "A the"·"A as" 의 A를 관사로 보고 건너뜀.

보강(`scripts/mock-exam-generation/position-fix-rules.ts`):
- 서수(한국어·영어)를 순열에 따라 새 위치의 서수로 치환(대소문자·띄어쓰기 보존).
- 문장 첫머리 "A + 소문자 단어": 기능어·부사(-ly)·3인칭 동사(-s)가 오면 참조, 명사·형용사면 관사. 문장 중간의 대문자 A는 참조. 따옴표 안은 불변.
- 불확실 표현("마지막·이전·위 선택지")은 섞지 않음.
- 정적 감사(전 대상): 선택지가 기존의 순열인가, 정답 선택지 내용 동일성, 참조 서열(글자·서수)이 새 순서로 정확히 사상되는가, 참조를 가린 본문 불변, 해설이 지목한 정답 위치가 새 정답과 일치하는가(원 해설의 지목이 원 정답과 다르면 기존 결함으로 생략). 실패하면 '생략'으로 확정하고 목표를 다시 배정.
- 단위 테스트 31개: 실패 13건 원문을 고정 사례로 포함(`scripts/mock-exam-generation/fixtures/position-fix-failures.json`), 돌연변이 테스트(서수 미치환·영어 미치환·글자 오치환·순열 훼손·본문 변조)가 모두 감사에 걸림.

## 7. 원격 반영 시 주의(총괄 작성 마이그레이션 입력)
- 세트 항목·수업 매니페스트·과제·풀이판·오류 신고·판정·채점 조정은 본문을 복사하지 않고 problem_version_id 로 참조하고, 채점도 응시 시점에 버전 행의 정답을 읽는다. 따라서 이미 응시·수업·과제·신고가 걸린 버전을 제자리에서 바꾸면 학생이 고른 번호와 저장된 정오가 어긋난다. 그런 문항은 건너뛰고 원문 유지(새 버전을 만드는 대안은 현재 공개 버전만 옮기므로 이미 조립된 세트는 옛 순서 유지).
- 반영 항목은 문항 식별(quality 의 gid), 기대하는 이전 내용(expected), 새 내용(options·correct_index·explanation·explanation_en), perm, 방식, 검증 구분을 가진다. 이전 내용이 현재와 다르면 건너뛴다(멱등·stale 방지). 이력은 append-only.
- 위험: 규칙이 확신 못 하는 표현의 잔여 오차(전수 검증으로 통제), 기존 결함 문항(28건 표시), Math 숫자 선택지 편향은 이 방식으로 교정 불가(생성 단계 목표 위치 주입으로만 해결).
