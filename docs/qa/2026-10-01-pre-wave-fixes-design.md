# 웨이브 전 사전 수정 5건 설계

## 스크립트 수정(구현·테스트 완료: `scripts/mock-exam-generation/diversity.ts`, `diversity.test.ts`)
1. **목표 정답 위치 주입**: 후보마다 `targetLetterFor(skill, idx)`로 A~D 균등 순환 배정. 프롬프트에 목표를 알리되 모델이 어겨도 `enforceTarget`이 코드로 선택지 재배치·해설 글자 치환(숫자 선택지·선택지 내 글자 토큰 문항은 건너뜀, 결과에 skipped 사유). 웨이브 생성 스크립트에 연결하는 일은 웨이브 승인 때 한다(현 생성 경로는 변경하지 않음).
2. **소재 씨앗 주입**: `data/mock-exam-generation/seeds.json`(6범주×20=120소재, 원문 복제 없음). `scheduleSeeds`가 skill 안 중복 금지, 전체 최대 2회로 배정. 프롬프트에 "이 소재를 다루되 도입부 문장 패턴 반복 금지" 지시로 주입.
3. **유사도 게이트**: `SimIndex`(3-gram MinHash 64)를 ledger 옆 jsonl로 영속, 생성 직후 검수 전 `gate()`로 같은 skill 내 유사도 ≥0.6 또는 같은 문두(첫 3단어) 3건 이상이면 폐기(재생성 1회). 전역 누적이라 웨이브 간·기존 풀(`passed.json`로 인덱스 초기화)과도 비교.

## 앱 코드 수정 제안(문서만, 미구현)
4. **세트 조립 hard 교차 세트 제외**: 위치 `lib/mock-exam/` 조립 선택 함수(선택 키 `[skill 사용량, 재사용 여부, 노출, id]`). 현재 skill 균형이 재사용 회피보다 우선이라 hard가 세트 간 겹칠 수 있다. 제안: hard(난이도=hard) 후보에 한해 이전 세트에서 쓴 문항 id를 하드 제외(후보 부족 시에만 재사용 허용하고 경고 기록). 테스트: 2세트 연속 조립 시 hard 교집합 0.
5. **`materialBlocker` 자료 종류 오탐**: 위치 조립 전 검증의 자료 종류 차단 로직. 그래프·표가 없는 순수 텍스트 문항을 자료 필요 문항으로 오판해 풀에서 제외. 제안: 자료 종류 판정을 `problem.material_kind`(명시 필드) 우선, 본문 키워드 추정은 경고만. 회귀 테스트: 텍스트 전용 문항 1개가 차단되지 않음.
- hard SPR 공급 부족은 별도(레시피 v2 골격 기반 생성) 과제로 유지.
