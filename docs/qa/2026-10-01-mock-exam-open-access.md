# 모의고사 배정 폐지 + 보드 할 일 감사 필드 — 착수 전 1장 정리 (2026-10-01)

오너 확정: 공개(published) 모의고사는 모든 활성 학생에게 공통 노출, 학생이 '시작'할 때 응시가 생긴다. 선생님의 학생 지정은 보드 할 일 추가로 대신한다. 보드 할 일에는 생성·편집 감사 필드를 서버가 남긴다.

## 1. 사용자 흐름

- **학생**: 모의고사 탭 → 공개 세트 목록(미응시 / 진행 중 / 완료) → `시작`(서버 RPC가 응시 생성, 이미 있으면 같은 응시) → 응시 화면(M1→경로→M2→채점, 기존 흐름 그대로) → 완료 후 `결과 보기`. 진행 중이면 `이어서 하기`.
- **학부모**: 같은 목록을 읽기 전용으로 본다(시작 불가). 자녀의 완료 응시만 상세 결과 링크.
- **선생님**: 담당 학생의 시작한 응시를 현황·열람·내역에서 읽기 전용 열람. 배정 서브탭 삭제. 특정 학생에게 시험을 지정하려면 학생 보드에 할 일 추가.
- **관리자**: 세트 생성·검토·공개·보관·응시 내역 열람. 배정 서브탭·`전체 학생 배정` 삭제.
- **보드**: 모의고사 카드는 시작한 응시(진행 중·완료)만. 미응시 세트는 카드가 아니다. 할 일 카드 상세에 `생성: 이름·날짜 / 최종 편집: 이름·날짜`.
- 실패·재시도: 시작 실패(비활성·미공개·보관·구성 미완료)는 오류 문구를 보이고 이동하지 않는다. 시작 버튼 중복 클릭·동시 시작은 응시 하나로 수렴(멱등).

## 2. 데이터와 권한

- **응시 생성 경로는 하나**: `mock_exam_open_start(set)` 정의자 RPC — `students.status='active'` 본인만, 세트가 published·미보관·(mst면 readiness=ready). 같은 학생·세트 계열 응시가 이미 있으면(기존 배정분 포함, 세트가 그 뒤 보관돼도) 그 id를 돌려준다. 최종 방어는 기존 고유 인덱스 `mock_exam_attempts_one_per_student_per_exam (student_id, exam_set_group_id)`.
- 교사 응시 INSERT/UPDATE RLS 제거(학생은 원래 INSERT 정책 없음). 관리자 전체 정책·서비스 롤은 유지. 기존 배정 응시(status `assigned`, 마감일·assigned_by 포함)는 그대로 유효.
- `mock_exam_open_catalog(student)`: 공개 세트 + 그 학생의 응시를 한 번에(학생 본인·학부모·담당 교사·컨설턴트·관리자, `_mock_exam_can_view`).
- 보드 감사: `board_manual_tasks`에 `created_by_name`·`updated_by`·`updated_by_name` 추가, BEFORE INSERT/UPDATE 정의자 트리거가 `auth.uid()`로 생성자·편집자·시각을 기록하고 클라이언트 값(`created_by`·`created_at`·`updated_*`)을 덮어쓴다. 생성 정보는 UPDATE에서 불변. 서비스 롤 수정은 편집자 유지·편집일 갱신. 이름은 기록 시점 스냅샷(profiles를 못 읽는 역할도 표시). 백필: 생성자 이름은 있는 대로, 한 번도 수정되지 않은 행만 편집자=생성자, 그 외 편집자 null('알 수 없음'). 삭제는 행이 사라지므로 기록 대상이 아니다.
- 마이그레이션(20261995~997 대역): `20261995000000_mock_exam_open_access.sql`, `20261995000001_board_task_audit.sql` — 모두 additive(정책 2개 drop 제외).

## 3. UAT 데이터

- 자동 테스트: 실행 ID(`oa<ts><rand>`) 접두로 학생 4(활성 3·비활성 1)·낯선 보호자 1·세트 5·응시·할 일을 만들고 종료 시 접두 단위 삭제(0건 확인). 시드 학생·교사·보호자는 읽기만(할 일은 실행 ID 제목으로만 생성·삭제).
- Preview UAT(오너 로그인 창): 실행 ID 전용 UAT 학생 2명(활성 1·비활성 1)·UAT 보호자 1·UAT 선생님 연결 + 공개 UAT 세트 1개(`UAT-<실행ID>-mock`, 고정형 소형 또는 구성 완료 mst). 사전 점검: 공식 공개 세트·공식 계정 수 기록. 종료 후: 실행 ID 응시·세트(보관→삭제)·학생·할 일 정리, 공식 계정·공식 세트 수 불변 확인. 공식 세트는 UAT에서 시작하지 않는다(학생이 실제로 응시를 남기므로).

## 4. UI 기준

- 학생 목록 행: 이름·난이도 배지·설명·상태 문구·행동 1개(시작 / 이어서 하기 / 결과 보기). 상태: 로딩("불러오는 중…")·빈("공개된 모의고사가 없습니다.")·오류(빨간 문구)·시작 중("시작하는 중…", 버튼 비활성). 모바일은 한 열 목록. 키보드: 버튼·링크 기본 포커스.
- 학부모: 같은 행, 행동은 완료의 `상세 결과 보기`만.
- 보드 카드 상세: `<details>` '상세' 펼침(키보드 토글), 시각은 뷰어 시간대(`lib/format-datetime.ts`), 모르면 '알 수 없음'. 모든 열람 화면이 `BoardColumnsView` 공통 컴포넌트를 쓴다.
- 폴리싱은 마일스톤 종료 라운드에서 일괄.

## 5. 검증과 성능

- DB 통합(격리 스택): 시작 RPC 권한 매트릭스(활성 허용 / 비활성·학부모·선생님·익명 거절 / draft·보관·없는 세트 거절 / 중복 멱등 / 8병렬 경쟁 → 응시 1건), 기존 배정 응시 공존·보관 뒤 멱등, 카탈로그 권한, 학생·교사 직접 INSERT 거절, 고유 제약, 보드 감사(서버 기록·위조 불가·불변·서비스 롤). 기존 모의고사 통합 회귀(교사 배정 가정 테스트 3곳 정정).
- 컴포넌트: 학생 목록(상태·시작·오류·빈), 학부모 읽기 전용, 보드 카드 감사 표시, 목록 합성 순수 함수.
- 성능: 학생 탭은 RPC 2회(카탈로그 + 응시 요약, 병렬, SSR 선로딩), 세트 수 30개 이상에서도 세트별 추가 요청 없음. 관리자 내역은 최근 200건·시작 전 제외·정답 집계 청크 8(PostgREST 1,000행 상한 아래).
