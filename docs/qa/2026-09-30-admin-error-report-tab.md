# 관리자 '오류 신고' 탭 — 착수 전 1장 정리 (2026-09-30)

1. 사용자 흐름: 관리자 > Error Reports > 신고 내역(문제은행 '신고' 탭에서 이전; 목록·상세·판정) / 통계(기간 필터, 축별 막대, 상위 칸 표). 상위 칸 행 클릭 → 해당 skill·난이도·기간으로 필터된 신고 내역. 문제은행에는 '신고 검토 필요 N' 칩과 이동 링크만 남김. 판정 UI는 1단계 '오류→보관 / 정상→복귀', 오류면 2단계 유형(정답/문제 자체/해설). 실패: 오류 + 다시 시도, 빈 상태 문구.
2. 데이터·권한: 신규 테이블 없음. `problem_error_report_stats(p_days)` 집계 RPC 1회(정의자, is_admin 전용), `problem_error_report_groups` 에 skill/난이도/영역/기간 필터 추가(기존 호출 호환). 신고율 = 신고 문항 수 ÷ 활성(공개·미보관) 문항 수, 신고된 보관 문항은 분모에 포함. 생성 배치 실행 ID는 저장 위치가 없어 생성 경로(created_via)×생성 월로 대체(한계 명시). 판정 RPC·권한·멱등성 변경 없음.
3. UAT 데이터: 자동 테스트는 실행 ID(RUN)가 붙은 skill_code `zz<RUN>`·학생·문항을 만들고 afterAll 에서 replica 모드로 그 행만 정리. 공식 계정·시드 미변경.
4. UI 기준: 요약 카드 4 + CSS 막대 목록 + 주별 막대 + 표, 스켈레톤·빈 상태·오류 재시도, 모바일 1열, 키보드 접근(탭·버튼), 날짜 lib/format-datetime(Asia/Seoul).
5. 검증·성능: 집계 정확성·권한 매트릭스·필터·재실행 안전은 통합 테스트, 화면은 Vitest. 쿼리는 집계 RPC 1회(클라이언트 추가 요청 없음), 기간 필터는 기존 created_at 인덱스, 새 인덱스 없음.
