# PDF 교사용 팁 레이어 — 착수 전 1장 정리 (2026-10-01)

브랜치 `feat/pdf-teacher-tip-layer`. 교재가 Drive PDF 고정 사본으로 바뀌어 옛 `teaching_tip` 칸은 쓸 수 없다.
관리자가 PDF 페이지 위에 기존 필기 도구(펜·지우개·텍스트·전체 지우기)로 쓴 "교사용 팁"을 선생님에게만 보여준다.

## 1. 사용자 흐름
- 관리자: 자료 열람(`/materials/[id]`, 관리자) → `팁 편집` 켜기 → 페이지를 보며 쓰고 그린다 → 자동 저장(`저장 중…/저장됨/저장 안 됨 + 다시 시도`) → 새 공개 버전은 팁이 **빈 채로** 시작(자동 이전·내용 비교 없음) → `이전 버전에서 팁 불러오기`: 쪽 매핑 화면(옛 쪽 행 → 새 쪽 선택·건너뛰기, `N쪽부터 +1/-1 밀기`, 두 쪽 맞바꾸기, 같은 대상 중복은 실행 전 차단, 대상에 팁이 있으면 덮어쓰기 확인, 결과 요약) → 불러온 쪽은 모두 **검토 전**(선생님에게 서버가 숨김) → 새 페이지와 같이 보며 쪽별 `이 쪽 확인`·`전체 확인`(고쳐 쓰면 그 쪽은 자동 확인) → 쪽수가 다르면 `쪽수가 달라졌습니다. 페이지가 밀렸는지 확인하세요.` 경고. 이미 불러온 뒤에도 편집 화면에서 한 쪽의 팁을 같은 버전 안 다른 쪽으로 복사·이동(충돌 시 확인).
- 선생님: 수업 화면 교재 탭 PDF 위에 팁이 겹쳐 보인다(기본 표시, `교사용 팁 보기/숨기기` 토글, 선택은 선생님 기기에 유지). 선생님 자기 필기 레이어와 색(자주색 점선 라벨 `교사용 팁`)으로 구분. 읽기 전용.
- 학생·학부모: 토글·레이어·요청이 없다(서버도 거절).
- 실패: 조회 실패면 팁 없이 교재는 정상, 저장 실패면 미저장 획 보존 + 다시 시도. 버전 가져오기는 트랜잭션(전부 또는 없음), 같은 조작 재실행은 no-op.

## 2. 데이터와 권한
- 새 테이블 `pdf_tip_events`(append-only 이벤트: stroke/clear_all, `(curriculum_doc_version_id, page_number)` 기준, `client_event_id` 고유로 중복 방지), `pdf_tip_page_copies`(쪽 단위 불러오기 기록·원본 버전/쪽·`needs_review`=검토 전). 기존 `session_annotation_events`는 수업 귀속이라 재사용하지 않는다(수업과 무관한 팁이 수업 행을 오염).
- 쓰기: 정의자 RPC `append_pdf_tip_events`·`copy_pdf_tips_from_version`·`mark_pdf_tip_page_reviewed`, **`is_admin()`만**. 테이블 직접 insert/update/delete 정책 없음.
- 읽기: RLS `can_read_pdf_tip_page(version, page)` = 관리자, 또는 (`can_read_pdf_tips(version)` 이면서 그 쪽이 검토 전이 아님). `can_read_pdf_tips(version)` = 관리자, 또는 그 버전을 매니페스트(시작 후)·회차 구성(시작 전)에 가진 수업의 **담당 선생님**. 학생·학부모·타 선생님·익명 불가(REST·RPC 모두). 스토리지 경로 없음(팁은 DB 행만).
- 팁은 **수업별로 얼리지 않는다**: 관리자가 옛 버전 팁을 나중에 고치면 그 버전을 쓴 과거 수업에서도 고쳐진 팁이 보인다(기본 동작, 오너 확정 전 권장).
- 마이그레이션 `20261980000000_pdf_teacher_tip_layer.sql`(additive, 기존 파일 수정 없음).

## 3. UAT 데이터
- 실행 ID(`tipuat_<timestamp>`)가 제목에 붙은 전용 PDF 자료·가족·수업, 자동 테스트와 분리. 시작 전: 관리자·담당 선생님·학생 계정 확인. 종료 후: 실행 ID 단위로 자료 보관/정리, 공식 계정 보존 확인. 이번 세션은 원격·Preview를 만지지 않는다(총괄이 Preview UAT 실행).

## 4. UI 기준
- 관리자 편집: 기존 필기 툴바(펜·지우개·T·전체 지우기·색) + 저장 상태 + 쪽 배지(`팁 있음`/`검토 필요`). 빈 쪽은 "이 쪽에는 팁이 없습니다" 안내, 로딩 "팁 불러오는 중…", 오류 "팁을 불러오지 못했습니다".
- 선생님: 토글 1개(`교사용 팁 보기/숨기기`), 읽기 전용(입력 캔버스 없음 → 클릭 통과), 모바일에서 툴바 줄바꿈.
- 키보드: 텍스트 상자 Enter 확정·Esc 취소(기존 동일), 토글은 버튼(Tab/Space).

## 5. 검증과 성능
- DB 통합(격리 스택 `ALTON-tip`, 54521~): 권한 매트릭스(관리자 쓰기, 선생님 읽기·쓰기 거절, 학생·학부모·타 선생님·익명 읽기/쓰기 거절), 버전 가져오기(멱등·덮어쓰기 확인·쪽수 불일치 검토), eventId 중복, 교재 변경 동작(새 버전·보관·시작 전 pin·팁 비동결) — 실행마다 고유 데이터, 재실행 안전.
- 컴포넌트: 선생님 토글·저장된 선택 유지, 학생 화면 비노출(요청 0), 관리자 편집 상태.
- 성능: 교재 탭 진입 시 선생님은 **보이는 페이지 1건당 select 1회**(`pdf_tip_events`, 일괄이 아닌 쪽 단위 지연 로드, 쪽 이동 때만), 숨김이면 0회, 학생 0회. 기존 교재 탭 요청(필기 2회/쪽)에 더해 +1.

## 6. 교재가 바뀔 때의 동작 (코드 확인 + 통합 테스트 `app/admin/pdf-teacher-tip-layer.integration.test.ts`)

1. **새 공개 버전**: 시작한 수업은 `session_content_manifest.curriculum_doc_version_id`(시작 때 고정)로 옛 사본·옛 버전의 교사/학생 필기·옛 버전 팁을 그대로 연다. 새 버전에는 필기·팁이 없다(필기는 (수업, 버전, 쪽), 팁은 (버전, 쪽)이라 섞일 경로가 없음). 테스트 통과.
2. **자료 보관(archived_at)**: 고정 사본 경로는 `curriculum_doc_versions.snapshot.asset`(버킷·경로)이고 서명 URL(`app/materials/asset-actions.ts`)은 서비스 키로 버킷을 직접 서명하므로 보관 여부를 보지 않는다. 버전 행 조회 RLS는 `curriculum_docs` 행 가시성을 따르는데 그 정책도 `archived_at`을 보지 않는다. 그래서 보관 후에도 학생·선생님이 옛 사본을 열고 필기·팁도 조회된다(보관 해제 후도 동일). 테스트 통과. (시작 전 수업의 *예정 구성*은 `loadPlannedMaterialData`가 보관 자료를 제외하고, 수업 시작·재고정은 보관 자료를 막는다 — 기존 의도대로.)
3. **시작 전(수업 준비 중) 수업**: 회차 구성에 자료를 담을 때(`curriculum_overlay_unit_materials` insert, `fill_unit_material_version`) 그 시점 공개본이 `curriculum_doc_version_id`로 채워진다. 그 뒤 새 버전이 공개돼도 구성은 담을 때의 버전 그대로(준비 화면이 보던 것이 바뀌지 않음). 매니페스트(고정)는 **수업 시작 시**(`link_unit_prep_to_session` → 시작) 생성되고 구성이 들고 있던 버전을 그대로 옮긴다. `null`(레거시)이면 예정 화면은 그 시점 최신 공개본을 쓴다(`loadPlannedMaterialData`) — 팁 읽기 권한도 같은 규칙(`coalesce(구성 버전, 지금 공개본)`)이라 화면과 권한이 어긋나지 않는다. 의도와 다른 점 없음.
4. **팁은 수업별로 얼리지 않는다**(오너 권장·확정 전 기본): 관리자가 옛 버전 팁을 나중에 고치면 그 버전을 쓰는 과거 수업에서도 고쳐진 팁이 보인다. `pdf_tip_events`에는 `session_id`가 없다. 테스트로 고정.
