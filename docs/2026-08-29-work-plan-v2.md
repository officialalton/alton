## 진행 규칙

- 아래 순서를 지킨다. 후속 UI부터 먼저 만들지 않는다.
- 각 에픽 시작 전 해당 에픽만 상세 구현 계획으로 분해한다.
- 각 티켓은 구현, 테스트, 문서 업데이트를 함께 완료한다.
- 개발 데이터라도 파괴적 변경을 피하고, 출시 가능한 migration 이력으로 관리한다.
- 기존 `docs/tickets.md`는 과거 개발 이력이며, 이번 개편 진행 상태는 이 문서에서 관리한다.

## GW-000 — 개발 기준 정리·레거시 제거

출시 전 코드에서 더 이상 사용하지 않을 Calendly·Zoom 구조를 제거하고 역할별 최종 권한을 명확히 만드는 준비 작업이다.

### GW-001 역할별 예약 권한 정리

- [ ] 학생은 본인의 수업을 예약·취소·재예약할 수 있도록 명세
- [ ] 학부모는 자녀의 일정과 Meet 링크를 조회할 수 있도록 명세
- [ ] 학부모 화면에서는 예약 변경 UI를 표시하지 않음
- [ ] 서버에서도 동일한 역할 정책을 적용하는 테스트 추가

완료 조건:

- 학생과 학부모의 권한이 UI와 서버에서 동일하게 적용됨
- 학부모의 조회 기능은 유지되고 일정 변경 기능만 제공되지 않음

### GW-002 자체 상담 흐름으로 교체

- [ ] Calendly iframe 대신 자체 인테이크 폼을 기본 상담 진입점으로 구현
- [ ] Zoom 문구 제거
- [ ] 인테이크 완료 후 Google 기반 상담 슬롯 선택 화면으로 연결

완료 조건:

- 상담 정보가 구조적으로 저장됨
- Calendly UI나 URL에 의존하지 않고 전체 상담 흐름이 동작함

### GW-003 Calendly·Zoom 연동 코드 제거

- [ ] Calendly webhook route와 처리 코드 삭제
- [ ] Calendly URL·signing key·Zoom 관련 환경변수 제거
- [ ] `utm_content` 기반 enrollment 연결 로직 삭제
- [ ] 관련 패키지·문구·테스트·문서 참조 제거
- [ ] 기존 컬럼이 필요하면 migration 기간에만 deprecated 상태로 유지하고 신규 코드에서는 사용하지 않음

완료 조건:

- 신규 상담 및 수업 예약 경로에서 Calendly·Zoom 코드를 호출하지 않음
- 사용하지 않는 webhook endpoint가 배포본에 남아 있지 않음

### GW-004 출시 전 자격증명 정리

- [ ] 테스트 관리자 비밀번호를 출시 전 교체
- [ ] 대화에서 공유된 Supabase secret key를 출시 전 교체하고 배포 환경 갱신
- [ ] 사용하지 않는 Calendly/Zoom/DocuSign 비밀값 삭제
- [ ] `.env.example`과 Vercel 환경변수 대조

- 동일 자녀에게 활성 또는 완료된 체험 수업을 중복 생성할 수 없음
