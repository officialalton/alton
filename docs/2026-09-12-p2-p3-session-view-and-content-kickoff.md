## 1. 사용자 흐름

- **교사(준비, 예약 전)**: 커리큘럼 → 회차 선택 → **수업 준비 모드** 진입(예약 없어도).
  회차 목표·키워드 확인 → 공개 교재·문제 자동 구성 확인 → 보강 자료·교사 메모·
  필기 초안 추가 → 과제 설정. **예약이나 수업 시작 기록을 만들지 않는다.**
- **교사(수업 중)**: 예약된 세션 진입 → 시작 시 콘텐츠 목록·순서·버전 고정(기존
  `pin_session_selection` 재사용) → 교재 보기/필기 모드 전환 → 문제 풀이 진행.
- **학생(수업 중)**: 같은 세션의 학생 모드 — 공유 필기를 보고, 자기 개인 필기·답안은
  따로 남긴다.
- **수업 후(복습)**: 회차에서 **종료된 수업**을 골라 당시 콘텐츠 버전 + 보존된 필기·
  답안을 **읽기 전용**으로 다시 연다.
- **실패/빈/권한 없음**: 준비 안 된 회차, 공개 콘텐츠 0건, 권한 없는 회차 진입,
  저장 실패·재접속을 각각 설계한다(§4).

## 2. 데이터와 권한

- **원본 경로 하나**: 교재는 `curriculum_docs`, 문제는 `problems`, 스냅샷은
  `session_content_manifest`. **본문을 교사·학생별로 복제하지 않는다**(정책 §2).
- **G2 필기 범위** — `canvas_annotations`에 범위·작성자를 더한다(구조 결정은 상세
  설계에서). 필요한 세 범위:
  | 범위 | 귀속 | 보이는 사람 | 시점 |
  | --- | --- | --- | --- |
  | 교사 준비 초안 | **회차**(세션 아님) | 교사 본인(+관리자 점검) | 수업 전 |
  | 수업 중 공유 필기 | 실제 세션 | 교사·해당 학생 | 수업 중·후 |
  | 학생 개인 필기 | 실제 세션 + 학생 | 그 학생(+교사 열람 여부는 §6 미확정) | 수업 중·후 |
- **G3 문제 버전**: 수정은 새 버전으로. 과거 수업이 참조한 버전은 보존하고
  기존 채점 결과를 자동 변경하지 않는다. 스냅샷은 **본문 복제가 아니라 불변 버전
  참조**로 구현한다(정책 §4).
- **권한**: 학생·보호자는 본인·가구 범위의 **공개된** 회차 내용만. 교사 전용 준비
  정보(메모·초안)는 공개하지 않는다. 관리자는 점검 모드로 열되 기준본·교사 운영본·
  학생 실제 세션을 같은 행이나 같은 쓰기 권한으로 합치지 않는다.
- **레거시**: `teacher_curriculum_templates`는 읽기 호환만 유지하고 이번에 제거하지
  않는다(별도 폐기 배치).

## 3. UAT 데이터

- 실행 ID `p3-session-view-20260912`. 전용 교사 1명 + 학생 2명(같은 과목, 한 명은
  종료 수업 이력 보유), 공개 교재 1종(긴 지문·이미지·수식 포함) + 문제 세트 1개.
- 자동 테스트는 `@example.com` 픽스처만, UAT 계정과 분리. 종료 후 실행 ID 단위 정리.

## 4. UI 기준

- **정보 위계**: 회차 목표 → 진도 → 다음 행동이 먼저. 내부 ID·원시 상태값·스키마
  용어(`final_status`, `manifest`, uuid 등)를 **화면에 노출하지 않는다.**
- **모드 분리**: 일반 보기(스크롤·선택·링크 우선)와 **필기 모드**를 분명히 나누고,
  현재 모드와 도구를 항상 보이게 해 오입력을 막는다. 기존 `CanvasOverlay`의 토글을
  그대로 쓰되 표현만 폴리싱한다.
- **교재·문제 화면**: 긴 지문·이미지·수식이 깨지지 않게, 문항 번호·난이도·배점·
  풀이 상태·피드백을 운영 메타데이터 없이 읽기 쉽게. 읽기/풀이/필기/해설/정답
  확인의 구분을 선명하게.
- **상태 전부 설계**: 로딩(스켈레톤), 빈 상태(준비 전·콘텐츠 0건), 오류, **권한 없음**,
  예약 전, 수업 중, 종료 후 복습.
- **기기**: 데스크톱 / iPad + Apple Pencil / 모바일. 정보 밀도와 키보드 동작 점검.
- 마일스톤 종료 시 역할별 스크린샷 기준을 남긴다.

## 5. 검증과 성능

- **통합 테스트**: (a) 예약 없이 세 계층 회차 진입, (b) 상위 구성 변경이 하위를
  덮어쓰지 않음(기존 overlay 테스트 확장), (c) 교재·문제 원본 수정 후에도 종료된
  수업의 콘텐츠·채점 결과 불변, (d) 필기 세 범위의 가시성·보존, (e) 같은 회차를
  여러 수업에서 진행했을 때 준비 구성과 각 수업 기록의 연결.
- **Preview UAT**: 준비 → 수업 시작 → 종료 후 복습 한 흐름을 교사·학생 2인으로.
- **성능**: 선택한 회차에 필요한 것만 로드한다. 전체 회차 콘텐츠 일괄 로드나
  본문 반복 복제를 만들지 않는다(정책 §2). 화면당 쿼리 수를 착수 시 기록한다.

## 6. 미확정 — 제품 오너 결정 필요(구현 착수 전)

1. **학생 개인 필기를 교사가 볼 수 있는가** — 수업 중/수업 후 각각. 현재 정책
   문서는 "권한·보존 범위를 실제 세션 기준으로 구분한다"까지만 정한다.
2. **교사 준비 초안 필기의 공개 시점** — 수업 시작 시 공유 필기로 승격되는가,
   끝까지 교사 전용인가.
3. **회차 ↔ 실제 수업 연결 방식** — 같은 회차를 여러 번 수업할 때 준비 구성을
   공유하는지, 수업마다 복사본을 두는지(정책 §5가 "1:1 가정 금지"만 정함).
4. **문제 버전 전환 시점** — 수정 즉시 새 버전인지, 검수·공개 단계를 거치는지.
5. **보호자 열람 범위** — 회차 목표·진도까지인지, 교재 본문·문제까지인지.
