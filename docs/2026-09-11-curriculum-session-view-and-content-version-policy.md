# 회차별 세션뷰·교재·문제 버전 관리 확정 정책

확정일: 2026-09-11. 제품 오너와 기획 세션에서 확정한 정책이다.
문서 반영만 수행하며 구현·migration·배포 승인 또는 완료 보고가 아니다.
적용 배치: P2-4, P3-1~3. 이번 C-1의 커리큘럼 읽기 전용 진입 수정과 구분한다.

## 1. 커리큘럼 계층과 회차별 준비

- 관리자 기본 커리큘럼 → 교사 과목 운영본 → 학생 개별 커리큘럼으로 이어진다.
- 교사 과목 배정 시 관리자 기본본을 받아 교사만의 운영본으로 조정하고,
  학생 배정 시 해당 교사 운영본을 학생 개별본으로 설정한다.
- 세 계층 모두 모든 회차에서 세션뷰를 열 수 있어야 한다. 예약 전에도 교사는
  회차별 수업 계획·준비를 할 수 있다. 예약이 없다는 이유로 진입을 막지 않는다.
- 상위 구성 수정이 기존 하위 구성을 자동으로 덮어쓰지 않는다. 학생별 변경은
  다른 학생·교사·관리자 구성에 영향을 주지 않는다.
- 공통 세션뷰 구조를 활용하되 관리자 기본본·교사 운영본·학생 개별본의 대상과
  권한을 구분한다. 템플릿 화면에서 출석·수업 시작·종료를 처리하지 않는다.
- 학생·보호자는 본인·가구 범위의 공개된 회차 내용을 열람한다. 교사 전용 준비
  정보와 실제 수업 참여·제출 권한은 별도로 구분한다.

## 2. 중복 저장·로딩을 줄이는 원칙

- 회차에는 구성·키워드·순서·참조·개별 메모 등 필요한 정보를 보관한다.
  모든 회차를 위해 예약이나 실제 수업 실행 데이터를 선생성하지 않는다.
- 선택한 회차에 필요한 내용을 불러온다. 전체 회차의 콘텐츠를 한 번에 읽거나
  같은 콘텐츠 본문·파일을 교사·학생별로 반복 복제하는 구조를 피한다.
- 교재는 관리자만 관리한다. 교재 원본·버전은 공통으로 보존하고 각 회차는
  이를 참조한다. 학생별 필기·답안·진도·수업 기록은 별도로 저장한다.
- 구성의 독립성과 콘텐츠의 공통 참조를 혼동하지 않는다. 교사의 회차 키워드
  변경은 기존 학생 구성에 자동 전파하지 않지만, 준비 중 키워드에 따른 자동
  구성 결과는 최신 공개 콘텐츠를 반영할 수 있다.

## 3. 문제은행

- 문제은행에서 문제 본문·보기·정답·해설과 변경되지 않는 버전을 관리한다.
- 준비 중에는 기존 확정 정책대로 회차 키워드에 맞는 공개 문제를 자동 구성한다.
  이번 결정으로 교사의 개별 문제 선택·원본 편집 정책을 새로 도입하지 않는다.
- 수업에는 실제 사용한 문제 목록·순서·각 문제 버전을 보관한다.
- 학생 답안·제출 시각·채점 결과·풀이 시도는 학생과 해당 수업/과제에 귀속해
  별도로 보관한다. 여러 학생이 같은 문제를 풀어도 문제 본문을 각각 복제하지 않는다.
- 문제 수정은 새 버전으로 관리한다. 과거 수업에서 참조한 버전은 보존하며,
  수정으로 과거 문제·정답·기존 채점 결과를 자동 변경하지 않는다.
- 정답·해설·채점 결과의 공개 시점은 기존 제출·채점 정책을 유지한다.

## 4. 수업 시작과 종료 기록

- 수업 시작 시 콘텐츠 목록·순서와 교재·문제 버전을 고정한다.
- 스냅샷은 본문 전체의 반복 복제가 아니라 보존된 불변 버전 참조로 구현할 수 있다.
  참조 대상 버전은 이후에도 당시 내용을 재현할 수 있어야 한다.
- 수업 종료 후 커리큘럼 회차에서 당시 콘텐츠와 보존된 수업 기록을 읽기 전용으로
  다시 열 수 있어야 한다. 원본·커리큘럼 수정이 과거 수업을 바꾸면 안 된다.
- 필기·화이트보드·풀이 등 수업 중 생성되는 기록은 해당 실제 수업에 귀속한다.
- 기존 교재 위 필기 기능은 원본 교재를 바꾸지 않는 세션 기록으로 유지한다.
  일반 보기와 `필기 모드`를 분리하고, 수업 전 교사 초안·수업 중 공유 필기·학생
  개인 필기와 답안의 권한·보존 범위를 실제 세션 기준으로 구분한다.

## 5. 개발자 상세 설계·인수 기준

- 예약 전 세 계층의 회차별 진입, 교사/학생별 구성 독립성, 학생·보호자 권한을 검증한다.
- 원본 수정 후에도 시작·종료된 수업의 콘텐츠와 기존 풀이·채점 결과가 유지되는지 검증한다.
- 같은 회차를 여러 수업에서 진행할 때 준비 구성과 각 실제 수업 기록의 연결·선택
  방식을 설계한다. 회차와 실제 수업을 무조건 1:1로 가정하지 않는다.
- 교사 준비 정보의 학생·보호자 공개 범위와 시점, 종료 시 보존할 기록의 상세 범위는
  기존 정책과 대조해 명시하고 미확정 제품 결정만 보고한다.
- 기존 스냅샷·문제은행·준비 기능의 구현 여부를 먼저 확인하고 중복 모델을 만들지 않는다.
  구체적인 저장 구조·로딩 방식은 개발자가 결정한다.
- 세션뷰·교재·문제 UI는 개발자 도구처럼 보이지 않는 전문 학습 화면이어야 한다.
  회차 목표·진도·다음 행동을 먼저 보이고, 읽기·풀이·필기·해설·정답 확인을
  명확히 구분한다. 내부 ID·원시 상태값·스키마 용어는 화면에 노출하지 않는다.
  긴 본문·이미지·수식·문제 세트, 빈 상태·오류 상태, 데스크톱·iPad/Apple Pencil·
  모바일의 정보 밀도와 조작성을 P3 UAT에 포함한다.
