# P 실행 로드맵 — 남은 계획 정본

상태: **2026-09-10 기준 향후 실행 정본**  
범위: 기존 R/M 표기는 완료 이력과 원래 요구사항의 출처로 보존한다. 앞으로의
착수·승인·보고·우선순위는 이 문서의 P 배치를 사용한다. `docs/CURRENT.md`가
현재 완료 상태의 원본이고, 이 문서는 그 상태 이후의 남은 실행 순서를 정의한다.

## 공통 운영 원칙

1. 배치는 순서대로 착수한다. P1-2처럼 측정 결과가 다음 우선순위를 정하는
   배치는 구현과 섞지 않는다.
2. 각 배치는 시작 전에 사용자 흐름, 데이터·권한, UAT 데이터, UI 상태, 검증과
   성능을 한 장으로 확정한다. migration은 해당 설계가 승인된 배치에서만 additive
   방식으로 진행한다.
3. 각 배치는 로컬 자동 검증과 Preview UAT를 마친 뒤 결과·남은 레거시 경로·UAT
   실행 ID 정리 결과를 보고하고, 다음 배치로 넘어간다.
4. Production 배포, 실제 고객 발송, 실제 결제·송금, Live 비밀값 변경은 P7의
   별도 출시 승인 전까지 금지한다.

### P2-3 문제은행·답안·채점·과제·아카이브

- 관리자 문제은행 검수 큐와 공개 문제만 노출되는 정책을 구현한다.
- 학생 세션 상단에 **현재 회차의 문제를 푸는 "문제" 화면**을 제공한다. 이 화면은
  현행 "문제 기록"과 다르며, 전체·키워드·문제 유형 필터와 객관식·서술형·풀이형의
  저장·제출을 제공한다. 수업 전에는 세션 상태와 공개 정책에 맞는 준비/대기 안내를
  표시하고, 수업 중·후에는 해당 세션의 문제와 제출 상태를 보여준다.
- 학생의 **"문제 기록"은 아카이브 전용**으로 유지한다. 과목·키워드·유형·채점 상태·
  기간 필터로 제출한 답안·확정 결과·교사 피드백을 모아 보며, 현재 회차에서 문제를
  푸는 진입점처럼 보이게 대체하지 않는다.
- 교사 문제별/일괄 채점·미채점 수·피드백을 연결하고, 정답·점수·피드백은 교사가
  채점을 확정한 뒤에만 학생에게 공개한다.
- 복수 키워드·유형·문항 수 기반의 독립 과제/모의고사 생성, 미리보기, 마감,
  학생 배정, 교사 전용 채점을 구현한다.
- 세 유형의 제출→채점→아카이브 및 과제 생성→배정→채점 골든 패스를 Preview에서
  검증한다.

### P2-4 키워드 자동 구성과 수업 시작 스냅샷

- 학생 운영 커리큘럼의 **각 회차 카드**에서 키워드를 적용·제거한다. 상단의 하나뿐인
  "세션 준비"가 최근 회차만 편집하는 구조를 두지 않는다.
- 회차에 연결된 예정 수업이 있으면 그 카드의 **세션 준비**를 눌러 해당 학생·수업
  일시가 식별된 세션뷰의 준비 모드로 들어간다. 예정 수업이 여러 개면 대상 수업을
  명시적으로 고르고, 아직 예정 수업이 없으면 준비할 세션을 임의 생성하지 않고
  "수업 일정이 정해지면 준비할 수 있습니다"를 표시한다.
- 회차 키워드와 일치하는 공개 교재 섹션·문제를 이 세션뷰 준비 모드에 자동 구성한다.
  교사는 관리자 공개 콘텐츠를 하나씩 고르거나 수정하지 않고 키워드만 적용·제거한다.
- 교사는 해당 세션에만 귀속되는 보강 자료 업로드, 수업 전 필기·화이트보드 초안,
  과제 설정을 준비 모드에서 할 수 있다. 이것들은 관리자 공개 라이브러리를 바꾸지
  않는 세션 전용 자료이며, 학생에게 보이는 시점과 수정 권한은 세션 상태로 제어한다.
- 세션뷰의 교재·문제·필기·과제·기록 영역과 기본 정보 구조는 관리자·교사·학생에
  공통으로 유지한다. 역할마다 별도 화면을 복제하지 않고 동일한 세션뷰를 데이터
  층위와 권한만 달리해 사용한다.
- 수업 시작 시점에 콘텐츠 목록과 교재/문제 내용을 불변 스냅샷으로 고정한다.
  시작 전 세션은 최신 공개본을, 시작 후 세션은 고정본을 읽는다.
- 기존 pin 기반 과거 세션은 삭제하지 않고 읽기 호환을 보존한다.
- 후보 0건 원인 안내, 키워드 변경 즉시 반영, 회차별 세션 준비 진입, 보강 자료·
  필기·과제 사전 설정, 원본 수정 후 과거 수업 재현을 Preview UAT로 검증한다.

## P3 — 수업 공간과 v3 커리큘럼 연속성

### P3-1 교사 공통 운영본

- `teacher_curriculum_profiles` 계열의 v3 교사 공통 운영본을 설계·구현한다.
- 새 학생별 오버레이는 교사 운영본이 있으면 그 기준으로, 없으면 관리자 과목
  기준본으로 시작한다. 학생별 조정은 해당 학생에게만 적용한다.
- 계층은 관리자 과목 기준본 → 교사 과목 운영본 → 학생별 운영 커리큘럼 → 실제
  예정 수업 세션 순서로 분리한다. 회차는 커리큘럼의 학습 단위이고 세션은 특정
  학생·일시의 실제 수업이므로 같은 이름으로 섞지 않는다. 세션에는 기본 회차와
  필요한 보강 회차를 명시적으로 연결해, 일정 변경·보강·재수업에서도 준비한
  자료가 어느 실제 수업에 속하는지 유지한다.
- 관리자 기준본과 교사 운영본에서도 실제 세션뷰와 같은 UI 구조로 자료 구성 결과를
  미리 본다. 단, 관리자는 공개 기준 콘텐츠를 관리하고, 교사는 자기 운영본·학생
  세션의 키워드와 세션 전용 자료를 준비하며, 학생은 배정된 세션 결과를 학습·제출
  권한으로 본다. 같은 UI의 탭과 정보 구조는 유지하되 쓰기 권한과 데이터 원본만
  역할별로 제한한다.
- 레거시 `teacher_curriculum_templates`는 실제 사용 경로가 소진될 때까지 읽기
  호환을 유지하고, 별도 폐기 배치에서 제거한다.

### P3-2 학습 연속성

- 과목별 커리큘럼·진도·주요 마일스톤을 `subject_enrollment` 기준의 버전형
  기록으로 만들고, 교사 변경 뒤에도 읽기 전용 이력을 이어 본다.
- 학생·보호자 지난 수업 기록, 과제 마감/지각/재제출, 리뷰·피드백, 다음 수업
  준비를 연결한다.
- 보호자/학생 마일스톤 보드에는 진행률, 현재 단원, 다음 수업, 예상 종료일,
  수업권과 요청 진입점을 표시한다.

### P3-3 실제 수업 공간 신뢰성

- v3 예약·세션에서 세션뷰로 실제 진입하도록 완성하고, 화이트보드 실시간 반영,
  영구 저장, 재접속 복원, 동시 편집, clear-all 권한·감사, 완료 세션 읽기 전용을
  검증한다.
- 회사 Shared Drive의 수업 폴더·권한·Smart Notes 이동, Drive/Meet 실패 재처리와
  정기 대조를 구현한다.
- iPad/Apple Pencil, 느린 네트워크, 오프라인·재접속, 교사·학생 2인 Preview UAT를
  완료 조건으로 둔다.

## P4 — 상담·결제·정산의 실제 운영 흐름

### P4-1 상담·온보딩 운영 백로그

- 체험수업권 재처리·교사 배정의 확인 절차, 체험 예약 완료 상담의 과거 이력 자동
  이동, 관리자 화면의 v3 배정 학생 표시를 처리한다.
- 직접 온보딩 학생 초대 재발송과, 완료된 수업을 잘못 종결했을 때의 관리자 복구
  흐름을 정리한다.

### P4-2 구매·환불·차지백·정산

- 구매·환불·차지백 대사, 수업권 환불 규칙, 가격·통화 스냅샷, payout item/batch,
  검토·승인·역분개, 교사 명세와 이의를 완성한다.
- 법인 설립 전에는 실제 송금과 `paid` 전이를 차단한다. Mercury/Wise 지급,
  Stripe Live, 세금·수수료·수취계좌·계약·회계/법률 조건은 별도 활성화 Gate를
  통과한 뒤에만 연다.
- 판매 지역별 환불·소비자법 검토는 출시 차단 항목으로 유지한다.

## P5 — 운영·소통 도구

- 이벤트별 알림, 수신 설정, 이메일·인앱 발송 상태, 재시도·중복 방지를 구현한다.
- 보호자–관리자 문의·지원 케이스, 기존 재원생 면담 요청·일정·처리 이력을
  신규 가입 상담과 분리해 운영한다.
- 지각·노쇼·미확정·민원·신규 교사·표본 수업의 QC 큐, 상담·계약·예약·수업권·
  정산 실패 재처리함, 운영 대시보드·전환 지표를 제공한다.

## P6 — 보안·안정성·데이터 수명

- 역할·관계·capability·RLS와 SECURITY DEFINER 함수 권한을 전수 감사한다.
- 중요 변경·조회 감사, 비밀값·외부 서비스 권한, 파일 보안, 오류 추적과 구조화
  로그를 정리한다.
- 테스트/UAT 데이터 격리·정리와 운영 통계 제외를 구조적으로 보장한다.
- 계정 inactive/복귀/병합 UI, 개인정보 보존·내보내기·삭제·비식별화, legal hold,
  정기 스케줄러, DB/Drive/Storage 삭제와 백업·복구 훈련을 완료한다.
- 접근성, 브라우저 호환성, 전반 성능 회귀를 검증한다.

## P7 — 파일럿·출시 게이트

- 상담→체험→계약→결제→수강→예약→수업→리뷰→정산의 종단 E2E를 통과한다.
- 과목 추가·중단·재개, 교사 변경, 환불·취소·노쇼·외부 서비스 장애, 복수 자녀·
  보호자·과목, 역할 우회, iPad 장시간 수업을 검증한다.
- 데이터 이관·롤백 리허설, 운영 매뉴얼·고객지원·장애 대응 훈련, 실제 도메인·
  이메일·법률 문서 점검, 초대 만료 스케줄러와 CI 병렬 안정화를 완료한다.
- Production 반영은 모든 출시 차단 항목과 외부 활성화 Gate를 통과한 뒤 별도 승인으로만
  진행한다.

## 누락 점검 결과

P0~P2만으로는 최근 UAT·콘텐츠 운영 요구는 다루지만, 기존 로드맵의 다음 필수
영역이 빠진다. 위 P3~P7에 각각 편입해 유지한다.

| 기존 요구 영역 | 편입 배치 |
| --- | --- |
| 세션뷰, 화이트보드, Drive/Smart Notes, API 실패 재처리, 기기·재접속 QA | P3-3 |
| 교사 운영본, 진도·마일스톤, 과거 수업·리뷰·보호자 보드 | P3-1~2 |
| 상담 운영 예외, 환불·차지백·교사 정산, 법률 활성화 Gate | P4 |
| 알림, 문의, 면담, QC, 운영 대시보드 | P5 |
| 권한·감사·보존·삭제·복구·테스트 데이터·접근성 | P6 |
| 전 여정 E2E, 이관/롤백, 운영 준비, 실제 외부 활성화 | P7 |

따라서 기능·개발 계획 차원에서 기존 R8~R13의 필수 항목은 P3~P7에 모두
보존됐다. 제품 정책이 아직 확정되지 않은 항목(예: 활성 계정 이메일 정정 절차)은
P6 착수 전 별도 정책 결정이 필요하며, 임의 구현하지 않는다.
