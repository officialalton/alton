# P 실행 로드맵 — 남은 계획 정본

상태: **2026-09-10 기준 향후 실행 정본**  
범위: 기존 R/M 표기는 완료 이력과 원래 요구사항의 출처로 보존한다. 앞으로의
착수·승인·보고·우선순위는 이 문서의 P 배치를 사용한다. `docs/CURRENT.md`가
현재 완료 상태의 원본이고, 이 문서는 그 상태 이후의 남은 실행 순서를 정의한다.

## 공통 운영 원칙

1. 배치는 순서대로 착수한다. P1-2처럼 측정 결과가 다음 우선순위를 정하는
   배치는 구현과 섞지 않는다.
2. 각 배치는 시작 전에 사용자 흐름, 데이터·권한, UAT 데이터, UI 상태, 검증과
   성능을 한 장으로 확정한다. migration은 해당 설계가 승인된 배치에서만 additive
   방식으로 진행한다.
3. 각 배치는 로컬 자동 검증과 Preview UAT를 마친 뒤 결과·남은 레거시 경로·UAT
   실행 ID 정리 결과를 보고하고, 다음 배치로 넘어간다.
4. Production 배포, 실제 고객 발송, 실제 결제·송금, Live 비밀값 변경은 P7의
   별도 출시 승인 전까지 금지한다.

### P0-3 포털 뒤로가기·내부 탭 이력 복원 — **완료(2026-09-10)**

- Preview UAT에서 학생 포털을 사용하다 브라우저 뒤로가기를 누르면 주소는
  `/student`인데 로그인 화면이 렌더링되는 결함이 발견됐다(제품 오너 재확인:
  역할 무관 — 관리자·학생·교사 어디서든 재현).
- 기대 동작: 유효한 로그인 세션에서는 뒤로가기 뒤에도 이전 포털 화면을 복원한다.
  로그아웃·세션 만료·권한 상실일 때만 로그인 화면으로 이동하며, 이때도 보호된
  URL과 로그인 UI가 동시에 남지 않는다.
- **확정된 원인**: history/OAuth/서버 세션/클라이언트 auth 복원/캐시 복원 중
  어느 것도 아니었다. `middleware.ts`의 matcher가 `/login`을 보호 대상에서
  제외하고 있어(포털 경로만 보호), `app/login/page.tsx`에 "이미 유효한
  세션이면 돌려보낸다"는 분기가 아예 없었다 — 로그인 직전 방문한 `/login`
  히스토리로 뒤로가기를 하면 그 페이지가 세션 상태와 무관하게 항상 폼을
  그렸을 뿐이다.
- **수정**: `LoginPage`에서 `resolveAccountDestination()`(로그인 성공 직후
  경로가 이미 쓰는 함수, 새 규칙 신설 없음)을 재사용해 유효 세션이면
  역할·계정 상태에 맞는 목적지로 리다이렉트, 세션 없으면 기존과 동일하게
  폼을 그대로 보여준다. 로그인 상태 재발급이나 redirect 일괄 제거 없음.
- **로컬 검증**: Playwright로 학생·교사·관리자 3역할 모두 수정 전 재현 →
  수정 후 뒤로가기 시 올바른 역할 홈으로 정상 이동(로그인 폼 미노출) 확인,
  로그아웃 상태·로그아웃 직후 `/login` 재방문은 여전히 폼 노출(회귀 없음)도
  확인. 자동 테스트 2건 추가, 전체 스위트 252 files/1761 tests +
  `next build` 통과.
- **남은 완료 조건**: Preview 재배포 후 학생·교사·관리자 각각 로그인 직후,
  탭 이동 뒤, 새로고침 뒤, 뒤로가기/앞으로가기를 실사용자 계정으로 재검증
  (유효 세션·로그아웃·만료 세션 구분).
- **2차 Preview 재현(2026-09-10)**: 관리자 홈에서 "수업권"으로 이동했는데 주소는
  `/admin?tab=home`인 채 수업권 화면이 렌더링됐고, 뒤로가기가 앱의 이전 탭이 아니라
  Google OAuth 계정 선택 이력으로 이동했다. 학생·교사 포털에서도 같은 현상이
  재현돼 역할별 개별 화면 문제가 아니라 공용 포털 내비게이션·history 처리 결함으로
  확정됐다. 이는 `/login` 가드 누락과 다른 결함이다.
- **2차 확정된 원인(로컬 프로덕션 빌드 재현)**: `AdminShell`/`StudentShell`/
  `TeacherShell`/`ParentShell` 넷 모두 `activeTab`을 `initialTab` prop으로
  **마운트 시점에만** 초기화하고, 이후 그 prop이 바뀌어도(뒤로가기/앞으로가기로
  Next가 새 searchParams를 내려줄 때) 다시 반영하지 않았다 — 그래서 주소창은
  바뀌지만 화면은 이전 탭에 멈춘다. 게다가 탭 전환이 전부 `router.replace()`라
  세션 전체가 히스토리 한 칸에 계속 덮어써져, 탭을 몇 번 옮기든 뒤로가기 한
  번이면 포털 진입 이전(로그인/OAuth) 이력으로 바로 빠졌다.
- **2차 수정**: 네 Shell 전부에 `initialTab` 변경 시 `activeTab`을 재동기화하는
  `useEffect` 추가 + 탭 전환의 `replace`를 `push`로 교체(탭마다 되돌아갈
  히스토리 항목 생성). `replace` 전면 교체나 OAuth redirect 제거 없이, 확인된
  두 지점만 최소로 수정.
- **2차 로컬 검증**: 로컬 프로덕션 빌드 + Playwright로 관리자(수업권↔커리큘럼),
  학생(수업↔교재) 뒤로가기/앞으로가기가 매 단계 URL·화면 일치하며 정확히
  직전 탭으로 이동함을 재확인(수정 전엔 앞으로가기 시 URL만 바뀌고 화면은
  멈춰 있던 것도 확인). 회귀 테스트 1건(관리자 대표, `rerender()`로 재현) +
  기존 `ParentShell.test.tsx`의 `replace` 단언 3건을 `push`로 갱신. 전체 스위트
  252 files/1762 tests + `next build` 통과.
- **남은 완료 조건**: Preview 재배포 후 학생·교사·관리자 세 역할 각각 로그인

- **Preview UAT 실패 재현(2026-09-10)**: 최신 Preview에서 관리자 "문의·면담"

## P2 — 키워드 기반 콘텐츠 운영

### P2-1 교재 관리 통합·저장 UX·키워드 분류

- 현행 "교재 문서"와 "교재 라이브러리"를 하나의 교재 관리 흐름으로 통합한다.
  라이브러리는 폴더가 아니라 **과목 템플릿 키워드별 교재 목록**으로 표시하며, 각
  키워드 목록에서 교재를 생성·열람·수정·배포한다.
- 키워드의 생성·이름 변경·삭제는 관리자 과목 템플릿 편집만 허용한다. 교재 문서,
  문제 은행, 세션 준비는 해당 과목에 등록된 기존 키워드를 칩으로 모두 표시하고
  적용·해제만 한다. 검색·자유 입력·새 키워드 생성 UI는 두지 않는다. 서로 다른
  과목의 키워드가 후보에 섞이지 않도록 현행 키워드-과목 연결과 권한 범위를 조사하고,
  조회·저장 규칙을 과목 단위로 강제한다.
- 교재는 정확히 하나의 과목 키워드에 연결한다. 교재의 섹션마다 별도 키워드를
  붙이지 않고 교재 키워드를 상속한다. 문제의 복수 키워드 연결은 유지한다. 단원명은
  교재 제목 또는 내부 구성일 뿐, 새 키워드를 자동 생성하는 기준으로 쓰지 않는다.
- 초안에서도 교재 키워드를 지정할 수 있게 한다. 다만 교사·학생의 회차/세션 자동
  후보에는 공개·배포 교재만 포함하고, 초안은 라이브러리에서 상태를 구분해 표시한다.
- 키워드별 교재에 운영자가 조정하는 정렬 순서를 둔다. 자동 구성과 라이브러리는
  같은 순서를 사용하고, 동순위 교재는 제목의 자연 정렬(1, 2, 3 … A, B, C …)로
  표시한다. 생성 시각을 노출 순서로 사용하지 않는다.
- 초안·배포 교재에 명시적 저장, 저장 중·완료·실패 표시, 미저장 이탈 경고,
  배포본 수정 영향 안내를 제공한다. 과목 템플릿에서 키워드를 저장한 뒤 교재의
  칩 목록과 문제·교사 세션 준비의 해당 과목 후보에 새로고침 없이 즉시 반영되어야
  한다. 저장 중에는 중복 클릭·재요청을 막고, 이미 존재하거나 적용된 키워드는
  재생성 요청이 아니라 사용자 안내로 처리한다. React/DB 등 기술 오류는 사용자
  화면에 노출하지 않는다.
- 기존 교재·섹션 키워드 연결을 위 단일 교재 키워드 모델로 옮길 수 있는지, 기존
  데이터가 복수 키워드/무키워드인 경우의 처리, migration 및 배포본 호환 정책을
  구현 전 조사·승인한다.
- 키워드 생성 직후 교재 선택 목록 반영, 초안 저장, 배포 후 자동 후보 포함, 배포
  취소 후 후보 제외, 정렬 변경 후 회차 자동 구성 순서, 네트워크 실패·새로고침/
  이탈·배포본 수정의 Preview UAT를 포함한다.

### P2-3 문제은행·답안·채점·과제·아카이브

- 관리자 문제은행 검수 큐와 공개 문제만 노출되는 정책을 구현한다.
- 학생 세션 상단에 **현재 회차의 문제를 푸는 "문제" 화면**을 제공한다. 이 화면은
  현행 "문제 기록"과 다르며, 전체·키워드·문제 유형 필터와 객관식·서술형·풀이형의
  저장·제출을 제공한다. 수업 전에는 세션 상태와 공개 정책에 맞는 준비/대기 안내를
  표시하고, 수업 중·후에는 해당 세션의 문제와 제출 상태를 보여준다.
- 학생의 **"문제 기록"은 아카이브 전용**으로 유지한다. 과목·키워드·유형·채점 상태·
  기간 필터로 제출한 답안·확정 결과·교사 피드백을 모아 보며, 현재 회차에서 문제를
  푸는 진입점처럼 보이게 대체하지 않는다.
- 교사 문제별/일괄 채점·미채점 수·피드백을 연결하고, 정답·점수·피드백은 교사가
  채점을 확정한 뒤에만 학생에게 공개한다.
- 복수 키워드·유형·문항 수 기반의 독립 과제/모의고사 생성, 미리보기, 마감,
  학생 배정, 교사 전용 채점을 구현한다.
- 세 유형의 제출→채점→아카이브 및 과제 생성→배정→채점 골든 패스를 Preview에서
  검증한다.

### P2-4 키워드 자동 구성과 수업 시작 스냅샷

- 학생 운영 커리큘럼의 **각 회차 카드**에서 키워드를 적용·제거한다. 상단의 하나뿐인
  "세션 준비"가 최근 회차만 편집하는 구조를 두지 않는다.
- 회차에 연결된 예정 수업이 있으면 그 카드의 **세션 준비**를 눌러 해당 학생·수업
  일시가 식별된 세션뷰의 준비 모드로 들어간다. 예정 수업이 여러 개면 대상 수업을
  명시적으로 고르고, 아직 예정 수업이 없으면 준비할 세션을 임의 생성하지 않고
  "수업 일정이 정해지면 준비할 수 있습니다"를 표시한다.
- 회차 키워드와 일치하는 공개 교재(교재당 하나의 키워드)·문제를 이 세션뷰 준비
  모드에 자동 구성한다. 여러 키워드가 선택되면 P2-1의 키워드별 교재 정렬 순서를
  그대로 적용한다. 교사는 관리자 공개 콘텐츠를 하나씩 고르거나 수정하지 않고
  키워드만 적용·제거한다.
- 교사는 해당 세션에만 귀속되는 보강 자료 업로드, 수업 전 필기·화이트보드 초안,
  과제 설정을 준비 모드에서 할 수 있다. 이것들은 관리자 공개 라이브러리를 바꾸지
  않는 세션 전용 자료이며, 학생에게 보이는 시점과 수정 권한은 세션 상태로 제어한다.
- 세션 준비는 세 층위 모두에 존재한다. 관리자는 **기준 세션 구성**으로 과목 템플릿
  회차의 키워드와 자동 구성 결과를 준비·미리 본다. 교사는 **과목 운영본 세션 구성**으로
  배정 과목의 기본 구성을 자기 운영 방식에 맞게 조정한다. 학생별 커리큘럼에서는
  **학생 수업 세션 준비**로 특수성을 반영해 특정 예정 수업을 준비한다.
- 실제 수업 세션을 열었을 때의 세션뷰(교재·문제·필기·과제·기록)는 교사·학생이
  같은 구조를 공유하고, 관리자는 운영 지원·점검 권한으로 같은 실제 세션을 열 수
  있다. 세 층위의 세션 준비는 익숙한 공통 정보 구조를 쓰되, 대상 데이터와 허용된
  변경 범위가 다르다.
- 수업 시작 시점에 콘텐츠 목록과 교재/문제 내용을 불변 스냅샷으로 고정한다.
  시작 전 세션은 최신 공개본을, 시작 후 세션은 고정본을 읽는다.
- 기존 pin 기반 과거 세션은 삭제하지 않고 읽기 호환을 보존한다.
- 후보 0건 원인 안내, 키워드 변경 즉시 반영, 회차별 세션 준비 진입, 보강 자료·
  필기·과제 사전 설정, 원본 수정 후 과거 수업 재현을 Preview UAT로 검증한다.

## P3 — 수업 공간과 v3 커리큘럼 연속성

### P3-1 교사 공통 운영본

- `teacher_curriculum_profiles` 계열의 v3 교사 공통 운영본을 설계·구현한다.
- 새 학생별 오버레이는 교사 운영본이 있으면 그 기준으로, 없으면 관리자 과목
  기준본으로 시작한다. 학생별 조정은 해당 학생에게만 적용한다.
- 계층은 관리자 과목 기준본 → 교사 과목 운영본 → 학생별 운영 커리큘럼 → 실제
  예정 수업 세션 순서로 분리한다. 회차는 커리큘럼의 학습 단위이고 세션은 특정
  학생·일시의 실제 수업이므로 같은 이름으로 섞지 않는다. 세션에는 기본 회차와
  필요한 보강 회차를 명시적으로 연결해, 일정 변경·보강·재수업에서도 준비한
  자료가 어느 실제 수업에 속하는지 유지한다.
- 관리자는 과목을 개설하고 기준 커리큘럼·공개 교재·문제·키워드를 저작·검수하는
  관리 화면과 기준 세션 구성을 쓴다. 관리자의 기준 세션 구성은 특정 학생·일시를
  만들지 않고, 이후 교사 운영본이 받을 기본 키워드·공개 콘텐츠 조합을 정한다.
- 교사는 자신에게 배정된 과목의 운영본을 관리자 기준본에서 시작해 자기 방식으로
  수정하고, 이를 새 학생별 커리큘럼의 기본 템플릿으로 활용한다. 교사의 과목 운영본
  변경은 다른 교사의 과목이나 관리자 기준본을 바꾸지 않는다.
- 학생별 운영 커리큘럼은 교사 운영본에서 시작하되, 그 학생의 진도·보강·제외·키워드
  조정 등 특수성만 덧붙인다. 여기서 특정 예정 수업에 연결된 회차를 준비하면 실제
  세션뷰 준비 모드로 들어간다. 학생은 배정된 실제 세션만 학습·제출 권한으로 연다.
- 필요할 때 관리자는 실제 세션뷰를 운영 지원·점검 권한으로 열 수 있다. 기준 세션
  구성, 교사 운영본, 학생 실제 세션을 하나의 데이터 행이나 같은 쓰기 권한으로
  합치지 않는다.
- 레거시 `teacher_curriculum_templates`는 실제 사용 경로가 소진될 때까지 읽기
  호환을 유지하고, 별도 폐기 배치에서 제거한다.

### P3-2 학습 연속성

- 과목별 커리큘럼·진도·주요 마일스톤을 `subject_enrollment` 기준의 버전형
  기록으로 만들고, 교사 변경 뒤에도 읽기 전용 이력을 이어 본다.
- 학생·보호자 지난 수업 기록, 과제 마감/지각/재제출, 리뷰·피드백, 다음 수업
  준비를 연결한다.
- 보호자/학생 마일스톤 보드에는 진행률, 현재 단원, 다음 수업, 예상 종료일,
  수업권과 요청 진입점을 표시한다.

### P3-3 실제 수업 공간 신뢰성

- v3 예약·세션에서 세션뷰로 실제 진입하도록 완성하고, 화이트보드 실시간 반영,
  영구 저장, 재접속 복원, 동시 편집, clear-all 권한·감사, 완료 세션 읽기 전용을
  검증한다.
- 회사 Shared Drive의 수업 폴더·권한·Smart Notes 이동, Drive/Meet 실패 재처리와
  정기 대조를 구현한다.
- iPad/Apple Pencil, 느린 네트워크, 오프라인·재접속, 교사·학생 2인 Preview UAT를
  완료 조건으로 둔다.

## P4 — 상담·결제·정산의 실제 운영 흐름

### P4-1 상담·온보딩 운영 백로그

- 체험수업권 재처리·교사 배정의 확인 절차, 체험 예약 완료 상담의 과거 이력 자동
  이동, 관리자 화면의 v3 배정 학생 표시를 처리한다.
- 직접 온보딩 학생 초대 재발송과, 완료된 수업을 잘못 종결했을 때의 관리자 복구
  흐름을 정리한다.

### P4-2 구매·환불·차지백·정산

- 구매·환불·차지백 대사, 수업권 환불 규칙, 가격·통화 스냅샷, payout item/batch,
  검토·승인·역분개, 교사 명세와 이의를 완성한다.
- 법인 설립 전에는 실제 송금과 `paid` 전이를 차단한다. Mercury/Wise 지급,
  Stripe Live, 세금·수수료·수취계좌·계약·회계/법률 조건은 별도 활성화 Gate를
  통과한 뒤에만 연다.
- 판매 지역별 환불·소비자법 검토는 출시 차단 항목으로 유지한다.

## P5 — 운영·소통 도구

- 이벤트별 알림, 수신 설정, 이메일·인앱 발송 상태, 재시도·중복 방지를 구현한다.
- 보호자–관리자 문의·지원 케이스, 기존 재원생 면담 요청·일정·처리 이력을
  신규 가입 상담과 분리해 운영한다.
- 지각·노쇼·미확정·민원·신규 교사·표본 수업의 QC 큐, 상담·계약·예약·수업권·
  정산 실패 재처리함, 운영 대시보드·전환 지표를 제공한다.

## P6 — 보안·안정성·데이터 수명

- 역할·관계·capability·RLS와 SECURITY DEFINER 함수 권한을 전수 감사한다.
- 중요 변경·조회 감사, 비밀값·외부 서비스 권한, 파일 보안, 오류 추적과 구조화
  로그를 정리한다.
- 테스트/UAT 데이터 격리·정리와 운영 통계 제외를 구조적으로 보장한다.
- 계정 inactive/복귀/병합 UI, 개인정보 보존·내보내기·삭제·비식별화, legal hold,
  정기 스케줄러, DB/Drive/Storage 삭제와 백업·복구 훈련을 완료한다.
- 접근성, 브라우저 호환성, 전반 성능 회귀를 검증한다.

## P7 — 파일럿·출시 게이트

- 상담→체험→계약→결제→수강→예약→수업→리뷰→정산의 종단 E2E를 통과한다.
- 과목 추가·중단·재개, 교사 변경, 환불·취소·노쇼·외부 서비스 장애, 복수 자녀·
  보호자·과목, 역할 우회, iPad 장시간 수업을 검증한다.
- 데이터 이관·롤백 리허설, 운영 매뉴얼·고객지원·장애 대응 훈련, 실제 도메인·
  이메일·법률 문서 점검, 초대 만료 스케줄러와 CI 병렬 안정화를 완료한다.
- Production 반영은 모든 출시 차단 항목과 외부 활성화 Gate를 통과한 뒤 별도 승인으로만
  진행한다.

## 누락 점검 결과

P0~P2만으로는 최근 UAT·콘텐츠 운영 요구는 다루지만, 기존 로드맵의 다음 필수
영역이 빠진다. 위 P3~P7에 각각 편입해 유지한다.

| 기존 요구 영역 | 편입 배치 |
| --- | --- |
| 세션뷰, 화이트보드, Drive/Smart Notes, API 실패 재처리, 기기·재접속 QA | P3-3 |
| 교사 운영본, 진도·마일스톤, 과거 수업·리뷰·보호자 보드 | P3-1~2 |
| 상담 운영 예외, 환불·차지백·교사 정산, 법률 활성화 Gate | P4 |
| 알림, 문의, 면담, QC, 운영 대시보드 | P5 |
| 권한·감사·보존·삭제·복구·테스트 데이터·접근성 | P6 |
| 전 여정 E2E, 이관/롤백, 운영 준비, 실제 외부 활성화 | P7 |

따라서 기능·개발 계획 차원에서 기존 R8~R13의 필수 항목은 P3~P7에 모두
보존됐다. 제품 정책이 아직 확정되지 않은 항목(예: 활성 계정 이메일 정정 절차)은
P6 착수 전 별도 정책 결정이 필요하며, 임의 구현하지 않는다.
