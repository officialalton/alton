# 과목별 전체 교재 보기 — 1장 정리 (2026-09-15)

착수 전 CLAUDE.md "새 기능 착수 전 1장 정리" 규칙에 따라 작성. 승인 대기 없이 바로 구현한다(제품 오너 지시).

## 1. 탐색 흐름 — 과목 → 단원 → 키워드 → 자료

- 학생·교사·보호자 각 포털의 "교재" 진입점에서 **수강/담당 과목 선택** → 그 과목의 **단원(`subject_template_units.position` 순서)** 목록 → 각 단원에 붙은 **키워드(`subject_template_unit_keywords`)** → 그 키워드를 대표 키워드로 갖는 **공개된 자료(`curriculum_docs.status='published'`)** 목록.
- 키워드가 여러 단원에 붙어 있으면(N:M) 그 키워드의 자료는 각 단원 아래에 그대로 반복해서 보인다 — 별도 "대표 단원" 개념을 만들지 않는다(기존 관리자 화면과 같은 규칙).
- 대표 키워드가 없는 자료, 또는 어떤 단원에도 붙지 않은 키워드의 자료는 **"단원 미지정"** 묶음에 모은다(관리자 화면과 동일 원칙).
- 자료 하나를 열면 그 자료 내부(HTML은 목차/섹션, PDF는 페이지)를 읽고, 같은 단원·키워드 순서를 기준으로 **이전/다음 자료**로 넘어갈 수 있다.
- 예약 없이 언제든 접근 가능(수업 세션과 무관한 열람 레이어 — 기존 원칙 유지).

## 2. 권한 — 관리자만 편집, 나머지는 읽기 전용

- **편집**: 관리자만. 기존 `app/admin/CurriculumDocsTab.tsx` · `CurriculumDocEditor.tsx` · Drive 동기화 경로를 그대로 쓴다 — 이 기능은 새 편집 경로를 만들지 않는다.
- **읽기**: 교사·학생·보호자는 전부 읽기 전용. 노출 범위는 각자 실제 수강/담당 관계로 좁힌다:
  - 학생: `enrollments`(student_id, active) + `subject_enrollments`(child_id, active) 로 이미 걸려 있는 과목만(기존 `loadMaterialsLibrary` 로직 재사용).
  - 교사: `enrollments`(teacher_id, active) + `teacher_assignments` + `teacher_curriculum_templates` 로 이미 걸려 있는 과목만(기존 `loadTeacherMaterialsLibrary` 로직 재사용).
  - 보호자: 지금까지 이 화면이 없었다 — **가족의 활성 자녀들의 `subject_enrollments`를 합쳐서** 접근 가능한 과목 집합을 새로 계산한다(자녀별로 구분해서 보여준다).
- 셋 다 `status='published'`인 자료만 본다. 미공개 초안·보관된 자료·보관된 과목은 노출하지 않는다.
- 정답·해설·학생 제출 이력의 노출 규칙은 손대지 않는다(문제가 포함된 자료는 기존 `redactProblem` 그대로 통과).

## 3. PDF·영상·교재 버전 표시와 기존 수업 고정본의 관계

- 이 화면(과목 전체 보기)은 **자료의 "지금 공개본"**(가장 최근 `curriculum_doc_versions`)만 보여준다 — `loadLibraryDoc`이 이미 이렇게 동작한다(주석: "과목 전체 보기는 지금 공개본을 쓴다").
- **이미 진행됐거나 진행 중인 수업**이 그 시점에 고정해 둔 버전(`sessions.material_version_id`, 시작/완료 후 재배정 불가 — `20261219000000_r8_material_version_lock.sql`)은 이 화면과 완전히 분리된 별개 경로다 — 절대 건드리지 않는다. 자료가 재공개되어 새 버전이 생겨도 과거 수업 기록은 그 당시 고정 버전을 계속 보여준다(기존 동작 유지, 회귀 테스트로 확인).
- 자료가 재공개되면 이 화면은 새 공개본으로 즉시 바뀐다(캐시 없음, 매 요청 최신 조회).

## 4. 학생 사전 열람 범위와 정답·해설 비노출 원칙

- 학생·보호자가 이 화면에서 문제가 포함된 자료를 열어도, **아직 풀지 않은 문제의 정답·해설·교사용 teaching_tip은 응답에 포함하지 않는다** — 기존 `/materials/[id]` 의 `redactProblem(problem, isTeacherLike || done || submittedResponse)` 규칙을 그대로 쓴다. 즉:
  - 교사·관리자: 항상 전체(정답 포함) 열람.
  - 학생·보호자: 그 학생이 이미 풀었거나(done) 제출 이력이 있는 문제만 정답 노출, 그 외는 가려짐.
- 보호자가 자녀의 자료를 열 때도 "그 자녀 기준"으로 done/submittedResponse를 판정한다(보호자 본인 이력이 아니다) — 자녀를 먼저 선택하게 한다.

## 5. 검증 계획

**UAT (모바일·데스크톱)**
- 학생/교사/보호자 각 역할로 로그인 → 교재 탭 진입 → 과목 선택 → 단원 펼치기 → 키워드 아래 자료 목록 확인 → 자료 열기 → 이전/다음 이동 → 다시 들어왔을 때 읽던 위치로 복귀.
- 모바일 폭(375px)에서 단원/키워드 접기·펼치기, 이전/다음 버튼 터치 크기, PDF 뷰어 가로 스크롤 없는지.
- 데스크톱(1280px)에서 목차 사이드바(또는 상단) 레이아웃 확인.

**권한**
- 미수강 과목의 자료가 목록에 안 보이는지(학생/교사/보호자 각각).
- 보관된 과목·미공개 자료·보관된 자료가 안 보이는지.
- 학생이 안 푼 문제의 정답·해설이 API 응답에 아예 없는지(교사용 필드 없음, 네트워크 탭 확인 수준까지).
- 보호자가 자녀를 바꾸면 done 판정 기준도 그 자녀로 바뀌는지.

**순서**
- 단원 표시 순서가 `subject_template_units.position`과 일치하는지.
- 키워드가 여러 단원에 걸쳐 있을 때 각 단원 아래 자료가 중복해서 올바르게 보이는지.
- "단원 미지정" 묶음이 맨 끝(또는 명시된 위치)에 오는지.

**빈 상태**
- 과목은 있지만 공개된 자료가 하나도 없을 때.
- 수강/담당 과목 자체가 없을 때(보호자는 활성 자녀가 없을 때 포함).

**버전 회귀**
- 자료를 재공개(새 버전)한 뒤: (a) 과목 전체 보기는 새 버전을 보여준다. (b) 이미 끝난 과거 수업 기록은 여전히 그 당시 고정 버전을 보여준다(둘 다 같은 테스트 안에서 대조 확인).
- 읽던 위치를 저장한 뒤 자료가 재공개되어 섹션 구성이 바뀌면, 존재하지 않는 위치를 가리키지 않고 안전하게 처음으로 돌아간다(깨진 위치로 크래시하지 않음).
