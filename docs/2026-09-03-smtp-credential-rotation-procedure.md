# SMTP 자격증명(official@alton.education 앱 비밀번호) 무중단 회전 절차 (문서화만, 2026-09-03)

- **상태: 문서화만 완료 — 실제 회전은 아직 수행하지 않았다.** 이 절차는 제품 오너의 별도
  명시적 승인이 있을 때만 실행한다(Vercel Production 환경변수 변경이 포함되므로).
- 배경: M1 Sandbox 실측 검증(2026-09-03) 중 제품 오너가 `official@alton.education`의
  Gmail SMTP 앱 비밀번호(Vercel Production `SMTP_PASS`와 동일 값)를 로컬 `.env.local`에
  일시적으로 넣어 실제 이메일 2통(`matchbox512@snu.ac.kr`)을 발송한 뒤 검증 직후 제거했다고
  보고했다. 이 세션에서 저장소 전체·`.env.local` 현재 상태를 재확인한 결과 평문 잔존은
  없었다(`docs/CURRENT.md`의 M1 절 참고). 강제 회전이 필요하다는 확정적 증거는 없지만,
  Production과 동일한 값을 로컬 환경에 임시로라도 옮긴 적이 있다는 사실 자체가 예방적
  회전을 고려할 이유는 된다 — 최종 판단은 제품 오너 몫이며, 이 문서는 그 판단이 내려졌을
  때 바로 실행할 수 있는 무중단 절차만 준비해둔다.

## 절차(무중단 — 서비스가 이메일을 못 보내는 공백을 만들지 않는다)

1. **새 앱 비밀번호 생성**: `official@alton.education` Google 계정의 보안 설정에서 새
   앱 비밀번호를 발급한다(기존 비밀번호는 아직 폐기하지 않는다 — 이 시점에는 신규·기존
   둘 다 유효해야 한다).
2. **Vercel Production 값 교체**: Vercel 프로젝트의 Production 환경변수 `SMTP_PASS`
   (및 필요 시 `SMTP_USER`/`SMTP_HOST`/`SMTP_PORT`)를 새 값으로 갱신한다. Vercel은
   환경변수 변경 후 재배포가 필요하다 — 다음 배포(또는 수동 재배포)부터 새 값이 적용된다.
3. **통제된 테스트**: 재배포 직후, 실제 고객에게 영향이 없는 통제된 테스트 계정(이번
   세션에서 쓴 `matchbox512@snu.ac.kr` 같은 팀 내부 주소)으로 실제 이메일 발송 흐름 1건을
   실행해 새 자격증명이 정상 동작하는지 확인한다 — 예: 상담 신청 거절 알림, Calendar 초대
   실패 fallback 등 기존에 이미 있는 발송 경로 중 하나를 이용(새로 테스트 전용 코드를
   추가하지 않는다).
4. **기존 비밀번호 폐기**: 3번 테스트가 성공적으로 확인된 뒤에만 Google 계정에서 기존
   (교체 전) 앱 비밀번호를 폐기한다. 이 순서를 지키면 3번 테스트가 실패해도 기존
   비밀번호가 아직 살아있어 즉시 롤백(Vercel 값을 원래대로 되돌리기)할 수 있다.
5. **완료 기록**: 회전 완료 시각·수행자·확인한 테스트 결과를 `docs/CURRENT.md`에 한 줄로
   기록한다(이 문서 자체는 절차 정의로 유지, 실행 기록은 CURRENT.md 쪽에 남긴다).

## 이번 세션에서 하지 않은 것(명시)

- 새 앱 비밀번호를 생성하지 않았다.
- Vercel Production 환경변수를 변경하지 않았다.
- 기존 앱 비밀번호를 폐기하지 않았다.
- 위 4단계 중 어느 것도 실행하지 않았다 — 이 문서는 절차 정의만 담고 있다.
