# AP English Language — MC 구조 감사와 공식 5묶음 재편 (2026-10-15)

범위: 게시된 EL1·EL2(v3)의 MC 구조를 공식 CED 구조와 비교하고, 5묶음 구조로 재편한 신규 구성(DB 적재·원격 쓰기 없음)을 만든다. 근거 문서: `englang-facts.md`, `englang-groundwork.md`, `englang-review-report.md`.

- **CED·AP Central 어디에도 지문 길이와 글쓰기 지문이 학생 초안인지 여부는 적혀 있지 않다.** 시험 페이지는 글쓰기 묶음을 "read like a writer 하며 stimulus 텍스트의 수정을 고려하는 문항"이라고만 적는다. 이 둘은 확인 불가이므로 공식 수치로 주장하지 않는다(아래 위험 참조).
- 따라서 이전 문서(`englang-facts.md` §2-2, 그라운드워크 §1)의 "읽기 약 5지문·쓰기 약 5지문, 지문당 4–6문항, 총 9–10지문"은 틀린 내부 가정이었다. 공식은 **5묶음 전체**이고 지문당 문항 수가 훨씬 많다.

## 4. 생성·검증 결과

동결 구성(`config/ap-frozen/englang-long-a.v1.json`, `englang-long-b.v1.json`: `--freeze` → 커밋 → `--check-only` → 유료 실행, 배치 모드), 파이프라인에 **확장 모드**(`cfg.ext`, 새 문항만 생성·기존 문항은 이전 검증 결과 재사용)를 추가했다. 모든 지문은 기존 ALTON 원본이며 새 문항은 지문과 블루프린트만 보고 쓰였다. 결정적 게이트(`englang-gates`)·풀이 3·적대 검토·심판 단계는 기존 파이프라인과 같다.

|---|---|
| 새 문항 요청 | 74(읽기 40 + 글쓰기 34; 이 중 글쓰기 10은 쓰지 않은 여분 묶음 lw32·lw22 몫) |
| 결정적 게이트 통과 | 69 (93%) |

| 시험 구성을 맞추려 남긴 새 문항 | 42 (`el-long-trim.ts` 정수계획: 공식 묶음 크기·8범주 범위·키 신뢰도 선호) |

**선지 길이 단서(키가 가장 긴 선지, 규칙 ≤ ~20%)**: 새 문항 42개 중 31개(74%, 글자 기준)가 키가 엄격히 가장 길었다(생성기가 습관대로 만듦). 키·줄기·순서를 그대로 두고 오답 선지를 키 길이의 85–115%로 다듬는 후처리(`el-long-rewrite.ts`, Opus)로 31 → 8개로 줄였다. 확장 8묶음 80문항 전체로는 글자 기준 18/80 = **22.5%**, 단어 기준 11/80 = **13.8%**(기반 el-rv 38문항은 지난 검수에서 이미 약 20%였다). 같은 후처리가 읽기 해설의 숨은 문장 번호(읽기 지문은 ¶ 번호만 보임)를 새 읽기 문항 13건에서 문단 번호·인용으로 바꿨다. 후처리가 새 결정적 위반을 만든 문항은 0건(되돌림 0).

**독립 맹검 패널(키 비공개, 지문+문항만)**: 확장 8묶음 80문항을 Opus 5.5·Sonnet 5.5·Fable 5.1이 각각 풀었다(Fable은 2차 패널).
- 키 일치 **240/240**, 모두 `clear`, 제2 방어 가능 선지 **0**, 문항 수준 결함 지적 10건(대부분 사소한 문구).
- 지문 수준 지적 11건: ① lr23·lw04·lw06의 "ALTON original passage" 표지(공개 라벨 정책이라 의도된 것), ② lr11 q10 줄기가 성별이 정해지지 않은 필자를 "she"로 지칭(Opus·Fable 모두 지적) → 줄기를 "they"로 정정, ③ lr11 기반 지문 4문단의 "Architecture is credited; so is the building"이 어색(Opus; 기반 지문의 문장이라 이번에는 수정하지 않음), ④ lr11이 2021년 실제 번역가 표기 캠페인 논의와 주제가 가깝다는 Fable의 가벼운 지적(이름·사건은 전부 가공), ⑤ lw06 문장 6·11의 "behind/near" 미세 불일치, lw02 문장 13·15의 요약 불일치(Opus, 사소), ⑥ lw04 지문의 의도된 오류 확인.
- 사람 검수는 여전히 필요하다(위험 참조).

**화면 검증**: 렌더 검사 `render-check` 재생성(8건 text_only), 격리 Supabase 스택(`ALTON_ellong`, 중지·`supabase/config.toml` 원복)에서 Playwright로 후보 8개 × 2 뷰포트 160건 점검: 체크 800 통과·320 해당 없음·실패 0. 증거 `data/ap/screen-evidence/evidence-el-long.json`, 스크린샷 `docs/ap/screen-evidence/el-long/`. 새 배치 `el-long`을 `lib/ap-admin/batches.ts`에 등록(보조 적재, 증거 파일 연결).

## 6. 새 버전 교체 계획과 앱 지원 조사

대상(SELECT 전용으로 확인): EL1 v3 `2dd750e9-676a-405f-b640-b02dfc85b862`, EL2 v3 `7c6df623-4e2c-496c-a710-757c2e22f432`(둘 다 published, 초안 없음; MC 45·FRQ 3; 묶음 수 12·10).

**순수 교체(swap) 계획으로는 표현할 수 없었다.** 기존 `resolveSwaps`는 슬롯이 공유 자료 묶음에 속하면 그 묶음 전체로 펼쳐 같은 크기의 새 묶음 하나로만 바꾸게 한다(크기가 다른 묶음 2~3개를 12문항 묶음 하나로 바꿀 수 없음). DB RPC `mock_exam_create_new_version`은 슬롯 단위로 문제를 바꾸고 마지막에 묶음 무결성(후보의 모든 하위 문항이 함께, `item_index` 순서가 슬롯 순서와 같음)만 검사하므로 DB는 이 재편을 허용한다.

**조치(최소 코드 변경)**: 교체 계획 항목에 선택 필드 `addIndex`를 도입했다("재편 항목"). `addIndex`가 있으면 슬롯(section+position)과 새 후보 안의 순서를 직접 지정하고 기존 묶음 펼치기를 건너뛴다(`lib/ap-admin/new-version.ts` `resolveSwaps`/`parseSwapPlan`, 테스트 `new-version-set.test.ts`). 조립 규칙 검사(`checkNewVersionComposition`: 기존 묶음은 통째로 교체, 새 묶음은 완전한 크기, 중복·문항군 상한)와 DB RPC는 그대로 최종 방어선이다. 기존 계획 파일 동작은 변하지 않는다.

**제약(설계에 반영)**: RPC는 이미 시험(원본 세트)에 있는 문제를 교체 후보로 쓸 수 없으므로 짧은 묶음을 다른 슬롯으로 옮길 수 없다. 그래서 짧은 묶음을 v3의 마지막 슬롯에 그대로 두는 배정으로 설계했다(EL1 w22 = 42–45, EL2 w32 = 40–45).

생성 파일(`scripts/ap-generation/el-long-swap-plans.ts`, 테스트 `el-long-structure.test.ts`가 v3 슬롯에 대해 `resolveSwaps` 문제 0·짧은 묶음 슬롯 미변경을 확인):
- `data/ap/stock/el1-long-v4-swap-plan.json`: 41 슬롯(1–41) 재편 → lr11(1–13), lr23(14–25), lw05(26–34), lw06(35–41); 42–45 w22 그대로; FRQ 그대로.
- `data/ap/stock/el2-long-v4-swap-plan.json`: 39 슬롯(1–39) 재편 → lr01(1–12), lr08(13–23), lw04(24–32), lw02(33–39); 40–45 w32 그대로; FRQ 그대로. (EL2 v3 읽기는 25칸이라 25번 칸이 글쓰기로 바뀐다.)

대안 경로(채택 안 함): 배정으로 새 초안 세트를 "AP English Language — Practice Exam 1 (long-passage)"로 저장하면 별도 `set_group_id`의 새 시험이 되어 v3의 버전 이력과 응시 기록이 이어지지 않는다(앱에는 구조가 다른 초안을 기존 시험의 다음 버전으로 올리는 기능이 없다). 새 버전 흐름이 이미 있고 이번 변경으로 표현 가능해졌으므로 권장하지 않는다.

## 8. 위험·한계

1. **지문 길이 미확인**: 읽기 614–698단어(6문단)·글쓰기 185–329단어는 기존 ALTON 지문 길이이며 공식 길이는 CED에 없다. 공식 읽기 지문이 이보다 훨씬 길다면(공개 샘플 확인 없이 단정 불가) 새 장문 지문 생성이 추가로 필요할 수 있다. 글쓰기 초안(185–329단어)에 7–9문항을 걸면 문항 밀도가 높다(초안 하나에 수정 포인트를 더 찾아 물음).
2. 모델 합의는 사람 검수가 아니다(같은 계열 3종의 공유 사각지대). 새 문항 42개의 사람 검토, 기반 지문 lr11(실제 캠페인과 가까운 주제·어색한 문장 1건)은 우선 대상이다. 잔여 키 오류율 추정은 기존 0–2% 가정을 유지하되 확장 문항 몫은 표본이 작아(42) 따로 확정하지 않는다.
3. 키 길이 단서 22.5%(글자)는 20% 목표보다 약간 높다(단어 기준은 13.8%). 권장 수준에서 더 줄이려면 후처리를 한 번 더 돌리면 된다.
4. 같은 지문에 문항을 더했으므로 확장 묶음의 기존 문항은 구 시험(v3)의 문항과 내용이 같다(별도 문제 행, 새 후보). v4 게시 뒤 v3는 보관된다.
5. 화면 증거는 Playwright 자동 점검(표시·입력·노출·잘림)이다. 문장 자연스러움·의미는 사람 확인이 필요하다.
