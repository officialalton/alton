# AP Statistics MC 난이도 치우침 진단·수정·S3 준비 (2026-10-12)

범위: 무료 작업만(유료 호출·Anthropic 키·DB·push·삭제 없음). ST1 의 MC 는 exam_prep 가 목표(≥ 약 35%)에 못 미친다 — 이번 작업은 (1) 라벨이 정해지는 방식을 진단하고 원칙적 수정을 넣고, (2) 다단계·결합 개념 MC 원형 10개를 만들고, (3) S3 유료 런을 오너 예산 확인 뒤 바로 돌릴 수 있게 동결 구성 템플릿과 단계별 명세를 준비한다.

## 1. 진단: difficulty_provisional 은 누가 정하는가

- **규칙이 아니라 LLM 판정기 하나가 정한다.** `pipeline2.ts` 의 난이도 단계(`difficultyStage`)가 Sonnet 에게 `submit_difficulty`(label·reasoning_steps·representation_changes·부하)를 받는다. 입력은 문항 겉모습(stem·보기·자료)과 일반 맥락뿐이다. 설계도의 사고 단계·오답별 오개념·원형이 아는 구조 사실은 보여 주지 않는다. 시스템 프롬프트(`DIFF_SYS`)에는 "어떤 구조가 exam_prep 인가" 기준이 없다.
- **`calibrateMc` 는 난이도를 정하지 않는다.** 이름과 달리 "참조 프로필 게이트"일 뿐이다(예상 시간 45–130초, 본문 ≤100단어, 서로 다른 오개념 ≥3). 난이도에 영향을 주는 입력이 아니고, Statistics 용 임계값도 없다.
- **설계도에 신호가 없다.** `student_thinking` 은 검증기가 "2개 이상"만 요구해서 S1~S2-b 의 통과 MC 51문항이 전부 정확히 2개다(실측). 단계 수가 모두 같아 원형 쪽에서 구별 신호가 나올 수 없다.
- **판정이 흔들린다(S1~S2-b 통과 MC 51문항의 판정기 출력).** 판정기가 스스로 센 `reasoning_steps` 와 라벨이 일치하지 않는다: 3단계라고 센 항목 중 basic 8 · exam_prep 5, 2단계에서도 exam_prep 1, 4단계는 exam_prep 2. 같은 "3단계"가 절반 넘게 basic 이다.
- **st_conditions_prop 이 basic 이 된 이유(판정기 사유 원문 요지):** "Single-concept item: verify random, 10%, large counts for a one-proportion z-test … It has no representation changes, minimal computation, and a short stem." 즉 한 절차 안의 세 조건 확인을 "한 개념"으로 보고, 짧은 stem·가벼운 계산·그림 없음을 쉬움의 증거로 읽었다. 코드가 만든 의도(p0 로 큰 수 조건 확인 + 10% 조건 경계값 + 세 조건을 따로 평가하는 오답)는 판정기에게 보이지 않았다.
- **집계 정정:** S2-b 보고의 "ST1 MC exam_prep 10/42 = 24%"는 공유 세트를 행 단위 라벨(가장 어려운 문항)로 세어 3문항을 모두 exam_prep 로 센 값이다. 문항 단위로 세면 **8/42 = 19%**(단독 7 + 회귀 세트 1). 목표 35% 와의 격차는 보고보다 크다. 배정기(`stats-assign.ts`)는 난이도를 목적에 넣은 적이 없어 비율은 재고 구성이 우연히 정한 값이다.

## 2. 수정: 신호를 선언하고 검증하고 판정기에게 사실로 준다 (라벨 부풀리기 없음)

라벨을 올리는 규칙이 아니라 "판정기가 못 보던 구조 사실을 보여 주고, 실제로 어려운 구조를 가진 원형을 추가한다"는 방식이다. 임계값을 낮추거나 라벨을 덮어쓰는 코드는 없다.

1. **원형이 구조 신호를 선언한다** (`pack.difficulty_signals`, `lib/ap-generation/stats-difficulty.ts`): 순서가 있는 필수 단계 2~4개(각 문장), 결합 개념 1~3개, 서로 관련지어 읽을 자료 수 1~3, 계산량(none/light), **오답별 "처음 틀어지는 단계"**.
2. **결정적 게이트가 선언을 검증한다** (`calibrateMc` 에 연결, Statistics 이고 선언이 있을 때만): 단계 문장 중복·짧음, 오답 지도가 실제 오답 보기와 일치, 단계 번호 범위, 설계도 단계 수 ≤ 선언 단계 수, 그리고 핵심인 **"단계가 정말 필수인가"** — 마지막 단계를 뺀 모든 단계(최소 steps−1 개)에서 틀어지는 오답이 있어야 한다. 단계를 부풀려 신호만 높이면 게이트가 막는다(테스트로 고정).
3. **판정기에게 사실로 준다** (`difficultyContext`, `pipeline2.ts` 의 난이도 요청 본문 뒤에 덧붙임): 단계 수, 결합 개념 수와 이름, 자료 수, "첫 단계는 통과하고 뒤에서 틀어지는 오답 수", 계산량, 그리고 기준 문장. 단계 문구와 정답은 주지 않는다. 선언이 없거나 다른 과목이면 빈 문자열이라 기존 요청과 바이트 단위로 같다. `DIFF_SYS`·도구 스키마는 바꾸지 않아 난이도 프롬프트 해시도 그대로다(생성기 해시는 파일이 바뀌어 재동결이 필요).
4. **구조 기준(문서화된 근거)**: `exam_prep` = 필수 단계 ≥ 3 **그리고** 결합 개념 ≥ 2 또는 자료 ≥ 2 (앞 단계 결과를 다음 단계로 가져가야 함); 그 밖은 `basic_learning`. MC 에서 `advanced_supplement` 는 구조로 주지 않는다. 근거: (a) CED 의 MC 는 보통 한 개념의 한두 단계 판단이고, 3단계 + 결합은 모의고사 대비 수준의 하한이다; (b) 실측에서 판정기 자신이 3단계 이상으로 센 항목만 exam_prep 가 나왔다(2단계 이하 exam_prep 는 1건); (c) 불공정 난이도(긴 산술·모호·긴 읽기)는 계산량 선언과 기존 게이트(반올림 명시·보기 간격·stem 100단어)가 막는다. 이 기준은 판정 라벨을 **바꾸지 않는다** — 감사 지표로만 쓴다.
5. **감사 지표**(`stats-s2a-finalize.ts` 요약의 `difficultyAudit`): 선언 문항 수, 구조 기준 exam_prep 수, 판정기 exam_prep 수, 일치/판정기 낮음/판정기 높음, 불일치 항목의 키·사유. 판정기가 구조 기준보다 낮게 주면 라벨은 그대로 두고 표시한다(조정 세션이 사유를 읽고 원형 설계 문제인지 판정 문제인지 판단). 판정기가 기준보다 높게 주는 경우도 똑같이 표시한다(양방향 감사).
6. **배정기 보조**: `stats-assign.ts --prefer-exam-prep`(기본 꺼짐, 기존 배정·고정 테스트 불변): 가상 1000·목표 이탈 1 보다 항상 작은 가중(−0.01/exam_prep 문항)으로 동점일 때만 어려운 문항을 선호한다. 출력에 `MC exam_prep n/42` 를 표시한다. 풀 로더는 세트를 문항별 판정(`difficulty` 배열)으로 센다.
7. **투영 도구** `scripts/ap-generation/stats-s3-projection.ts`: 통과 가정을 얹은 무료 투영(아래 §6).

## 4. 한계와 정직한 주의

- 구조 기준(단계 ≥3 + 결합 ≥2)은 **설계 규칙**이지 이번 데이터에 맞춰 적합한 값이 아니다. 판정기가 이 사실을 받고도 basic 을 주면 라벨은 그대로 두고 감사 표시만 남는다 — 비율은 판정기 결과로 정해진다. 판정기가 기준을 따르는 쪽으로 쏠릴 수 있다는 점(사실을 줬을 때의 유도 효과)은 `difficultyAudit` 의 불일치 사유와 풀이자(Opus) 정답률·검토 5기준 통과로 교차 확인한다. 유료 런에서 판정기-기준 일치율과 실제 풀이 정답률(어려운 문항이 정말 더 많이 틀리는가는 학생 데이터가 있어야 확인)을 함께 본다.
- 설계 결함 가능성: 원형 4·5·7·9 는 그림·표 의존이라 화면 증거(390×844·1280×800)를 아직 만들지 않았다(무료 범위에서 격리 스택을 띄우지 않았다). 렌더는 그림 게이트 통과까지만 확인.
- 원형 8 의 "조건 미충족" 변형은 넣지 않았다(오답이 모두 첫 단계에서만 틀어져 단계 필수성 게이트를 만족하지 못함) — 큰 수 조건은 거짓 근거("p 가 0.5 가 아니다")를 오답으로 둔다.
- 새 원형 10개는 모두 단독 MC 다(공유 세트 아님). ST2·ST3 를 채우려면 이 원형의 다른 시드와 기존 원형의 새 시드가 필요하다(§6).
- 기존(S1~S2-b) 원형에는 신호 선언이 없다. 소급 선언은 하지 않았다(재고가 이미 동결·화면 증거까지 끝났고, 선언은 새 런에서만 의미 있다).

## 5. 동결 구성 템플릿 (동결하지 않음)

`config/ap-frozen/stats-s3-a.template.json`(S3-a), `config/ap-frozen/stats-s3-b.template.json`(S3-b). `expected` 해시는 `UNFROZEN` 이라 이대로는 `--check-only` 가 일부러 실패한다. `generatorFiles` 에 `stats-difficulty.ts` 를 추가했고 문장 다듬기 단계는 S2 와 같이 `skipStages:["gen"]`, 수선 없음.
사용 절차(오너 예산 확인 뒤): 파일을 `*.v1.json` 으로 복사 → `npx tsx scripts/ap-generation/run-frozen.ts --config <복사본> --freeze` → 커밋 → `--check-only`(유료 호출 없음, 불일치면 중단) → 실행. `hardStopCumulativeUsd` 40.7 은 현재 누적 $39.5118 + 1.2 가정이므로 동결 직전 원장으로 다시 계산한다. `--freeze`/`--check-only` 는 추적 파일 `data/ap/sample-2027/_frozen_check/*` 를 다시 쓰므로 커밋 대상에서 의도적으로 구분한다.

단가 근거: S2-b 단독 12 후보 $0.4462($0.0372/후보: 풀이 $0.0059·검토 $0.0246(재요청 포함)·난이도 $0.0067)에 다단계 문항의 긴 검토 출력과 신호 문구(난이도 요청 +약 150토큰)를 반영해 $0.040 로 잡았다. 마무리: `stats-s2a-finalize.ts --runs stats-s3-a[,stats-s3-b] --batch stats-s3` → 화면 증거(격리 스택) → 재고 반영 → `stats-assign.ts --sets ST1 --prefer-exam-prep`. 첫 통과율 가정 80%(S2-b 단독 92%·S2-a 73%).

**투영** (`stats-s3-projection.ts`, 전부 exam_prep 판정 가정, 재고 = 현재 커밋분):
| 통과한 새 원형 | ST1 MC exam_prep (현재 8/42 = 19%) |
|---|---|
| 8/10 | **16/42 = 38%** |
| 10/10 | 18/42 = 43% |
가정이 틀려 판정기가 일부를 basic 으로 주면 그만큼 내려간다(예: 새 통과 8개 중 5개만 exam_prep → 13/42 = 31%). **ST1 한 세트는 S3-a 만으로 충분**하고 목표 35% 를 넘을 수 있다. ST2(두 번째 풀 세트)는 새 원형 두 번째 시드 + 기존 원형의 새 시드가 함께 필요하다(투영: S3 만 쓰면 ST1+ST2 동시 배정 시 가상 문항 다수) — S2-b 보고의 풀 세트 1개 ≈ $2.5 가 별도로 든다. 예산 순서: S3-a($0.88 상한) → 결과 확인 → 오너 결정 → S3-b → ST2 재고.
