## 35~41. 게시 후 전문가 검수와 launch 조건 (2026-10-08 오너 확정, 마지막 개정 반영)
- 35. 전문가 승인은 **게시 전 게이트가 아니다**. 게시된 문제를 모의고사 검수 방식·기존 오류 신고 흐름(마이그레이션 20261940000000/360)으로 사후 검수한다. 사후 검수·신고 절차는 유지.
- 36. 검수 환경 게시 조건 `review_env_ready` = 최신 자동 게이트 통과 AND 필수 그래프/자료 렌더링 검증 AND 학생 화면 검증.
- 37. `expert_status`: unreviewed / in_review / approved / issues_reported(정보용). 별도 `release_tier`: candidate / review_env / launch.
- 38. **launch 조건** = 최신 자동 게이트 통과 + 렌더·학생 화면 검증 + 미해결 launch 차단 결함 0건(오답 키·복수 정답·조건 누락·그림/표 오류, `ap_launch_blockers` + 현재 버전의 wrong_key/flawed_problem 미해결 신고). **전문가 승인과 검수 기간 만료는 조건에서 제외**하고 `review_period_ends_at` 결정은 폐기한다. "신고 0건"을 검수 완료 증거로 쓰지 않으며 검수 기한·알림 기능은 만들지 않는다. (마이그레이션 395)
- 39. 흐름: 후보 → 문제(검수 환경) → 신고 → 새 버전으로 수정 → launch. 상세 `publication-flow.md`. 구(767행) 적재는 삭제하지 않고 `is_current=false`(마이그레이션 394, 현재 로컬만 적용).
- 40. Bio 파트별 스킬·토픽·루브릭 지원, 공식 점수 근거 `bio-frq-rules.md`. **Bio 점수 비례 시간 추정은 내부 참고일 뿐 공식 문항별 시간이 아니며 그것만으로 반려하지 않는다**(실제 과제량·풀이 검토로 판단). Bio 생성은 AB 결과 보고 후 별도 오너 결정.
- 41. 비교 실험은 AB에서 구방식 대조군 포함 2-arm, 1.3배는 개선 목표이지 소표본 단독 합격선이 아니다(`experiment-plan.md`). 기존 후보 재검증은 소표본 LLM 검증 → 전수 비용 추정 → 오너 결정 순서(확정 재고 승격은 최신 게이트 통과 후에만).

## 42~46. 용도 분리·변환·응시 (2026-10-09 오너 확정/구현)
- 42. **AP 문항 용도는 `mock_exam` 또는 `lesson` 하나뿐**: 변환 때 고정, 변경·공유·예외 없음. 세트 조립은 모의고사 용도만, 선생님 선택기는 수업 용도만, 무료 회원은 수업 용도를 볼 수 없다. 용도별 재고·부족분은 별도 집계(`ap_stock_by_purpose_v`). 구현·테스트 `publication-flow.md` §5.
- 43. 모의고사 층 = SAT 모의고사와 같은 수준의 독립 시험(무료·과외 공통, `access_tier` free/tutoring). 기존 엔진·재응시 모델 재사용, SAT 적응형/4모듈 불변.
- 44. FRQ: 타이핑 입력 + 자동 저장, 제출 뒤 참고 답안(공식 채점 아님). AI 피드백·점수 환산은 범위 밖(미구현). 학부모 AP 결과 화면은 후속(목록에서 AP 제외).
- 45. 그림은 stimulus.data(자유 형식)를 정규화해 표준 파이프라인(`ap_graph`·`ap_table`·`ap_table_set`·`ap_diagram`)으로 그린다. **생성기 결함 3건 발견**: (a) 문자열 stimulus 93건이 닫는 `}` 누락(보충해 읽음), (b) 아키타입 MC 선택지 184건이 `{text, why, value}` 객체, (c) 데이터 모순(교점 y 부호, 표 본문 없음)은 게이트가 잡는다 — 새 생성분은 엄격 스키마로 내야 한다.
- 46. 로컬 데모 세트는 공식 문항 수보다 작은 구조(라벨 검증은 복사된 레이아웃 기준)이므로 출시용이 아니다. 실제 세트는 `assemble-ap-set.ts` 가 공식 구조를 다 채울 때만 만든다.

## 44~50. 2026-10-09 결정 요청·확정 (개정)

- 49. 결정 필요: 근사 중복(duplicate_gate_near_duplicate)을 재고 정책대로 반려가 아닌 문항군 변형으로 일괄 처리할지(현재 run2 일부가 반려로 남음, 6건).
