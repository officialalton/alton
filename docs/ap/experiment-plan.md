# 비교 실험·기존 후보 재검증 개정안(2026-10-08 개정 2) — 유료 실행 없음, 오너 확정 전 대기

AB 비교 실험과 기존 후보 재검증을 합쳐 **총 상한 $30, 중단선 $27**. 아래 예산표를 오너가 확정하기 전에는 어떤 단계도 실행하지 않는다. Bio 는 이 계획에 포함하지 않으며 AB 결과 보고 후 별도 오너 결정이다.

## 1. 대조군(구방식 arm) 필수 — 기존 결과는 조건 불충족
기존 구방식 결과(런1, AB 포함)는 비교 조건을 충족하지 않는다: 목표 셀 목록이 다르고, 검토·난이도 프롬프트가 이후 수정되어 현재 동결 검토기와 다르며, 새 시드·수선 1회 제한·동일 후보 수로 실행된 적이 없다. 따라서 **대조군을 새로 돌리고 그 비용을 예산에 포함**한다.

## 2. 실험 설계(AB, 두 arm 동일 조건)
- 목표 셀: AB MC 60칸(단원·스킬 층화 추출) + FRQ 8템플릿. **두 arm 이 같은 셀 목록**을 쓴다.
- 칸당 최초 후보 1개, 수선 한도 1회, **동결 검토기**(검토·난이도 프롬프트 해시를 `run_manifest.json` 에 기록하고 두 arm 모두 같은 해시). 시드는 새 값(`--seed0 1000` 이상, 기존 튜닝 시드와 겹치지 않음). 구방식 arm 은 시드 개념이 없으므로 같은 시드 번호를 변형 ID 로 쓰고 새로 생성한다. 기존 후보를 재사용하지 않는다.
- 정답만 맞히는 방식은 품질로 인정하지 않는다: 기준 문항·키·해설(루브릭)을 직접 작성한 후보만 평가 대상.
- 동결 후에는 프롬프트·게이트를 바꾸지 않는다(이번 개정에서 Bio 시간 규칙을 바꿨으므로 **동결은 예산 확정 후 실험 시작 시점에 한다**).

## 3. 보고 지표(소표본이므로 한 숫자로 합격 판정하지 않음)
두 arm 에 대해 함께 보고하고 `armReport()`(lib/ap-generation/pipeline-policy.ts)로 계산한다.
1. 최초 후보 수(분모. 수선·재검토 호출은 절대 섞지 않음) 2. 최초 통과 수 3. 수선 후 통과 수 4. **사용 가능 고유 문항당 총비용**(생성+수선+재검토 호출 전부 포함, 미귀속 비용 포함) 5. **스킬별·구조별 분해표** 6. 문항군 다양성 7. 개발 시간(커밋 구간, 근사).
- **1.3배 첫 통과율은 개선 목표이지 소표본 단독 합격/불합격 기준이 아니다.** 비용·스킬별 결과·결함 탐지와 함께 판단한다.
- 정직한 한계: 개발·튜닝 비용은 API 비용에 안 들어간다. 코드 우선 arm 은 같은 원형 코드로 튜닝된 상태라 그 점을 보고서에 명시.

## 4. 주입 결함 탐지(문항별 보고)
- 준비된 시험(`lib/ap-generation/defect-injection.ts`, `scripts/ap-generation/inject-defects.ts --per-item`)이 정상 문항에 launch 차단 결함 4종을 주입하고 **문항×결함별** 탐지 여부·걸린 게이트를 기록한다. 전체 탐지율 90% 같은 합산 기준으로 통과 판정하지 않는다.
- 요구: **launch 차단 결함(오답 키·복수 정답·조건 누락·그림/표 오류)은 준비된 시험에서 전부 탐지되어야 한다**. 동시에 정상 문항 오탐(false reject)률을 측정한다.
- 무료 계층 현재 결과(auto_passed MC 118개): 오탐 0/118. 오답 키 118/118, 복수 정답 118/118 탐지. **조건 누락 0/95, 그림·표 오류 0/18 — 코드 게이트로는 탐지 못 함** → 독립 풀이·동결 검토기(유료 계층)가 잡아야 하며, 이 두 종류가 전부 탐지되지 않으면 no-go. 유료 측정 대상: 조건 누락 주입 20 + 그림·표 오류 18 + 정상 30(오탐률), 약 $2.
- 오답 키·복수 정답은 해설 키 일치 규칙(`explanation_key_mismatch`) 등 결정적 게이트가 이미 전부 잡는다.

## 5. 기존 후보(needs_revalidation 220) 재검증 — 소표본 먼저
- **무료 선별 결과(163 → 규칙 오탐 교정 후 185)**: 구조 실패 중 오탐으로 확인한 규칙을 교정했다 — `part_X_calculation_without_answer_row` 키워드 목록 확장(루브릭 문구 "Computes … with units" 등), `stem_does_not_reference_table` 에 "shown/results/above/trial …" 허용, 이스케이프된 `\$` 통화 기호 균형 오류, 구형식 문자열 stimulus 어댑터. 그 결과 163 → **185개 생존**(MC 167, FRQ 18). 163 생존분은 모두 그대로 유지되고(탈락 22 → 생존), 남은 35개 탈락의 주 사유는 `narrated_error_in_option`(15), `reference_time_out_of_range`(12), 표 미참조(8), 점수 불일치 등이며 삭제하지 않고 이력 보존. 확정 재고로의 승격은 최신 게이트 통과 후에만.
- 이전 반려 사유(`rejectionReason`)는 220개 모두 비어 있다(런1 통과분이라 반려 이력이 없음). 따라서 "이전 반려 사유" 층은 **무료 검사에서 탈락한 35개의 규칙 사유 코드**로 대신한다.
- 소표본(층화): 과목×구조(standalone / frq_multipart / shared_stimulus_set)×무료 결과(생존 / 규칙 탈락 사유별).

| 층 | 모집단 | 표본 |
|---|---|---|
| 생존: Bio MC / Bio FRQ | 51 / 3 | 8 / 3 |
| 생존: AB MC / AB FRQ | 47 / 9 | 8 / 4 |
| 생존: Micro MC / Micro FRQ | 69 / 6 | 10 / 4 |
| 규칙 탈락(사유별 비례): AB MC / AB FRQ | 23 / 1 | 6 / 1 |
| 규칙 탈락: Micro FRQ / Bio MC / Micro MC | 6 / 3 / 2 | 2 / 1 / 1 |
| 합계 | 220 | **48 (MC 34, FRQ 14)** |
- 비용(실측 단가, 동기): MC 항목당 약 $0.030 → $1.0, FRQ 약 $0.075 → $1.05, 합 **약 $2.1**.
- 표본 결과(층별 통과율)로 전수 재검증 비용을 추정: `전수 비용 = Σ 층 모집단 × 항목당 비용`, `사용 가능 문항당 비용 = 전수 비용 / (모집단 × 층 통과율)`. 이 값을 신규 생성 비용(MC $0.134, FRQ $0.399 / 사용 가능 고유 1건)과 비교한 뒤 **오너가 전수 실행 여부를 결정**한다. 전수 상한 추정 약 $6.3(동기).
