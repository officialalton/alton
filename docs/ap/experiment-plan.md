# 비교 실험 개정안(단계별 예산) — 실행하지 않음

기존 제안의 $30 일괄 실험은 **실행하지 않는다**. 총 상한 $30, **중단선 $27**(누적이 $27에 닿으면 즉시 중단·보고). 각 단계는 앞 단계 결과 보고 후 오너 승인으로만 시작한다. Bio는 AB 결과 보고 전에는 자동 실행하지 않는다.

## 공통 통제
- 같은 목표 셀·같은 후보 수·같은 수선 한도(1회)·**동결된 검토기**(검토·난이도 프롬프트 해시를 `run_manifest.json`에 기록, 실험 중 변경 금지).
- **새 시드**(`--seed0 1000` 이상, 기존에 튜닝한 시드와 겹치지 않음). 분모 = 첫 후보 수(수선은 별도 후보로 세지 않음).
- 정답만 맞히는 방식은 품질로 인정하지 않는다: 모든 후보는 기준 문항·키·해설·루브릭이 있어야 하며, 풀이 일치는 보조 증거.
- 별도 보고 지표: ① 첫 통과율 ② 수선 후 통과율 ③ 고유 문항 수 ④ 문항군(item family) 다양성 ⑤ 총 호출 비용 ⑥ 개발 시간(커밋 시각 구간은 근사치).

## 1단계 go/no-go 기준(사전 고정)
- go: 첫 통과율 ≥ 구방식 1.3배 **그리고** 사용 가능 고유 1건당 비용 ≤ 구방식(MC $0.134 / FRQ $0.399) **그리고** 주입 결함 탐지율 ≥ 90%(알려진 오류 문항을 섞어 동결 검토기·게이트가 잡는지) **그리고** 문항군 다양성 감소 없음.
- no-go: 위 중 하나라도 미달 → 3단계 자동 진행 안 함, 원인 보고.
- 정직한 한계: 개발 시간·튜닝 비용은 API 비용에 안 들어간다. 새 시드라도 같은 원형 코드이므로 "튜닝 후 성능"이 올라간 값임을 보고서에 명시.
