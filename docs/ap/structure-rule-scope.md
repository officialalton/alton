# 구조 중복 규칙의 정확한 적용 범위 (2026-10-22, 오너 확정)

이 문서가 구조 중복 검사 문구의 기준이다. 다른 문서가 "시험당·세트 쌍당 하나", "구조 가족 전면 금지" 같은 요약을 쓰면 이 문서가 우선한다.

## 적용하는 것 (두 가지)
1. **세트 내 상한**: 한 세트(풀 모의고사 한 벌) 안에서는 구조 기준으로 같은 문항군(구조 가족)을 **1개로 제한**한다. 기존에 검증기가 적용하던 세트 내 문항군 상한이며 새 제한이 아니다.
2. **풀 모의고사 간 금지**: 서로 다른 풀 모의고사 사이에서 **동일 문항**과 **구조 동일 문항**을 쓰지 않는다. 구조 동일 = 숫자·이름·문장만 바꿨고 자료 구조와 풀이 단계가 같은 문항(독립 신규 문항으로 세지 않는다).

## 적용하지 않는 것
- 평가 유형·스킬·코드 생성 원형(archetype)을 세트 간에 **전면 금지하지 않는다.** 같은 개념이나 같은 유형(completion 등)을 다시 평가할 수 있다.
- 판정 기준은 **자료·조건·질문·필수 추론 단계에 실질적인 차이가 있는가**다. 문항군 ID, 원형 이름, 주제, 문자열 유사도는 단독으로 탈락 근거가 아니다(후보를 고르는 용도로만 쓴다).
- 새 제한을 추가하거나 기준을 완화하지 않는다.

## "한 구조 가족을 시험당·세트 쌍당 하나" 표현의 정정
이 표현은 위 두 항목을 압축하다 부정확해졌다. 정확한 문장은 다음과 같다.
- 세트 안: 같은 구조 문항군은 1개까지.
- 서로 다른 풀 모의고사 사이: 같은 구조(구조 동일)로 판정된 문항은 쓰지 않는다. (같은 유형이라도 자료·조건·질문·추론이 실질적으로 다르면 허용.)
- 숫자만 다른 변형 묶음(예: m01-k0/k1/k2)은 하나의 구조 문항군으로 센다.

## "파일 수준 조립 가능" ≠ "공개 준비 완료"
- **계산상 조립 가능(파일 수준)**: 배정기가 가상 칸 0·검증기 위반 0을 낸 상태. 아직 공개 근거가 아니다.
- **공개 준비 완료**는 아래를 **모두** 통과한 뒤에만 쓴다.
  1. 최신 품질 게이트(후보의 최신 검수·반려 상태)
  2. 코드 의미·추론 구조 중복 검사(문항 내용을 읽고 판정)
  3. 최신 DB 기준 편성·중복·해시·렌더·화면 증거·변환 검증
- **코드 토큰 마스킹 검사**와 군 ID 기반 자동 비교는 후보를 좁히는 보조 수단이며, 단독으로 최종 판정하지 않는다. 경계 사례는 내용을 읽고 판정하며 판단이 남는 건만 대표 문항·비교 근거와 함께 오너에게 올린다.

## 공개 전 필수 게이트: 엄격한 구조 쌍둥이 점검 (2026-10-22 추가)
공개 전에 아래를 **모두** 수행하고 결과(상위 쌍과 읽고 내린 판정)를 보고에 적는다. 공개 뒤 재점검에서 CH4·CS4·CS5·PS3·PS4에 쌍둥이가 발견돼, 토큰 겹침(Jaccard) 단독 점검은 부족하다는 것이 확인됐다(`docs/ap/post-publish-twin-audit-2026-10-22.md`).
1. 비교 대상은 **DB의 현재 공개 세트 전부**(방금 공개한 세트 포함)와, 같은 배정에 들어가는 다른 새 세트다. 배정기의 정적 차단 목록(`blocked-db-*.json`)은 최신 공개 세트를 반영하지 않을 수 있으므로 공개한 세트의 키를 먼저 추가한다. 복구 목록(`recoverable`)에 있는 후보가 이미 다른 새 세트에 쓰였는지 키 단위로 확인한다.
2. **문장 순서 유사도(difflib 등)**: 질문 문장을 숫자·LaTeX 기호를 가린 뒤 비교한다. 숫자와 단위 표기만 다른 변형은 토큰 겹침으로는 낮게 나온다.
3. **코드 문항**: 코드 원문(`stimulus.description`)을 그대로 쓴다. JSON 직렬화 문자열을 쓰면 `\n` 이스케이프가 토큰을 오염시켜 유사도가 실제보다 낮게 나온다. 문자열·문자 리터럴·숫자를 가리고 식별자를 하나로 합친 뒤 4-gram 겹침을 본다. 단 "missing code" 틀만 같은 문항은 값이 높게 나오는 거짓 양성이므로 읽고 판정한다.
4. **상위 쌍은 반드시 읽는다**(0.55 이상 전부, 같은 템플릿 문구 포함). 자료·조건·질문·필수 추론 단계 중 하나라도 실질적으로 다르면 독립, 숫자·이름·상수·표현만 다르면 쌍둥이다. 판단이 갈리면 경계 목록에 올리고 독립으로 세지 않는다.
5. FRQ·세트형은 시나리오 id가 아니라 내용(지문·요구 과제·단계)을 읽고 비교한다. 같은 메서드명·시그니처·조건이 한 부분이라도 겹치면 그 부분을 기록하고 보수적으로 독립으로 세지 않는다.
이 게이트를 통과하기 전에는 "공개 준비 완료"라고 쓰지 않는다.
