# AP 문항 생산·검수 구조 — 지출 분해와 비교 실험 제안 (설계만, 대량 생성 없음)

## 1. 신규 지출 $21.75 분해 (Calc AB run2a→b→최종, BC bc_a→bc_b→최종; ledger·호출 결과 파일 기준)
방법: 호출(생성 문장·풀이·검토·난이도·표본)을 **슬롯(원형 + 시드 = pack_id)** 단위로 모아, 최종 런 상태로 분류했다. 호출 결과 파일이 지워진 반복(수선으로 팩을 재생성한 칸)의 비용 $0.58은 ledger 합계와의 차이로 따로 표기(미귀속).
> 주의: 반복 중 게이트·프롬프트·원형이 계속 바뀌었으므로 "첫 통과"는 **동결된 버전의 first-pass가 아니다**. 동결 버전 기준 first-pass는 아직 측정된 적 없다(아래 실험이 처음 측정).

### 선택(reserve)과 사용 가능한 고유 문항
- 최종 통과 중 샘플 선택 vs 미선택(legacy reserve): MC 선택 46 / reserve 76(그중 AB 정확 중복 4 포함), FRQ 선택 6 / reserve 9. **reserve는 낭비가 아니라 사용 가능한 재고**(최신 게이트 통과).
- 사용 가능한 고유 문항(최신 게이트 통과, 완전 중복 제외, 숫자 변형은 별도 표기): **MC 118, FRQ 15** (AB 79·11, BC 39·4).

→ **API 비용만 보면 신규 MC가 구 방식보다 싸지 않다**($0.134 vs $0.108). 이점은 (1) 정답·수치가 코드로 확정되어 키 오류 반려가 사라진 것, (2) 템플릿이 안정되면 재생산 비용이 낮아지는 것(재현 $0.06), (3) 통과 항목의 품질 신뢰. 단 코드 템플릿 개발(엔지니어링)은 API 비용에 포함되지 않았다.

## 2. 생산·검수 구조 원칙(제안)
1. **보관**: 품질 통과 고유 문항은 세트 선택과 무관하게 전부 재고로 유지. 숫자만 다른 변형은 별도 집계(문항군), 완전 중복만 제외.
2. **칸당 후보 1개 먼저**, 실패했거나 부족한 칸에만 추가 후보. (대량 병렬 생성 금지)
3. **코드 검사 → LLM 검토** 순서: 수치·키·보기·자료를 코드로 먼저 검증하고 **코드 통과 후보만** LLM 검토로 보낸다.
4. **생성 계산과 독립된 검증 경로**: 검증기는 생성기 모듈과 코드를 공유하지 않는다. 입력은 **공개된 문항(지문·자료·보기)뿐**(생성 시 `facts` 비공개), 구현은 다른 라이브러리·방법(예: 생성=sympy 기호, 검증=mpmath 고정밀·구간 열거·부분합; FRQ 루브릭 수치는 별도 풀이 스크립트). 검증기와 생성기가 불일치하면 반려. 현재는 생성기 내부 assert + 후단 Opus 풀이로 부분 독립만 확보했다.
5. **수선 규칙**: 결함 부분만 수정(예: 한 오답의 `why`, 한 파트의 루브릭 행)하고 관련 문항(같은 템플릿·같은 시드 계열)만 재검증. **기본 재시도 1회**. 같은 템플릿이 첫 4후보 중 2개 이상 같은 사유로 실패하면 **생성 중단 → 템플릿 수정**.
6. **버전 동결·보고**: 런마다 `run_manifest.json`(생성기 커밋, 게이트 버전, 검토 프롬프트 해시, 모델 ID)을 남기고, **새 후보의 first-pass율**(동결 버전)과 수선 후 통과율을 분리 보고. 누적 재평가 수율은 보고하지 않는다.
7. **비용 지표**: 사용 가능한 고유 문항당 총비용 = (생성 + 검토 + 수선 호출) / 사용 가능 고유 문항, **MC·FRQ 따로**, 구·신 방법 비교.
8. **검토기 오류 관리**: 검토기 반려 중 코드·독립 풀이 근거가 없는 의견은 '의견만'으로 분류하고 표본으로 오탐률을 측정(Bio FRQ 분석 참고: `bio-frq-bottleneck.md`).

## 3. 비교 실험 제안(아직 실행하지 않음)
**목적**: 동결된 구 방식 vs 신 방식의 first-pass율·결함 유형·사용 가능 고유 문항당 비용을 같은 칸에서 처음으로 공정하게 비교.
**비용 상한**: **$30**(승인 잔액 약 $30). 예상 $17~20, 상한 $27 도달 시 자동 중단·보고.

| 항목 | 설계 |
|---|---|
| 칸 | Calc AB MC 24칸(단원 1~8 층화, 계산기 필수 6) + FRQ 템플릿 4 + Bio 짧은 탐구 FRQ 1(신규 코드 템플릿). **이전에 쓴 시드·원형과 겹치지 않는 새 시드**. |
| 팔 A(구) | 런1 파이프라인 동결(커밋 해시 고정): LLM이 문항·키·표·루브릭 전부 생성. 칸당 후보 2~3개씩 MC 60 + FRQ 12. |
| 팔 B(신 v3) | 코드 우선 + **독립 검증기** + 코드 통과만 LLM 검토 + 수선 1회 + 칸당 후보 1개로 시작, 실패 칸에만 추가(상한 동일 후보 수). MC 60 + FRQ 12. |
| 공통 판정 | 두 팔 모두 **같은 동결 검토기**(v2 검토 프롬프트·Opus 독립 풀이·결정적 게이트)로 최종 판정 — 생성 방식 비교가 목적이므로 검토 변수를 고정. |
