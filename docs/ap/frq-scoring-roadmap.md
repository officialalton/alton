# AP FRQ 채점 없는 과목 — 구현 로드맵 (2026-10-21, 제안)

범위: 공개 세트가 있는 18과목 중 FRQ 채점이 **없는** 13과목(영어·문학·미국사·세계사는 기존 AI 채점, 유럽사는 별도 지시로 진행 중이라 제외). 요청서의 "12과목"과 한 과목 차이가 나는 이유는 CS A·Psychology 를 모두 포함해 13개로 세었기 때문이다 — 오너 기준 목록이 다르면 알려 달라. 이 문서는 조사·제안만 한다(구현·유료 호출·DB 쓰기 없음).

## 1. 원칙

- "전체 FRQ 채점"이라는 표시는 **그 응시의 모든 FRQ 파트가 자동 평가 가능한 유형이고 실제로 채점됐을 때만** 쓴다. 자동 평가 불가 유형(예: 손글씨 풀이 이미지, 그래프 그리기)이 한 파트라도 있으면 "Partially scored: <유형> parts are not scored"로 표시하고 합산 점수·등급은 내지 않는다(현재 `result-score.ts` 는 이미 채점 불가 문항이 있으면 합산을 막는다).
- 최종 답 또는 코드 실행 성공만으로 부분 점수를 판단하지 않는다. 부분 점수는 항상 공식 루브릭 요소(채점 요소)별 근거로 매기고, 근거(요소별 충족 여부와 인용)를 학생에게 보인다.
- 결정적 검증(수치·수식·단위·테스트 실행)은 "최종 답 요소"만 판정한다. 풀이 과정·설명 요소는 루브릭 근거 채점(LLM)으로 분리한다.
- 모든 새 채점 경로는 기존 에세이 파이프라인(대기열·상한·예산·재시도·주입 방어·`mock_exam_essay_scores` 행 모델)을 재사용하고, 켜기 전 자체 샘플 검증(개발/최종 평가 분리, 파일럿 계획 A단계)과 오너 승인을 거친다.

## 2. 과목·답안 유형별 현황표

현재 입력 방식은 `lib/ap-exam/frq-delivery.ts`(paper = 타이핑 또는 손글씨 SVG 선택, digital = 타이핑)와 문항 파트 `mode`(DB `problem_versions.statements`, 공개 세트 전수 집계)에서 확인했다. 루브릭 열의 "참고 답안+요소 점수"는 문항 해설에 `- N pt:` 요소 목록이 있고 합이 문항 만점과 일치함을 확인한 경우(CS A 12문항 확인; 다른 과목은 요소 목록 형식을 과목별로 추가 확인 필요). 점수 비중은 해당 과목 파트 점수 기준 %.

| 과목 | 입력 | 파트 유형(점수 비중) | 루브릭 | 지금 채점 가능한 범위 | 부족한 기능 |
|---|---|---|---|---|---|
| Calculus AB | 종이 과목: 타이핑 또는 손글씨 | 수치·수식 66% / 설명 34% | 참고 답안+요소 점수(형식 확인 필요) | 없음 | 수식 동치 검사(결정적), 한계·미적분 풀이 요소의 근거 채점, 손글씨 이미지는 읽을 수 없음 → 타이핑 답만 대상 |
| Calculus BC | 동일 | 64% / 36% | 동일 | 없음 | AB 와 같음 + 급수·매개변수 수식 동치 |
| Precalculus | 종이(타이핑/손글씨) | 수치·수식 88% / 설명 13% | 요소 점수(FRQ 6점 분석 채점) | 없음 | 수식 동치·함수 모형 검증이 대부분이라 결정적 검증의 효과가 가장 큼 |
| Statistics | 디지털(타이핑) | 계산 35% / 설명·해석 65% | 요소 점수(문항당 10점) | 없음 | 가설·조건 확인·결론 문장의 근거 채점, 수치 허용오차 |
| Biology | 종이 | 설명 66% / 계산 19% / 그래프·도식 15% | 요소 점수 | 없음 | 설명 근거 채점, 그래프 그리기(학생 입력 방식 없음) |
| Chemistry | 종이 | 수치·결정 67% / 설명·정당화·예측 31% / 그림 1% | 요소 점수 | 없음 | 단위·유효숫자 포함 결정적 검증, 부분 점수 요소 분리 |
| Physics 1 | 종이 | 계산 18% / 설명 34% / 그래프·다이어그램 31% / 유도 18% | 요소 점수 | 없음 | 유도(수식 단계) 채점, 그래프·다이어그램 평가(입력·시각 평가 모두 없음) |
| Physics C: Mechanics | 종이 | 21% / 31% / 25% / 유도 23% | 요소 점수 | 없음 | Physics 1 과 같음 + 미적분 수식 동치 |
| Physics C: E&M | 종이 | 20% / 33% / 25% / 23% | 요소 점수 | 없음 | 동일 |
| Microeconomics | 종이 | 계산·식별 40% / 설명 28% / 그래프 그리기 32% | 요소 점수(장문 10·단문 5·5) | 없음 | 그래프 입력(축·곡선·표시 점)과 시각 평가 |
| Macroeconomics | 종이 | 30% / 33% / 37% | 동일 | 없음 | 동일 |
| Psychology | 디지털(타이핑) | 설명 64% / 식별 36% | 요소 점수(7점×2: AAQ·EBQ) | 없음 | 에세이형 루브릭 근거 채점(기존 파이프라인 재사용 가능), 인용 근거 검증 |
| Computer Science A | 디지털(코드 입력) | 코드 100% | 요소 점수 `- N pt:` 합계=만점(세트 1·2 7/7/5/6 일치) | 없음 | 실행 검사 하네스(안전한 샌드박스에서 학생 메서드·클래스를 JUnit 유사 케이스로 실행), 요소별 근거 채점 |

자동 평가 불가 유형: **손글씨 이미지 답안**(현재 이미지로 저장되며 문자 인식·시각 평가 없음), **그래프·도식 그리기**(Bio·Physics·Micro·Macro: 학생 입력 도구 자체가 없다). 이들이 있는 과목은 해당 파트가 채점될 때까지 "부분 채점"이다.

## 3. 유형별 구현 설계

1. **수치·수식·단위(결정적 검증)**: 문항마다 정답 요소를 구조화(값, 허용오차, 단위, 유효숫자 규칙, 허용 표현 형식, 흔한 변환). 수식은 서버에서 심볼릭 동치 검사(표현 파싱·샘플 대입). 부분 점수는 요소 단위: 올바른 식 설정 / 대입 / 계산 / 단위를 각각 루브릭 요소에 연결하고, 최종 값이 맞더라도 풀이 요소가 비어 있으면 그 요소는 근거 채점이 판단한다. 최종 값만 맞은 경우 전 요소 만점으로 처리하지 않는다. 오답 후속 값에 대한 "오류 이월(carry-forward)" 요소는 루브릭에 명시된 경우에만 적용.
2. **풀이·설명(근거 기반 채점)**: 기존 `essay-grading` 구조 재사용 — 루브릭 요소별 0/1(또는 점수) + 요소별 근거 인용, 보수적 채점, 두 번 채점 후 낮은 값, 학생 글은 데이터로만 취급(주입 방어). 문항별 채점 노트(요소·허용 답)를 입력으로 준다. 새 루브릭 id 를 과목군별로 추가(`stats-v1`, `psych-v1`, `science-v1` …).
3. **그래프·도식**: 단계 1 = 학생 입력 도구(좌표축·곡선·점·라벨을 구조화 데이터로 저장하는 그리기 도구; 현재 손글씨 SVG 는 의미 정보 없음). 단계 2 = 구조화 데이터 기반 결정적 평가(곡선 이동 방향, 교점 좌표 허용 범위, 라벨 존재) + 도식 요소는 사람 검수 병행. 이미지 AI 평가는 오차 근거가 없어 별도 검증 전 사용하지 않는다.
4. **CS A 코드**: 샌드박스(네트워크·파일 차단, 시간·메모리 제한)에서 학생 코드를 컴파일·실행해 케이스별 통과 여부를 얻되, 점수는 루브릭 요소별로 매긴다 — 통과 케이스는 해당 기능 요소의 증거일 뿐이며, 컴파일 실패여도 요소별 부분 점수는 근거 채점이 읽기로 판단한다. 요소 `- N pt:` 합계 검사 테스트 포함.
5. **공통**: 채점 결과는 요소별 점수·근거·검증 유형(결정적/근거 채점/미지원)을 저장 → 결과 화면의 "채점 근거"가 된다. 미지원 파트는 상태 `not_scored` 로 남기고 0점으로 처리하지 않는다.

## 4. 우선 과목·비용·단계 제안

수요 데이터(읽기 전용, 비아카이브·아카이브 세트 포함 모든 AP 응시): 총 79건. 테스트 계정 외 실사용 응시는 과목당 0~2건뿐이고 실사용 학생은 과목당 최대 1명이다(Calc AB 21건 중 실사용 2, Statistics 6건 중 2, World History 4건 중 2, 그 밖은 0~1). **이 규모로는 수요로 우선순위를 가를 수 없다.** 따라서 구현 준비도(결정적 검증 비중, 기존 파이프라인 재사용, 입력 도구 유무)로 정하고, 실사용이 늘면 재평가한다.

| 단계 | 과목 | 이유 | 부분 채점 범위 | 예상 비용(개발 외 API) |
|---|---|---|---|---|
| S1 | Psychology | 설명 64% — 기존 근거 채점 파이프라인을 그대로 재사용, 입력 도구 추가 불필요, 디지털 타이핑 | 전체(자동 평가 불가 유형 없음) | 루브릭·보정 약 $5~8(30샘플×2회 기준, 에세이당 ≈$0.05 외삽) |
| S1 | Statistics | 디지털 타이핑, 계산+설명 모두 결정적+근거 채점으로 분리 가능 | 전체 | 약 $6~10 |
| S2 | Precalculus, Calculus AB/BC | 수식 동치 검사가 핵심(결정적). 손글씨 제출은 제외 → 타이핑 답만 점수, 손글씨 응시는 "not scored" | 타이핑 응시만 전체 | 수식 검사 개발 비용이 큼(API 비용은 설명 요소만 ≈ $5/과목) |
| S2 | Chemistry | 수치·단위 67% 결정적, 설명 31% 근거 채점, 그림 1% 예외 | 그림 파트 제외 → 부분 | 약 $6 |
| S3 | CS A | 샌드박스 하네스 신규 개발 필요(보안 검토). **배점 정정 선행**(세트 3) | 전체(코드) | 하네스 개발, API 약 $4 |
| S4 | Micro, Macro | 그래프 그리기 30~37% — 그리기 도구 선행 | 도구 전까지 부분 | 도구 개발 + 약 $6 |
| S4 | Biology, Physics 1, Physics C ×2 | 그래프·도식 15~31%, 유도 18~23%, 손글씨 | 도구 전까지 부분 | 가장 큼 |

원칙: 각 단계는 (1) 자체 샘플로 개발/최종 평가 분리 검증 (2) 오너 승인 (3) 켠 뒤 실제 답안 점검의 순서이며, 한 번에 전체를 구현하지 않는다. 비용 수치는 에세이 실측 단가에서의 외삽이며 단계 착수 시 단계별 상한·최소 범위를 먼저 제출한다. 개발 인력 비용은 포함하지 않았다.

## 5. 오너 결정 필요

1. S1(Psychology·Statistics) 착수 승인과 단계별 상한.
2. 손글씨만 제출된 FRQ 를 "not scored"로 남기는 방침(OCR·이미지 평가는 별도 검증 전까지 미사용) 확인.
3. 그래프 그리기 입력 도구를 만들 시점(Micro·Macro·Bio·Physics 의 선행조건).
4. 13과목 vs 12과목 대상 목록 확인.
