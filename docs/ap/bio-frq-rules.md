# Biology FRQ 규칙: 파트별 스킬·토픽·루브릭, 공식 점수·시간 근거, 검토기 오류 의심 29건 점검

## 1. 구조 변경(스키마·검증기·프롬프트·게이트)
- **번들 대표 스킬(`representative_skill`)과 파트별 평가 스킬(`parts[].skill_codes`)을 분리**한다. 공식 FRQ는 파트마다 스킬이 다르다(예: 2026 Q1 = 1.A / 3.C / 4.B / 5.A / 6.E / 6.B). 대표 스킬은 라벨이며 **어떤 한 파트라도 그 스킬을 평가해야 한다**(게이트 `representative_skill_not_assessed_by_any_part`). 모든 파트가 같은 스킬일 필요는 없다.
- **파트별 토픽(`parts[].topic_codes`)** 필수(Bio 게이트 `part_X_no_topic` / `unknown_topic`): 공식 토픽 코드만.
- **파트별 루브릭 행**: 파트당 ≥1행, 행 점수 합 = 파트 점수, 행마다 필수 요소.
- 마이그레이션 스키마: `ap_frq_parts.skill_codes[]`·`topic_codes[]`는 data-design §9, 후보 payload(`parts[]`)는 이미 같은 형태. 검증기: `lib/ap-generation/gates.ts`(`FrqPart.topic_codes`, `FrqPack.representative_skill`, `gateFrq(…, {requirePartTopics, topics})`). 검토 프롬프트(`pipeline2.ts` REVIEW_SYS): "각 파트를 **자기 스킬·루브릭 행**으로 판단하고 번들 단일 스킬로 판단하지 말 것, 공식 점수·시간 입자를 이유로 반려하지 말 것".

## 2. 공식 점수·시간 규칙 검증(근거와 적용 연도)
| 규칙 | 공식 근거 | 연도 |
|---|---|---|
| 섹션 II = 6문항, 90분, 점수 50% | AP Central Biology 시험 페이지·CED | 2027 시험 구조(CED V.1 © 2025) |
| 긴 문항 2개(각 9점: 실험 해석·평가 / 실험 해석+그래프) + 짧은 문항 4개(각 4점: 과학적 탐구 / 개념 분석 / 모델·시각 표현 / 데이터 분석) | CED 샘플 FRQ 정답표와 채점 가이드 헤더("Question 1: Interpreting and Evaluating Experimental Results 9 points … Question 3: Scientific Investigation 4 points …") | 2023·2024·2025·2026 채점 가이드 확인 |
| 짧은 문항 = **정확히 4개의 1점 파트(A–D)** | 2025·2026 채점 가이드(Point A1…D1, 문항당 4점), 2023·2024 (a)–(d) | 2023–2026 |
| 긴 문항 파트 점수는 문항마다 다름 | 2023 Q1: a2/b3/c2/d2, 2024 Q1: a2/b3/c1/d3, 2025·2026 Q1: A1/B3/C3/D2, Q2: A1/B4/C2/D2 | 2023–2026 |
| 1점 계산·읽기 파트는 정상 | 2026 Q2 C(ii) 퍼센트 증가 계산 1점, 2025 Q1 C(iii) 아미노산 수 계산 1점, 2024 Q2 C(ii) 단위 계산 1점 | 2024–2026 |
| 계산 답은 **허용 범위**를 둔다 | 2024·2025 가이드 예: 97,750(허용 93,150–102,350), 3% 감소(−2.8~−3.2) | 2024–2025 |
| 문항별 권장 시간은 **공시되지 않음**(섹션 총 90분만) | AP Central | — |
→ 시간 규칙은 **점수 비례 추정**(90분 / 34점 ≈ 2.65분/점 → 긴 9점 ≈ 24분, 짧은 4점 ≈ 10.6분)이며 내부 프로필이다: 긴 18–26분, 짧은 7–13분(`BIO_PROFILE`). Calculus 는 90분/54점 ≈ 1.67분/점(9점 ≈ 15분), Micro 는 쓰기 50분/20점 = 2.5분/점(10점 ≈ 25분, 5점 ≈ 12.5분; 60분 중 읽기 10분 제외)로 별도 프로필을 둔다.
(검토 프롬프트가 요구했던 "1~3점 파트"·"22분은 길다"는 공식 입자와 어긋나는 규칙이었다.)

## 3. 검토기 오류 의심 29건 — 대표 사례 점검 결과
대상: 런1 Bio FRQ 반려 중 시간·점수 입자 비판이 있는 29건. **대표 사례(칸별 4~5건)를 읽고** 판정했다. 일괄 통과 처리는 하지 않는다.
- 시간·입자 비판 중 **공식 패턴과 충돌하는 주장**: "짧은 문항의 4×1점은 AP FRQ 같지 않다"(공식은 정확히 4×1점), "9점 22분은 길다"(점수 비례로 약 24분), "1점 계산 파트는 사소하다"(공식에 1점 계산 파트가 있다). → 이 주장들은 **검토기 규칙 오류**이며 프롬프트·프로필을 수정했다.
- 하지만 29건을 대표 사례로 분류하면 **시간·입자 비판만으로 반려된 건은 0건**이다. 28건은 키·허용 답·자료·루브릭·계산기 메타데이터 등 실제 결함이 함께 있고 1건은 혼합이다. 즉 검토기 규칙을 고쳐도 29건 중 어느 것도 자동으로 통과로 바뀌지 않는다(대표 사례: "part (d)가 1점에 세 요소 요구", "허용 답·키 불일치").
- 따라서 처리: 29건은 반려 상태를 **유지**(이력에 '규칙 수정 전 반려' 표기 가능)하고, 수정된 규칙·코드 우선 원형으로 **새로 생성한 후보**로 재평가한다. 일괄 구제 없음.

## 4. 짧은 탐구 FRQ 코드 우선 원형(생성 전 준비 완료, 아직 생성하지 않음)
- `frq_bio_investigation`(3.B/3.C/6.B, 토픽 8.1): 설계표·평균·±2SE 겹침을 코드가 계산, 파트 A 독립변수 / B 대조군+이유 / C 귀무가설 / D 데이터로 주장 뒷받침. 4×1점, 파트마다 토픽·스킬·루브릭 1행.
- `frq_bio_data_short`(Q6형, 4.B/5.A/5.B/6.B, 토픽 3.2·3.5·3.7): A 추세 서술 / B 퍼센트 변화 계산 / C ±2SE 겹침으로 같은 쌍 판정 / D 주장 뒷받침. 퍼센트 변화·겹침은 독립 검증기(`bio_checks.py`)로 재계산(테스트 `gates.test.ts`).
- 두 원형 모두 `representative_skill` 과 파트별 스킬이 다르다. 이후 원형: 개념 분석(Q4형), 모델·시각(Q5형)은 시각 자료 렌더링 규격 필요(후속).

## 5. 시간 추정의 지위(2026-10-08 오너 결정)
- 점수 비례 시간(약 2.65분/점)은 **내부 참고 수치일 뿐 공식 문항별 시간이 아니다**. 게이트(`est_minutes_too_long`, `reference_time_out_of_range`)는 Bio 에 적용하지 않고(코드 반영), 편차는 `advisoryBioTime()` 의 참고 표시로만 남긴다. 검토기 프롬프트도 "예상 시간 차이만으로 반려·감점하지 말고 실제 과제량(단계·자료 읽기·작성량)과 풀이 검토로 판단"하도록 수정했다. 공식 입자 규칙(짧은 문항 = 4개의 1점 파트, 긴 문항 9점)은 유지.
