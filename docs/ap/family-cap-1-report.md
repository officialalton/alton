재현: `npx tsx scripts/ap-generation/family-cap-report.ts --subject ap_calculus_ab|ap_calculus_bc` (디스크 무변경). 판정 코드 `lib/ap-exam/look-alike.ts`, 선택기 `lib/ap-exam/ab-select.ts`(`FULL_EXAM_FAMILY_CAP=1`, 옵션 `fullExamFamilyCap`).

## 규칙
- 풀 모의고사에서 **독립 문항**의 같은 문항군은 최대 1. 한 지문을 공유하는 하위 문항과 FRQ 의 소문항은 묶음 1건으로 센다(현재 MC 는 전부 standalone, FRQ 는 묶음 단위라 영향 없음). 부분 세트는 기존 규칙(MC 문항군당 2) 유지.
- **look-alike 는 문항군 ID 만으로 판정하지 않는다.** 같은 단원.토픽·같은 자료 형태에서 (a) 숫자·`$...$` 수식을 가린 문장 틀이 같거나 (b) 같은 archetype·같은 풀이 단계 서명·문장 단어 겹침 70% 이상이면 같은 문항군으로 병합(연결 요소). 선택기는 병합된 군집을 문항군으로 쓴다.
- **같은 개념의 반복은 금지가 아니다.** 개념 키 하드 규칙·교체 사유 없음(공식 범위 유지).

## 게시본 교체를 적용할 때의 안전한 방식(적용하지 않음)
- 저장소 메커니즘: `mock_exam_sets` 는 `set_group_id` + `version_no` 버전 행이고(`20261415000000_p7_mock_exam_v1_foundation.sql`), 세트 수정은 **새 버전 행**이다. 응시 `mock_exam_attempts.exam_set_id` 는 시작 시점 버전을 고정 참조하고, `mock_exam_answers.set_item_id` 는 그 버전의 `mock_exam_set_items`(problem_version_id 스냅샷)를 가리키므로 기존 응시·답안·채점은 바뀌지 않는다.
- 적용 절차: 같은 `set_group_id` 에 `version_no+1` 초안 → 교체 10건이 반영된 `mock_exam_set_items` 구성(문항은 `problem_versions` 신규 스냅샷 아님·기존 공개 버전 재사용, 변경분만 다름) → 공개 시 이전 공개본은 `archived`(그룹당 공개 1개 부분 유니크). 공개 게이트(섹션별 문항 수·시간)는 기존 그대로 통과해야 한다.
- 오너 결정 필요 한 가지: 응시 기록이 `exam_set_group_id` 당 학생 1건이라, 이미 응시한 학생이 새 버전을 다시 볼지(재응시) 구버전 결과만 유지할지는 정책 결정이다. 지금 응시자가 없으면(테스트 계정 제외) 부담이 없다.
