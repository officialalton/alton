# 채택 기준 5가지 + 검수 파이프라인

## 1. 채택 기준(5개 전부 통과해야 채택, 하나라도 미달이면 반려/수선 — 다른 항목으로 상쇄 불가)
**즉시 반려(보상 없음)**: 오답 키 / 정답 복수 / 조건 누락 / 자료 오류(자료가 서술과 불일치) / 범위 밖 지식 필요.
| # | 기준 | 통과 조건 |
|---|---|---|
| 1 | 범위·스킬 적합 | 공식 단원·LO 존재, `primary_skill` 공식 코드와 실제 수행 과제 일치, 삭제 주제 아님, 범위 밖 지식·도구(과목별 허용 목록 밖) 불필요 |
| 2 | 정답·채점 정확성 | 단일 정답 키; 계산·단위·코드는 **실제 실행/재계산으로 검증**; FRQ는 부분 점수 행이 일관(총점=행 합, 파트별 스킬 연결), **유효한 대체 풀이 허용 목록** 정의 |
| 3 | 자료·표현 완결성 | 축·범례·단위·참조 라벨 일치, 표/그래프 수치가 서술과 일치, 영어 문장이 명확·단일 해석, 세트 문항이 자료 1개로 완결 |
| 4 | 오답·해설 품질 | 오답은 **구체 오개념 기반**(선지별 오개념 메모 필수), 길이·형식으로 정답 노출 없음, 해설이 정답 이유와 각 오답이 틀린 이유를 설명(영어, 한국어 토글 선택) |
| 5 | 시험 적합성 | 시간·읽기·계산 부하가 공식 문항과 같은 범위(과목별 초당 기준), 허용 계산기·참고 자료 일치, **세트 내 과반복 없음**(같은 단원·스킬·구조 편중, 숫자만 바꾼 변형 금지) |
- 난이도는 채택 기준이 아니라 **별도 태깅**(잠정). 난이도를 올리려고 부하·모호성·범위 밖 지식을 쓰면 5·1번 위반.
- 수율 25%는 **효율 점검 지표**이며 기준을 낮추는 근거가 아니다. 수율 미달이면 생성 프롬프트·검증을 고치고, 기준은 유지.

## 2. 검수 파이프라인(문항당)
1. **자동 구조 검사** — 필드 완전성, 스키마(자료/세트/FRQ 파트·루브릭 행), 선지 수(과목별), 길이·형식 편차, 삭제 주제 필터, 영어 해설 존재.
2. **계산·코드·자료 일치 검증** — 과목별 결정적 방식(SymPy/수치/Java 실행/표 재계산/그래프 방향 규칙). 자료 수치↔서술 일치 점검.
3. **독립 키·해설 검토** — 정답 키를 숨기고 다른 모델이 풀이 → 불일치·복수 정답 탐지. **모델 일치는 보조 증거일 뿐 정답·난이도·품질의 충분 근거가 아니다**(특히 hard 근거로 사용 금지).
4. **범위·스킬·난이도·시험 적합성 검토** — 공식 코드 대조, 부하·시간 추정, 반복성, 난이도 근거 서술(잠정).
5. **과목 전문가 검토** — **처음 3과목(Calc AB, Bio, Micro)은 채택 후보 100%**. 이후 확대는 표본 검수 제안: 위험도 층화(고위험: FRQ·계산/코드 정답·그래프 자료·신규 CED 과목[Stats]·세트 문항 → 100%; 중위험: 일반 MC 25%; 저위험: 정의형 MC 10~15%) + 직전 표본 오류율이 임계(예: 5%)를 넘으면 해당 층 100%로 복귀. 오너 승인 필요.
6. **세트 단계 검토** — 구성 후 별도 세트 검증(set-and-weakness-validation.md).
- **AI FRQ 채점**: 전문가 비교 보고(AI vs 전문가 채점 일치도·편향·오류 유형) 승인 전에는 학생에게 비노출. 노출 후에도 "참고용 피드백"으로만 표시, 점수 환산·합산 없음.
- 모든 단계의 결과·비용·소요 시간·반려 사유를 `ap_verifications`/`ap_review_events`에 기록.
