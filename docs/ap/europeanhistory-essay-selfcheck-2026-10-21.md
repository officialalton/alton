# AP European History 에세이 채점 — 자체 샘플 기반 채점 기능 검증 (2026-10-21)

**이 문서의 위치**: ALTON이 직접 작성한 문항·자료·응답으로 AI 채점 기능(`euro-v1`)의 동작을 점검한 기록이다. **공식 채점 일치율이 아니며, 실제 학생 응답에 대한 정확도 보정도 아니다.** 공식 학생 응답·공식 문제·공식 Scoring Guidelines 원문은 이번 검증에 복제·변형·모델 입력·저장하지 않았다.

## 0. 사전 등록 (실행 전 고정 — 결과를 본 뒤 바꾸지 않는다)

### 0.1 절차와 고정 시점
1. `data/ap/euro-selfcheck/designs.json` — 응답 설계(범주·의도 요소 점수). 응답 작성 전 고정.
2. `questions.json`(문항·자료·채점 메모), `responses.txt`(응답 본문) — 설계 후 작성.
3. `reference.json` — 응답 본문을 다시 읽고 요소별 체크리스트로 재채점한 **기준 점수**(요소별 점수·근거·허용 총점 범위). 설계 의도와 다르면 `disputed` 표시. 채점 호출 전 고정.
4. 위 파일들의 SHA-256 을 `hashes.txt` 에 기록하고 로컬 커밋으로 시점을 남긴 뒤에만 모델을 호출한다. **채점 호출에는 기준 점수·설계 의도를 절대 넣지 않는다**(프롬프트는 운영 경로 `buildPrompt` 그대로, 문항 + 자체 채점 메모 + 학생 응답).
5. 기준 점수를 만든 주체(이 작업의 작성 에이전트)는 평가받는 채점 모델과 별개다. 단, 응답 작성자와 기준 점수 확정자가 같은 에이전트라 완전한 독립 검토는 아니다(§한계). 설계 점수와 기준 점수가 다른 응답은 이견으로 표시하고, 이견이 해소되지 않은 응답(`excluded`)은 정확도 집계에서 제외하고 따로 보고한다.
6. dev 세트(DBQ-A·LEQ-A·SAQ-A)는 하네스 점검·프롬프트 수정 판단용, holdout 세트(DBQ-B·LEQ-B)는 최종 평가용으로 한 번만 채점한다. **이번 검증에서 프롬프트·루브릭 코드는 수정하지 않는다**(수정이 필요하다고 판단되면 권고만 기록).
7. 채점 경로: 운영과 동일한 2회 호출 후 행별 낮은 점수 결합(`combineRuns`). 두 번의 원본 실행을 모두 기록해 재현성도 본다. 모델·단가는 운영 기본값(`AI_ESSAY_MODEL`/`GENERATION_MODEL`, 입력 $3/출력 $15 per M 가정값).
8. 비용: 총상한 $12(재요청·수선 포함), 호출 전 예상으로 상한 직전 중단. 예상 $6–7.

## 1. 방법과 표본
- 문항 5개(전부 ALTON 자작): DBQ-A·DBQ-B(자료 6개씩), LEQ-A·LEQ-B, SAQ-A(자료 1개). 자료는 ALTON이 쓴 "시대풍 문서"이며 실존 인물·간행물을 인용하지 않는다(진짜 1차 사료가 아님 — 한계). 프롬프트·자료·채점 메모는 `questions.json`.
- 응답 49건(기본 응답 42건 + 주입 변형 7건; 주입 변형은 `responses.txt` 의 기본 응답에 `questions.json` 의 주입 문장을 덧붙여 러너가 생성). 문항당 범주: 상(만점) / 경계(6·5점, 한 요소 결여) / 중 / 경계 하(3점·2점) / 하(요약·일반론) / 길고 유창하지만 근거 없음 / 서툰 표현이지만 기준 충족 / 사실 오류·자료 오독 / 무관 / 주입(직접 지시문, 구분자 위조 태그). 무응답은 호출 전 차단 확인(`checkEssayLength("")="empty"`, 공백만="empty", 7단어="too_short").
- dev(하네스 점검, DBQ-A·LEQ-A·SAQ-A): 28건. holdout(최종 평가, DBQ-B·LEQ-B): 21건. 기준 점수 이견 제외 0건(`excluded`=0). 단 모호 허용 범위(`ambiguous_kept`) 사용: 49건 중 21건. 설계와 기준 점수가 달랐던 응답 2건: LEQA-8(설계 맥락 1 → 기준 0, 한 문장 맥락은 지나가는 언급), SAQA-5(설계 A=1 → 기준 0, 응답이 지문과 반대로 서술). 둘 다 같은 에이전트가 재검토해 기준 점수를 따랐다.
- 채점: 운영과 동일한 `buildPrompt`(앵커 샘플 없음 — 한계), 응답당 2회 호출 후 행별 낮은 점수 결합. 전체를 두 번(1차·2차 반복) 채점해 같은 응답의 반복 변동을 측정. 프롬프트·루브릭 코드 수정 없음.
- 모델 `claude-sonnet-5-5`(운영 기본). 호출 기록·토큰·비용: `calls-*.jsonl`. 결과 원본(요소별 점수·근거): `results-*.json`. 집계: `analysis-*.json`, 집계 스크립트 `scripts/euro-selfcheck-analyze.ts`.

## 6. 한계 (이 결과를 이렇게 읽지 말 것)
1. **공식 채점 일치율이 아니다.** 기준 점수는 ALTON(응답 작성자와 같은 에이전트)이 같은 루브릭 정의로 매겼다. 순환성이 있고 실제 채점 정확성을 확인한 것이 아니다. '엄격한 편향'·'과소 평가'는 이 기준 점수와의 차이를 뜻할 뿐이다. 기존 holdout은 분석에 사용되어 이제 수정용 자료이며, 같은 자료의 재통과는 독립 검증으로 집계하지 않는다.
2. **실제 학생 응답 정확도 보정이 아니다.** 응답은 의도된 범주를 보여주도록 쓴 짧은 합성문(DBQ 약 150–500단어)이라 실제 학생 글의 분포·길이·오류 양상을 대표하지 않는다. 자료도 진짜 1차 사료가 아니다.
3. 표본이 작다(holdout 16건 + 주입·무관 5건, 문항 2개). 비율은 한 건이 6%p 이상이며, 문항 2개로 일반화할 수 없다. SAQ 는 dev 전용 소량이라 판정에서 제외.
4. 운영 프롬프트의 앵커 샘플(ALTON 자체 생성)을 쓰지 않았다 — 앵커가 점수를 올릴지 내릴지 미검증. 채점 메모(자체 작성)는 포함했다.
5. 2027 개편 형식·공식 루브릭 개정 반영은 검증하지 않았다. holdout 은 한 번 채점 후 같은 세트로 반복(프롬프트 수정 없음)했다.
6. 단가는 가정값($3/$15 per M)으로 계산했다.

## 7. 활성화 판단 자료 (오너 결정용 — 이 작업은 켜지 않았다)
`EURO_ESSAY_GRADING_VALIDATED` 는 false 로 두었고 켜는 커밋도 만들지 않았다. 서버 플래그 `AI_ESSAY_GRADING_ENABLED` 와 코드 상수는 변경하지 않았다.
**판단 요약**: 자체 정의 기준으로 (a) 과대 채점·주입·길이/유창성 편향·무관 응답·재현성은 양호, (b) 보수 편향이 크고(특히 LEQ) 만점급이 한 점 낮게 나오는 경향이 있어 정확도 기준은 미달, (c) 그 정확도가 학생 경험에서 허용 가능한지는 오너 판단(참고용 추정치·"엄격하게 채점될 수 있음" 고지 전제), (d) 공식 일치·실제 학생 응답 정확도는 알 수 없음.
권장 순서: ① 사후 분석(`europeanhistory-essay-analysis-2026-10-21.md`)으로 불일치 원인 분류 ② LEQ 논지·증거·분석 안내를 자체 문구로 재작성(루브릭 문구 점검 겸) 후 **새 holdout**(기존 holdout 은 이번 평가에 소진됨)으로 1회 재검증, 예상 $1–2 ③ 공식 샘플 이용은 허락 문의(§8.2, 초안만 있고 발송하지 않음)와 별개로 보류.
