- 기준일: 2026-08-29
- 용어 기준: `../CONTEXT.md`
- 실행 계획: `2026-08-29-master-roadmap-v3.md`
- 개발 전달: `2026-08-29-developer-handoff-v3.md`

## 1. 목표 변경

이 프로젝트의 목표는 20명 파일럿에 맞춘 최소 기능이 아니다. 고객 수와 무관하게 정식 서비스 오픈 전에 핵심 고객 여정, 교육 기록, 결제·수업권·정산, 권한과 예외 상황이 일관되게 동작하는 제품을 완성한다.

- 파일럿 인원은 사업 운영 계획일 뿐 제품 스코프 결정 기준으로 사용하지 않는다.
- 일정 때문에 데이터 무결성, 기록 보존, 보안, 핵심 수업 경험을 생략하지 않는다.
- 자동화가 없어도 수동 운영 절차가 명확하면 출시 가능하지만, 상태와 이력은 반드시 Alton에 남긴다.
- 화면 완성보다 도메인 관계와 상태 전이를 먼저 확정한다.

## 2. 시스템 원칙

> Alton/Supabase는 업무 상태의 원본이고 Google Workspace와 Stripe는 외부 실행 수단이다.

```text
가족·자녀·선생님·관리자
          │
       Alton 앱
          │
 ┌────────┼─────────┐
Supabase  Google     Stripe
업무 원본  일정·Meet  결제 실행
수업 기록  문서       결제 식별자
수업권     권한       환불 결과
정산 원장
```

외부 서비스의 이벤트·파일·결제가 삭제되거나 실패해도 Alton의 계약, 수업, 수업권, 정산 이력은 소실되지 않아야 한다.

## 3. 핵심 관계 모델

```text
Household
 ├─ Guardians
 └─ Students
      ├─ Contracts
      ├─ Entitlement Grants ─ Entitlement Ledger
      └─ Subject Enrollments
           ├─ Teacher Assignments (history)
           ├─ Curriculum Progress
           └─ Sessions
                ├─ Reservation / Calendar / Meet
                ├─ Teacher + rate snapshot
                ├─ Material version snapshot
                ├─ Attendance / status history
                ├─ Annotation events / snapshots
                ├─ Homework / review / files
                └─ Payout Item
```

### 3.1 반드시 분리할 개념

| 개념 | 수명 | 변경 시 보존할 것 |
|---|---|---|
| 계약 | 자녀별 계약 기간 | 서명 문서, 가격·정책 버전, 상태 이력 |
| 과목 수강 | 자녀가 과목을 듣는 기간 | 진도, 수업권 연결, 시작·중단·종료 |
| 선생님 배정 | 과목 내 담당 기간 | 이전/새 선생님, 적용일, 사유 |
| 예약 | 한 수업의 예정 시간 | 취소·새 예약 출처·Google 동기화 이력 |
| 수업 | 실제 교육 기록 | 당시 선생님·시급·교재·필기·출석 |

현재 `enrollments`가 과목 수강과 선생님 배정을 동시에 표현하는 구조는 v3에서 분리한다.

## 4. 확정된 사업 정책

### 4.1 체험 수업

- 자녀당 기본 1회, 60분이다.
- 학생·보호자 계정은 체험 전에 생성한다.
- 정규 수업과 같은 세션뷰를 사용한다.
- 수업권을 보류하거나 소진하지 않는다.
- 완료된 체험은 회사 부담으로 선생님에게 기존 정규 시급을 지급한다.
- 당일 취소·노쇼에는 선생님 비용을 지급하지 않는다.
- 당일은 선생님의 IANA timezone상 수업 예정일을 기준으로 한다.
- 체험 선생님은 해당 자녀·과목의 정규 선생님으로 기본 승계한다.
- 체험 취소·노쇼 후 예외적인 재체험은 관리자 승인과 이력을 요구한다.

### 4.2 선생님 변경

- 선생님 배정은 자녀·과목 단위다.
- 관리자는 적용일과 사유를 지정해 변경한다.
- 다른 과목의 배정에는 영향을 주지 않는다.
- 완료된 수업·리뷰·채팅 아카이브·정산은 당시 선생님을 유지한다.
- 확정된 미래 예약은 자동 이전하지 않고 취소 대상을 관리자에게 제시한 뒤 학생에게 일반 새 예약을 안내한다.
- 새 선생님에게 필요한 커리큘럼 진도·문서 접근만 인계한다.
- 이전 선생님의 미래 접근 권한은 회수하되 과거 기록은 감사 목적으로 보존한다.

### 4.3 정규 수업과 수업권

- 사용자 화면과 업무 용어는 `크레딧` 대신 `수업권`으로 통일한다.
- 현재 정규 수업 유형은 1:1, 120분이다.
- 현재 기본 수업권 1장은 정규 수업 1회 120분을 이용할 권리다.
- 예약 확정 시 수업권 1장을 보류하고, 정상 완료 시 보류를 소진으로 확정한다.
- 정책상 무료 취소는 보류를 해제한다.
- 체험 수업은 수업권과 무관하다.
- 잔여 수업권은 직접 수정하는 숫자가 아니라 원장 합계에서 계산한다.

### 4.4 미래 수업권 확장

수업권 유형은 버전 관리하며 다음 값을 갖는다.

- 코드와 표시명
- 적용 가능한 수업 유형
- 기본 수업 시간
- 1회 예약당 필요한 수업권 수량
- 개인/그룹 형태와 참여 인원
- 적용 가능한 과목 범위
- 유효기간 규칙
- 취소·노쇼 소진 규칙
- 판매·중단 상태와 버전 적용일

향후 60분 수업, 90분 수업, 그룹 수업, 진단 수업 등이 생겨도 기존 구매·수업 기록의 의미가 바뀌지 않아야 한다. 상품 정의를 수정하지 않고 새 버전을 만든다.

### 4.5 선생님 취소와 지각

#### 선생님 취소

- 학생 수업권을 소진하지 않고 예약에 걸린 보류를 해제한다.
- 선생님 비용을 지급하지 않는다.
- 기존 예약은 취소 상태와 사유를 남긴다.
- 학생은 별도 우선권 없이 기존 예약 절차로 다시 예약한다.
- 우선 재예약 기능과 대체 선생님 자동·수동 배정 기능은 만들지 않는다.

#### 선생님 지각

- 10분 이상 지각하면 제공하지 못한 시간을 `보충시간`으로 다룬다.
- 학생과 선생님이 수업 중 모두 동의하고, 해당 수업 직후 선생님의 다른 수업·일정과 충돌하지 않으면 같은 날 바로 이어서 연장할 수 있다.
- 같은 날 연장해 부족 시간을 모두 제공하면 별도 보충시간 잔액을 만들지 않는다.
- 바로 연장하지 않으면 제공하지 못한 분만큼 보충시간을 생성한다.
- 학생은 향후 해당 선생님의 정규 수업에 보충시간을 붙일 수 있다.
- 미래 수업의 원래 종료 시각 뒤 구간도 선생님이 오픈한 가능 시간 안에 있고 다른 일정과 충돌하지 않아야 한다.
- 보충시간은 별도 수업이나 수업권이 아니며, 붙인 미래 수업의 예약 종료 시각과 Google Calendar 이벤트를 그 시간만큼 연장한다.
- 보충시간을 적용해도 학생 수업권을 추가로 보류하거나 소진하지 않는다.
- 사용 전 보충시간은 잔여 분, 발생 수업, 담당 선생님, 적용 수업과 상태 이력을 보존한다.

### 4.6 선생님 정산 시간 기준

- 선생님 시급은 단가이며 정산 계산 단위는 1분이다.
- 정산은 Google Meet의 실제 통화·접속 시간이나 앱 체류 시간을 측정해 계산하지 않는다.
- 정산 기준은 예약된 수업 시간과 최종 수업 판정에서 확정된 `정산 인정시간`이다.
- 정상 완료된 정규 수업의 기본 정산 인정시간은 120분이고, 정상 완료된 체험 수업은 60분이다.
- 선생님이 지각했지만 같은 수업 뒤에 바로 연장해 총 120분을 제공하면 해당 수업의 정산 인정시간은 120분이다.
- 선생님 지각분을 미래 수업에 붙이는 경우, 원래 수업은 `120분 - 미이행 보충시간`만 인정하고 미래 수업에서 보충시간을 실제 이행한 뒤 그 분을 추가 인정한다.
- 보충시간을 약속만 하고 아직 제공하지 않았다면 정산하지 않는다.
- 선생님 취소는 정산 인정시간 0분이다.
- 개별 정산 항목은 시급과 인정 분을 스냅샷으로 보존한다.
- 계산식은 `시급 × 정산 인정시간 ÷ 60`이다. 소수 금액은 항목에서 보존하고 정산 묶음 합계에서 최종 원 단위로 반올림한다.

### 4.7 학생 취소·노쇼·지각

#### 정상 취소와 새 예약

- 수업 시작 24시간 전까지 학생이 직접 취소할 수 있고, 필요하면 일반 예약 흐름에서 별도의 새 예약을 만든다.
- 수업권 보류를 해제하고 수업권을 소진하지 않는다.
- 선생님 비용을 지급하지 않는다.

#### 늦은 취소

- 수업 시작까지 24시간 미만일 때 취소하면 늦은 취소로 처리한다.
- 수업권 1장을 소진한다.
- 선생님에게 정규 수업 120분 비용을 지급한다.

#### 학생 노쇼

- 수업 시작 후 15분까지 학생이 접속하지 않으면 선생님이 학생 노쇼를 신고할 수 있다.
- 관리자 또는 시스템 정책으로 최종 확정한 뒤 수업권 1장을 소진한다.
- 선생님에게 정규 수업 120분 비용을 지급한다.
- 학생·보호자·관리자에게 결과를 알린다.

#### 학생 지각

- 수업은 원래 예약된 종료 시각에 끝난다.
- 수업권 1장을 소진하고 선생님에게 120분 비용을 지급한다.
- 선생님이 자발적으로 연장할 수 있지만 의무가 아니며, 학생 지각으로 보충시간을 생성하지 않는다.

#### 관리자 예외

- 관리자는 특별한 사유가 있으면 수업권과 정산 판정을 조정할 수 있다.
- 원래 판정, 변경 판정, 수업권 처리, 정산 처리, 사유, 관리자, 시각을 감사 이력으로 남긴다.

### 4.8 접속 기록

- 학생과 선생님의 접속·이탈 시각은 가능한 범위에서 수집해 보존한다.
- Google Meet에서 제공되는 참가 기록과 Alton의 수업 입장 클릭·세션뷰 접속 기록은 출처를 구분한다.
- 한 사용자가 여러 번 들어오고 나간 경우 각각의 접속 구간을 보존한다.
- 기술적 제약으로 Meet 참가 기록을 가져오지 못한 경우 Alton 접속 기록을 실제 Meet 접속으로 표시하지 않는다.
- 접속 기록은 출석 분석, 노쇼 확인 보조, QC, 향후 제품 분석에 사용할 수 있다.
- 접속 기록만으로 수업 상태, 수업권 소진, 선생님 정산을 자동 확정하지 않는다.
- 최종 판정은 예약 정보, 당사자 신고, 관리자 확인과 정책 결과를 함께 사용한다.
- 접속 기록의 보존 기간과 사용자 고지는 개인정보 정책에서 관리한다.

### 4.9 수업권 유효기간·환불·이전

#### 유효기간과 소진 순서

- 기본 수업권은 구매일로부터 12개월간 유효하다.
- 유효기간은 수업권 유형 버전에 설정하며 향후 상품별로 다르게 정할 수 있다.
- 예약하려는 수업의 시작 시각이 수업권 만료 시각 이내여야 한다.
- 만료일이 가장 가까운 수업권부터, 만료일이 같으면 먼저 지급된 수업권부터 보류·소진한다.
- 만료 30일 전과 7일 전에 학생·보호자에게 알린다.
- 만료된 수업권은 삭제하지 않고 원장에 `expired`로 남긴다.

#### 취소 후 복원과 연장

- 학생 정상 취소는 보류된 수업권을 원래 만료일로 복원하며 만료일을 연장하지 않는다.
- 학생 늦은 취소와 노쇼는 확정된 정책에 따라 수업권을 소진한다.
- 선생님 또는 회사 사유 취소는 수업권을 복원한다.
- 선생님 또는 회사 사유로 복원되는 시점에 만료까지 30일 미만이면 취소일로부터 30일까지 연장한다.
- 질병·장기 입원·회사 귀책·서비스 장애 등은 관리자가 사유를 남기고 추가 연장할 수 있다.

#### 환불

- 사용하지 않았고 예약에 보류되지 않은 유료 수업권만 환불할 수 있다.
- 기본 판매 단위는 20회 패키지이며 실제로 판매되는 단건 회당가보다 낮은 패키지 할인가를 적용한다.
- 중도 해지 환불액은 `실제 패키지 결제액 - (소진 회차 × 실제 단건 판매가)`로 계산하고 0보다 작으면 0으로 한다.
- 늦은 취소와 학생 노쇼로 소진된 수업권도 소진 회차에 포함한다.
- 환불 확정 시 남은 패키지 수업권은 모두 `refunded` 처리하고 더 이상 사용할 수 없다.
- 정상 회당가는 환불 계산만을 위해 만든 가상 가격이 아니라 실제로 단건 구매가 가능한 가격이어야 한다.
- 결제 전에 단건가, 20회 패키지가, 할인액, 중도 해지 재정산 공식과 예시를 같은 구매 흐름에서 명확히 고지한다.
- 무료·프로모션·관리자 보상 수업권은 환불 대상이 아니다.
- 환불된 수업권은 삭제하지 않고 원장에 `refunded`로 남긴다.
- 학생 환불과 이미 확정된 선생님 정산은 별도 원장과 정책으로 관리한다.
- 청약철회와 환불 제한 문구는 서비스 제공 지역의 법률 검토 후 약관에 반영한다.

#### 자녀 간 이전

- 학부모의 직접 이전 기능은 제공하지 않으며 자녀별 계약 원칙상 일반 이전은 허용하지 않는다.
- 잘못된 자녀에게 결제한 경우 등 명확한 운영 예외에 한해 관리자가 이전할 수 있다.
- 이전 수업권은 미사용 상태이고 예약에 보류되지 않아야 하며, 받는 자녀에게 호환되는 계약·수업 유형이 있어야 한다.
- 이전은 기존 자녀 차감과 새 자녀 지급을 각각 원장에 남기고 사유·처리자·시각을 감사 이력으로 보존한다.
- 사용 이력이 있는 계약 전체를 다른 자녀에게 변경하지 않고 기존 계약 정리와 신규 계약으로 처리한다.
- 관리자는 원장 기록 없이 수업권 잔여량을 직접 수정할 수 없다.

### 4.10 120분과 다르게 진행된 수업

#### 정상 완료와 학생 사유

- 양쪽이 정상 완료로 확인한 정규 수업은 실제 접속 길이와 무관하게 수업권 1장을 소진하고 선생님에게 120분 비용을 지급한다.
- 학생 요청, 학생 일정, 학생 기기·인터넷 문제로 일찍 종료한 경우도 수업권 1장 소진·120분 지급이며 보충시간은 생성하지 않는다.
- 양쪽 합의로 자발적으로 120분을 초과해도 추가 수업권이나 추가 지급은 없다. 이미 발생한 보충시간을 적용한 경우만 해당 분을 별도 인정한다.

#### 선생님 사유

- 수업이 일부 진행된 뒤 선생님 사유로 조기 종료·중단되면 수업권 1장을 소진하고 미제공 분만큼 보충시간을 생성한다.
- 원래 수업은 최종 판정된 제공 분만 정산하고, 나머지는 보충시간을 실제 제공한 뒤 정산한다.
- 최종 제공 시간이 90분 미만이면 관리자 QC 대상으로 자동 표시한다.
- 수업이 전혀 시작되지 않으면 선생님 취소·노쇼로 처리해 수업권을 복원하고 선생님 비용을 지급하지 않는다.

#### 회사·Google Meet 장애

- 수업을 전혀 시작하지 못하면 기존 예약을 취소하고 수업권을 복원하며 해당 예약의 선생님 비용을 지급하지 않는다. 학생은 일반 예약 흐름에서 새 예약을 만든다.
- 수업 도중 중단되면 수업권 1장을 소진하고 미제공 분을 보충시간으로 생성한다.
- 중단된 원래 수업은 제공된 분만 정산하고, 보충시간은 실제 제공 시 정산해 두 수업의 인정시간 합계가 120분을 넘지 않게 한다.
- 실제 Meet 접속 시간만으로 제공 분과 최종 판정을 자동 확정하지 않는다.

### 4.11 과목 대화방

- 대화방은 자녀·과목·현재 선생님을 기준으로 생성한다.
- 학생, 보호자, 담당 선생님과 권한 있는 관리자가 접근한다.
- 학생과 선생님의 비공개 1:1 대화는 제공하지 않고 보호자가 포함된 과목 대화방에서 소통한다.
- 관리자는 모든 활성·보관 대화방의 메시지, 첨부파일, 수정·삭제 이력과 신고 내용을 조회할 수 있다.
- 관리자 조회 행위도 권한과 감사 로그로 기록하며, 사용자에게 관리자 조회 가능성을 고지한다.
- 선생님 변경 시 기존 대화방은 읽기 전용으로 보관하고 새 선생님용 대화방을 생성한다.
- 일정 변경은 메시지가 아니라 예약 기능으로, 계약·결제·환불은 관리자 문의로 처리한다.
- 개인 전화번호나 개인 이메일을 기본 소통 수단으로 사용하지 않는다.

### 4.12 계약 유지·해지

- 계약은 자녀별 계속 계약이며 고정 만료일, 자동 갱신, 자동 결제를 초기 버전에서 사용하지 않는다.
- 자동 갱신·자동 결제는 향후 별도 상품·동의·해지 흐름을 갖춘 기능으로 추가할 수 있다.
- 20회권 추가 구매는 계약 갱신이 아니라 활성 계약 아래의 신규 구매이며 구매 당시 가격·환불정책 버전을 보존한다.
- 가격·환불·수업 형태 등 중요한 조건이 바뀌면 다음 구매 전에 보호자의 재동의를 받는다.
- 과목 하나를 중지·종료해도 다른 과목과 자녀 계약은 유지할 수 있다.
- 보호자는 언제든 계약 종료를 요청할 수 있고 미래 예약에는 각각 기존 취소정책을 적용한다.
- 보호자 사유 환불은 패키지 할인 재정산 정책을 적용하며 별도 해지 위약금은 부과하지 않는다.
- 회사가 서비스 제공 불가 등 운영상 사유로 종료하면 미사용 유료 수업권을 패키지 실결제 단가로 환불하고 할인을 회수하지 않는다.
- 활성 과목·미래 예약·사용 가능한 수업권·미처리 환불이나 분쟁이 모두 없는 상태가 12개월 지속되면 30일 전 고지 후 휴면 종료할 수 있다.
- 환불 승인 후 5영업일 이내 결제대행사에 환불을 요청하며 실제 입금 시점은 결제수단에 따른다.

### 4.13 데이터 보존·삭제

**(2026-08-30 정정)** 아래 보존기간은 정식 오픈 이후 생성되는 실제 고객 데이터에 적용한다. ALTON은 아직 운영을 시작하지 않았고 현재 DB의 예약·계약·수업·수업권(credit) 데이터는 실제 고객의 과거 업무 이력이 아니라 개발·테스트 데이터다. 이 데이터는 법률·회계 보존 대상이 아니므로 장기 보존하거나 신규 구조로 이관할 필요가 없다 — 구조 변경·레거시 제거 시 안전한 백업과 롤백 지점만 남기면 폐기할 수 있다. 다만 로그인 테스트 계정과 프로필(사용자·역할·상태)은 업무 테스트 데이터와 구분해 그대로 유지한다.

- 계약·가격·동의, 결제·환불·수업권 원장, 선생님 정산 기록은 종료 또는 거래 후 7년을 기본 보존기간으로 둔다.
- 최종 수업 기록·과제·필기 결과·리뷰·과목 대화방·확정 출석 및 QC 판정은 마지막 수업 또는 계약 종료 후 3년 보관한다.
- Meet 접속·이탈 원시 기록, 화이트보드 원시 이벤트, 로그인·기기·보안 로그는 12개월 보관한다.
- 계약하지 않은 상담 고객 정보는 마지막 활동 후 12개월 보관한다.
- 삭제된 데이터가 포함된 백업은 최대 35일 안에 순차 삭제한다.
- 탈퇴 시 로그인을 즉시 중단하고 진행 중인 예약·환불·분쟁을 정리한 뒤 일반 프로필을 30일 이내 삭제 또는 익명화한다.
- 법률·회계·안전상 보존이 필요한 기록은 접근 제한 상태로 유지하고 보존 사유와 삭제 예정일을 관리한다.
- 13세 미만 학생은 검증 가능한 보호자 동의 전 계정을 활성화하지 않으며 동의 버전·시각·방법을 기록한다. **(2026-08-30 R2 확정)** 학생 계정에 생년월일 또는 최소 연령대 정보를 저장해 13세 미만 여부를 판별한다. 동의 전에는 로그인·수업 참여·메시지 작성을 차단하고 동의에 불필요한 개인정보 수집도 막는다. 보호자는 동의를 철회할 수 있으며 철회 시 계정은 다시 동의 대기 상태로 돌아간다. 동의 문구는 버전 관리해 정책이 바뀌면 새 버전으로 재동의를 받을 수 있게 한다.
- 보호자는 자녀 정보의 조회·정정·삭제를 요청할 수 있다.
- Google Drive와 Supabase Storage에 같은 보존정책을 적용하고 자동 삭제 실패는 관리자 재처리 대상으로 만든다.
- 개인을 다시 식별할 수 없도록 익명화된 집계 통계만 장기 보존할 수 있다.
- 실제 서비스 제공 지역의 개인정보·미성년자·세무 규정 검토 결과가 더 짧거나 긴 법정 기간을 요구하면 정책 버전으로 조정한다.

### 4.14 수업자료 저장과 Drive 자동화

- 회사 소유 Shared Drive를 사용하고 원본 구조는 `학생 → 과목 수강 → 연도 → 일자별 수업`으로 둔다.
- 선생님 중심 구조는 원본 저장 위치가 아니라 ALTON 화면 또는 Drive 바로가기 포털로만 제공한다.
- 학생·과목 수강·예약·선생님 배정 이벤트에 따라 폴더 생성, 권한 부여·회수, 바로가기 생성·삭제를 자동 처리한다.
- 정상 운영에서 관리자가 폴더를 만들거나 선생님 권한을 수기로 부여하지 않는다. 실패 건만 관리자 재처리함에서 처리한다.
- 선생님은 현재 배정된 과목 폴더에만 접근하고 Shared Drive 전체 구성원으로 추가하지 않는다.
- 선생님 변경·퇴사 시 원본을 이동하지 않고 기존 권한을 회수한 뒤 새 선생님 권한만 부여한다.
- 학생·보호자에게 Drive ACL을 직접 주지 않고 ALTON의 가족·세션 권한 검사를 거쳐 자료를 제공한다.
- Gemini Smart Notes는 생성 후 해당 세션 폴더로 자동 이동하고 Drive file ID를 수업에 연결한다.
- Drive 폴더명이나 위치가 아니라 ALTON DB의 student/enrollment/session ID와 Drive file ID를 원본 연결정보로 사용한다.
- 폴더·권한 작업은 멱등성 키, 재시도, 이동 후 검증, 정기 대조 상태를 가진다.
- Google Drive는 확정 문서·수업자료를, Supabase는 제품 상태·실시간 화이트보드·임시 자료를 담당한다.

### 4.15 Gemini 회의록과 수업 리뷰

- 체험·정규 수업에서 Smart Notes를 기본 활성화한다. 영상·원본 음성 녹화와 별도 Meet `Transcribe the meeting` 기능은 비활성화한다.
- Smart Notes 생성 과정에서 Google이 회의록 문서에 포함하거나 연결하는 텍스트 전사는 허용한다. 이 전사는 영상·원본 음성 녹화물이 아니며, 학생·보호자에게 직접 공개하지 않고 담당 선생님과 권한 있는 관리자/QC만 접근한다.
- 화면 스크린샷은 Admin Console에서 `Only allow ... when recording is enabled`로 제한한다. ALTON은 녹화를 켜지 않으므로 정상 수업에서는 스크린샷이 생성되지 않아야 하며 Gate C에서 실제 결과를 검증한다.
- 보호자는 자녀별로 AI 회의록 및 수반 텍스트 전사 처리를 사전에 거부할 수 있다. 거부된 수업은 Meet 입장 전에 Smart Notes를 끄고 선생님이 리뷰를 직접 작성한다.
- 거부하지 않은 수업도 Google Meet 입장 시 모든 참석자에게 자동 메모에 대한 명시적 동의 화면을 표시한다. 동의 화면은 보호자의 사전 거부권을 대체하지 않는다.
- 성인 회사 관리 계정이 회의를 주최하고 Smart Notes 원본 및 수반 텍스트 전사는 선생님과 권한 있는 관리자/QC만 접근한다.
- Smart Notes는 수업 리뷰 초안이며 선생님 검토 전 학생·보호자에게 공개하지 않는다.
- 선생님은 수업 후 24시간 이내 리뷰를 확정하고, 18시간에 알림, 24시간 초과 시 관리자 목록, 36시간 초과 시 QC 건을 생성한다.
- AI 회의록 생성 실패 시 수동 리뷰 흐름으로 전환한다.
- AI 초안은 출석, 수업권, 정산, 성취도 확정의 자동 근거로 사용하지 않는다.
- 미검토 Smart Notes 원본과 수반 텍스트 전사는 12개월, 확정 리뷰는 3년 보관한다.

### 4.16 통화와 정산 일정

- 가족의 기본 결제 통화는 USD이고 가족 상황에 따라 다른 지원 통화를 설정할 수 있다.
- 상품 가격은 통화별 price version으로 관리하고 구매 건에 금액·통화·가격 버전을 고정한다.
- 환불은 원결제 통화와 원결제 수단으로 처리하며 다른 통화로 임의 환산하지 않는다.
- 선생님의 기본 지급 통화는 KRW이고 선생님별 시급 이력에서 다른 통화를 설정할 수 있다.
- 지급 통화 변경은 적용일 이후 수업에만 적용하고 과거 수업·정산을 바꾸지 않는다.
- 하나의 정산 묶음에는 하나의 통화만 포함하며 통화가 바뀐 선생님은 정산 묶음을 분리한다.
- 고객 매출과 선생님 비용은 서로 독립된 원통화로 기록하고 수업권에는 통화를 저장하지 않는다.
- 회사 보고 통화는 USD를 기본으로 하며 환율 스냅샷은 경영 리포트에만 사용한다. 환율이 계약상 환불액이나 선생님 지급액을 바꾸지 않는다.
- 정산은 매월 말일 마감, 다음 달 3영업일까지 명세서 생성, 5영업일 이의제기, 10영업일까지 지급을 기본으로 한다.

### 4.17 예약·알림 기본값

- 학생은 수업 시작 24시간 전부터 8주 뒤까지 예약할 수 있고 관리자는 24시간 이내 예약을 예외 처리할 수 있다.
- 수업 사이에는 최소 15분의 선생님 버퍼를 확보한다.
- 주간 고정 예약은 한 번에 최대 8회 생성하고 각 회차에 수업권을 보류한다. 수업권이 부족하면 가능한 회차까지만 생성한다.
- 수업 24시간·2시간 전, 예약·취소 직후, 선생님 변경, 리뷰 공개, 과제 마감 24시간 전에 이메일·인앱 알림을 보낸다.
- 수업권은 잔여 3장·1장·0장과 만료 30일·7일 전에 알린다.
- 초기에는 SMS를 제공하지 않는다.

### 4.18 과제·파일·QC 기본값

- 과제 기본 마감은 다음 수업 24시간 전이며 늦은 제출과 재제출을 허용한다. 미제출로 예약을 차단하지 않는다.
- 기본 허용 파일은 PDF, Google Docs, DOCX, PPTX, XLSX, JPG, PNG이고 파일당 최대 50MB다.
- 실행파일·압축파일·영상 업로드는 초기에는 허용하지 않고 공개 전 악성 파일 검사를 수행한다.
- 교재 업로드 시 사용 권한과 AI 생성·보조 여부를 기록하고 수정본은 새 버전으로 만든다.
- 자동 QC 대상은 90분 미만 수업, Gemini 실패, 36시간 미확정 리뷰, 신고, 지각·노쇼, 반복 취소, 신규 선생님 첫 3회와 전체 수업의 무작위 5%다.

### 4.19 계정 초대·상태·병합 (2026-08-30 R2 확정)

- **초대**: 초기 범위에서 자기가입은 제공하지 않는다. 관리자가 보호자를 초대하고, 가입한 보호자는 자기 화면에서 자녀를 추가로 초대·연결할 수 있다. 관리자는 예외 상황(보호자가 초대를 못 받는 경우 등)에서 대신 자녀 계정을 생성·연결할 수 있으며, 이 대리 개입은 감사 이력에 남긴다.
- **초대 유효기간·재발송·철회**: 초대 링크 유효기간은 7일이다. 재발송하면 기존 링크는 즉시 무효화되고 새 링크가 발급된다. 같은 이메일에 대한 pending 초대는 재발송할 때마다 새 행을 만들지 않고 재발송 이력으로 누적한다. 24시간 내 재발송은 최대 3회까지 허용한다(어뷰징 방지). 관리자는 pending 초대를 철회할 수 있다. 만료·재발송·철회는 전부 감사 이력에 남긴다.
- **계정 상태**: `pending`(초대됨, 미가입) → `active`(정상 사용) → `suspended`(복구 가능한 일시정지, 재활성화로 `active`로 되돌릴 수 있음) → `closure_pending`(탈퇴·폐쇄 처리 중) → `closed`(인증 차단, 보존기간 후 삭제·익명화, 사용자 기능으로 복원하지 않음). `suspended`와 `closed`는 서로 다른 상태다 — 방학 중 일시정지 같은 가역적 조치는 `suspended`를, §4.13의 탈퇴·30일 삭제 흐름은 `closed`(경유 상태 `closure_pending`)를 쓴다.
- **학생 활성화 조건**: 정식 계약만을 유일한 활성화 조건으로 두지 않는다. 계약 이전에 체험 수업 여정이 존재하므로, 다음 중 하나의 근거가 있으면 `active`로 전환할 수 있다 — (1) 유효한 체험 수업 여정, (2) 유효한 계약, (3) 사유가 기록된 관리자 이관 예외(레거시/이관 데이터 등). 근거 없는 활성화 전환은 차단한다.
- **계정 병합**: 중복 계정을 발견하면 병합되는 계정의 로그인을 즉시 차단하고, 관련 데이터(수업 이력, 정산, 가족 관계 등)를 생존 계정으로 단일 트랜잭션에서 재배정한다. 병합된 인증 계정 자체는 30일 후 삭제·익명화하되, 병합 매핑과 감사 기록은 7년 보관한다(계약·정산 기록과 같은 보존 기간). 병합은 관리자 전용 작업이며 실행 전 영향 범위를 재확인하고, 사용자 화면에서 되돌리기 기능은 제공하지 않는다.

### 4.20 선생님 Google Workspace 계정 (2026-08-30 R2 확정)

- 보호자·학생은 개인 이메일을 그대로 쓰고 별도 Workspace 계정을 만들지 않는다. 선생님은 `@alton.education` Workspace 계정이 필수다(Drive·Meet 접근용 신원이며, §9에서 제외한 "Google SSO 전환"과는 무관하다 — ALTON 로그인은 계속 Supabase Auth를 쓴다).
- 관리자가 선생님을 초대하면 Workspace 계정을 새로 만들거나(또는 기존 계정과 충돌하는지 확인한 뒤) 연결하고, 그 결과를 Supabase 계정과 연결한다.
- 선생님은 시급(§선생님 정산) 설정이 끝난 뒤에만 `active`로 전환할 수 있다(R1의 `teacher_rate_history` 강제 규칙과 동일 원칙).
- Workspace 계정 생성이 일부만 성공하고 일부 실패하면(예: 계정은 만들었지만 Supabase 연결 전에 실패) 처음부터 다시 하지 않고 실패한 단계부터 재처리할 수 있는 상태로 저장한다.
- 관리자 계정의 Workspace 발급은 초기에는 수동으로 허용한다(자동화 대상이 아님).

### 4.21 시간대 (2026-08-30 R2 확정)

- 사용자 시간대는 IANA 표준 형식(예: `Asia/Seoul`)으로 저장한다.
- 최초 로그인 시 브라우저가 감지한 시간대를 자동으로 제안한다.
- household 단위로 기본 시간대를 설정한다. 학생은 기본적으로 household 시간대를 상속하되 개별로 재정의할 수 있다(유학 중 시차가 다른 경우 등). 선생님은 개인 시간대를 별도로 가진다.
- 시간대를 알 수 없거나 감지에 실패하면 `America/Los_Angeles`를 기본값으로 쓴다.
- 예약은 UTC 저장값과 예약 생성 시점의 원본 시간대를 함께 보존해, 이후 사용자의 시간대 설정이 바뀌어도 그 예약이 실제 생성됐을 때의 맥락을 다시 계산할 수 있게 한다.

## 5. 상태 모델

### 5.1 상담 건

`requested → scheduled → completed → trial_planned → trial_completed → proposed → contracted → converted`

중간 종료는 `closed`로 처리하고 종료 사유를 남긴다. 상담 예약 취소·노쇼는 상담 건 자체를 삭제하지 않는다.

### 5.2 과목 수강

`planned → active → paused → completed/terminated`

한 자녀는 여러 과목 수강을 동시에 가질 수 있다. 자녀 전체 상태와 과목 수강 상태를 혼용하지 않는다.

### 5.3 예약

`holding → confirmed → cancelled/failed/reconciliation_needed`

예약 상태는 수업 진행 상태와 분리한다. 다시 예약할 때는 기존 예약을 `cancelled`로 남기고 별도의 새 예약을 생성한다.

### 5.4 수업

`draft → scheduled → live → completed`

예외 종료는 `student_cancelled`, `teacher_cancelled`, `student_no_show`, `teacher_no_show`, `company_cancelled`, `interrupted`로 구분한다. 모든 최종 상태는 처리자·사유·시각을 가진다. 완료 후 수정은 재개방 이력 없이 허용하지 않는다.

### 5.5 계약

`draft → ready → sent → awaiting_signature → signed → active → termination_pending → terminated`

서명 전 무효는 `void`, 새 계약 버전으로 대체된 계약은 `superseded`로 구분한다. 향후 고정기간 상품에만 `expired`를 사용한다. 수정 계약은 기존 계약을 덮어쓰지 않고 연결된 새 버전으로 만든다.

**(2026-08-30 확정)** 전자서명 서비스는 DocuSign을 계속 사용한다(제거 대상 아님). 확정 구조:

- 계약 데이터와 상태의 기준 원본은 ALTON DB다. DocuSign은 서명 발송·서명 절차만 담당하고, 서명 완료본과 감사증명서(certificate of completion)의 장기 보관은 회사 Google Shared Drive가 담당한다(§4.14 Drive 원칙과 동일 계열 — Drive는 최종본, DocuSign은 서명 처리 경로).
- 계약 단위는 자녀별이다(한 자녀당 계약 1건 원칙, §4.12).
- 수정 계약은 기존 계약을 덮어쓰지 않고 새 버전을 생성한다. 가격·환불정책·계약 조항은 발송 시점 버전을 스냅샷으로 보존한다(구매 이후 정책이 바뀌어도 이미 발송·서명된 계약의 조건은 바뀌지 않는다).
- DocuSign envelope는 계약 버전과 1:1로 연결하고, `sent/delivered/completed/declined/voided` 상태를 웹훅으로 자동 반영한다. 웹훅은 서명 검증을 반드시 거치고, signing secret이 설정되지 않은 환경(개발 환경 포함)에서는 요청을 통과시키지 않는다. 중복·재전송·순서 역전 웹훅은 `external_event_receipts(provider, event_id)` 기반으로 멱등 처리한다.
- 서명 완료본·감사증명서는 다운로드해 회사 Shared Drive의 해당 자녀 계약 폴더에 저장하고, Drive file ID를 계약과 `drive_artifacts`에 연결한다.
- 계약 서명 완료 후 결제 단계로 전환한다.
- 웹훅 누락·다운로드 실패·Drive 저장 실패는 재처리 대상으로 남기고 정기적으로 DocuSign·Drive·ALTON DB 상태를 대조한다.
- 비밀키와 access token은 서버에서만 사용하며 클라이언트에 노출하지 않는다. 계약 발송·무효·재발송·완료·파일 보관은 전부 감사 이력을 남긴다.

### 5.6 결제·환불

- 결제 시도: `created → processing → succeeded/failed/cancelled/reconciliation_needed`
- 환불 요청: `requested → reviewing → approved/rejected → processing → succeeded/failed`
- 구매의 `pending/paid/partially_refunded/refunded/disputed` 상태는 결제·환불 원장에서 파생한다.
- 외부 응답이 불명확하거나 중복되면 임의로 성공 처리하지 않고 대조 대상으로 남긴다.

### 5.7 계정 (2026-08-30 R2 확정)

`pending → active → suspended → active(재활성화)` 또는 `active/suspended → closure_pending → closed`

`suspended`는 되돌릴 수 있는 일시정지이고 `active`로 복귀 가능하다. `closed`는 종착 상태이며 사용자 기능으로 복원하지 않는다(§4.13 탈퇴·삭제 흐름, §4.19 계정 병합과 연결). 초대(`pending`) 자체의 만료·재발송·철회는 §4.19를 따른다.

## 6. 핵심 데이터 무결성 규칙

1. 같은 자녀·과목에는 같은 시점에 활성 선생님 배정이 하나만 존재한다.
2. 세션은 당시 선생님 ID, 시급, 수업 유형, 교재 버전을 직접 보존한다.
3. 수업권 보류·소진·환불·조정은 모두 불변 원장 항목이다.
4. 수업권 잔여량과 정산 합계는 파생값이며 임의 덮어쓰기 하지 않는다.
5. 완료된 수업은 읽기 전용이고 보정은 새 감사 이벤트로 남긴다.
6. 과거 교재와 필기는 최신 교재 변경의 영향을 받지 않는다.
7. 선생님 배정 변경은 과거 수업과 정산 귀속을 바꾸지 않는다.
8. Google·Stripe 작업은 idempotency key와 재처리 상태를 가진다.
9. 사용자·선생님·보호자 관계 종료 시 향후 접근은 회수하되 법적·회계 기록은 보존한다.

## 7. 수업 기록·화이트보드 원칙

- 필기는 문서 버전과 페이지/영역에 고정된 정규화 좌표로 저장한다.
- 각 필기 이벤트는 작성자, 도구, 시각, 순서, 기기 세션을 가진다.
- 실시간 전송과 영구 저장을 분리하고 재접속 시 누락 이벤트를 복구한다.
- 전체 필기 배열을 마지막 저장자가 덮어쓰는 방식을 사용하지 않는다.
- 전체 지우기는 권한과 확인을 요구하며 복구 가능한 이벤트로 기록한다.
- 완료된 수업은 필기·과제·문서 수정이 잠긴다.
- iPad Safari, Apple Pencil, 손바닥 터치, 화면 회전, 확대·스크롤을 필수 QA 범위에 포함한다.
